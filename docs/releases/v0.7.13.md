# v0.7.13 — Git 自动资料读取凭据解码修复候选

## 修复范围

- Git 连接凭据按 `encodeGitCredential("token", token)` 编码后加密保存，指纹对应编码后的完整载荷。定时资料读取现在先解密并核对该指纹，再以明确的 `token` 类型解码，并把原始 GitHub token 交给只读客户端。
- 裸 token、错误认证类型、畸形载荷和指纹不匹配均失败关闭，错误不包含凭据。没有增加旧格式回退，也未改变通用 Git 读取上下文的编码返回契约。
- PostgreSQL 验收夹具改为使用与真实写入路径相同的编码格式。没有数据库迁移、权限或凭据规则变更。
- Next 16 在全局响应头已设置 `Referrer-Policy` 时不会用 Route Handler 的同名响应头覆盖它。现在仅在精确路径 `/mcp/authorize` 省略全局该头，授权成功页继续由路由设置 `same-origin`，错误、POST 和重定向继续由路由设置 `no-referrer`；其他路径仍保留全局 `no-referrer`，其余安全头不变。

## 候选版本与更新入口

应用、健康接口和 OCI 镜像版本一致为 `0.7.13`。`deploy/production/ai-project-os-v0713-deploy.py` 只接受精确的 v0.7.12 来源收据和源修订 `30cf7c00fd70f76d492480b8971da40dd66cea98`，再验证目标注释标签 SHA 和源历史祖先关系。它预构建应用与两个 Worker，核对原有 140 条迁移账本，并在切换前后保留生产环境文件及 Compose 运维覆盖文件；不执行迁移。
