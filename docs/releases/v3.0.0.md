# AI Project OS V3.0.0 内部研发里程碑记录（非正式发布）

记录日期：2026-08-29

状态：内部研发里程碑（非正式发布）

V3.0.0 将 AI Project OS 从单一人工资料管理扩展为可本地部署的项目长期记忆与只读项目智能工作台。本版本的核心闭环是：多来源资料进入项目后保留来源与版本，经 AI 抽取或视觉识别生成候选，由人工审核进入事实库，再构建项目级语义索引，并通过引用式 RAG、项目简报和受约束的只读智能体使用这些记忆。

## 发布能力

- 页面配置 OpenAI、DeepSeek、Qwen、GLM 的生成、视觉和向量模型，不要求把业务 API Key 写入环境变量。
- 上传并解析文本、PDF、Office 文档和常见图片；图片与扫描 PDF 可在当次授权后调用视觉模型。
- 添加公开网页、经明确授权的内网页面和浏览器选择的本地文件夹。
- 连接 GitHub、Gitee、GitLab、自建 GitLab、Gitea、Forgejo 和通用 Git；单项目可关联多个服务上的多个仓库。
- 对人工、文件、网页和代码资料执行自动抽取、人工审核、统一向量索引、语义搜索与引用式 RAG。
- 生成项目简报，并通过固定项目内只读工具运行受约束智能体。
- 使用独立 Worker 执行持久化自动化，集中展示通知、失败状态和记忆质量问题。
- 使用工作区与项目两级角色、邀请链接和 OIDC 管理团队访问。

完整使用方式与限制见[操作手册](../operation-manual.md)。

## 升级前准备

升级前必须同时保存以下三类数据，并保证它们来自同一时间点：

1. PostgreSQL 数据库备份。
2. `ai-project-os-secrets` 卷，其中包含解密模型、Git 与 OIDC 凭据所需的主密钥。
3. `ai-project-os-uploads` 卷，其中包含上传文件原件。

数据库导出不包含主密钥和上传二进制，项目 JSON 导出也不能替代以上备份。不要执行 `docker compose down -v`。

## Docker Compose 升级

```bash
git switch main
git pull --ff-only
docker compose config --quiet
docker compose up -d --build
docker compose ps --all
```

期望状态：

- `postgres` 为 `healthy`。
- `migrate` 为 `Exited (0)`。
- `app` 为 `healthy`。
- `worker` 为 `running`。

迁移任务使用 `prisma migrate deploy` 依次应用仓库中的 42 个迁移。应用和 Worker 只有在迁移成功后才启动。

## 回滚原则

- 先停止 `app` 与 `worker`，防止旧代码继续写入新结构。
- 同时恢复升级前代码、数据库、凭据主密钥卷和上传卷；不得把旧代码直接连接到已升级数据库。
- 恢复后先运行数据库只读核对和 `docker compose ps --all`，再开放页面访问。
- 若只有数据库备份而没有匹配的主密钥或上传卷，凭据和上传文件无法完整恢复；此状态不应视为成功回滚。

## 外部服务验证边界

以下能力已通过代码、自动化测试或本地替代服务验证，但因为没有在发布环境中提供真实凭据，本次未做第三方现场连接验收：

- OpenAI、DeepSeek、Qwen、GLM 的真实模型调用与计费行为。
- GitHub、Gitee、GitLab、自建 GitLab、Gitea、Forgejo 和通用 Git 服务器的真实仓库连接。
- 企业 OIDC 身份提供商的真实登录；自动化测试使用本地签名 OIDC 服务。

管理员应在自己的网络与账号边界内，从页面执行连接测试和最小范围试运行后再开放给团队。未完成现场验证不影响本地功能、数据库迁移与恢复验收，但不能被表述为对应第三方服务已经联通。

## 已知限制

- 当前页面不提供多个工作区的创建和切换。
- OIDC 不会按邮箱自动合并已有本地账户。
- Issue、PR 和 Release 等扩展资料仍是 GitHub 专用能力。
- 网页来源不执行 JavaScript，也不支持登录态页面或自定义请求头。
- Office 内嵌图片、音频和视频不会被识别。
- 涉及向模型发送项目内容的自动化只创建待确认通知，不绕过用户当次授权。
- 只读智能体没有 Shell、文件写入、Git 写入、部署或 MCP 写权限。
