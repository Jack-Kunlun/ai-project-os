# v0.7.12 — MCP 工具目录与浏览器授权修复

## 修复范围

- 接受工具描述中的正常换行和制表符；继续拒绝其他控制字符。
- 支持工具属性的精确可空类型（单一基础类型加 `null`），保留原始 Schema 指纹、严格对象根节点及输入/输出校验；任意类型联合和可空 Header 绑定仍拒绝。
- 非空远端目录如果全部被拒绝，连接测试明确失败，避免显示“成功、0 个工具”。微软官方文档 MCP 的三个公开工具定义作为回归夹具，不代表调用已验收。
- 成功 OAuth 同意页使用 `Referrer-Policy: same-origin`，让原生表单提交正确的同源 `Origin`；错误、POST 和回调重定向继续使用 `no-referrer`，严格同源和 CSRF 校验保留。

## 已观察到的生产与浏览器证据

- 修复前，生产微软 MCP 完成 `2025-11-25` 握手，三个工具定义含多行描述与可空属性，被旧目录校验拒绝；未保存连接或调用工具。
- 本地真实 Chrome 原生表单对照复现：`no-referrer` 产生 `Origin: null`；`same-origin` 产生正确源。测试仅使用临时 loopback 页面，不使用生产凭据。
- v0.7.11 的两份生产 OAuth 同意均未成功；验收进程已停止，实际项目读取 0 次。修复后的生产 OAuth、六次合成项目读取、重放拒绝和撤权仍待切换后验证。
