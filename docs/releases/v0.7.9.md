# v0.7.9：从项目配置接入代码仓库

Git 主入口调整为“项目配置 → 代码仓库”。可在项目内选择已有个人连接，或通过弹窗添加连接、测试指定仓库和分支，再保存并填写项目读取范围。个人空间保留“Git 授权管理”，维护凭据、查看关联项目并撤权。

保存连接后从项目接口重新核验当前用户可用连接，仅带回连接 ID、测试仓库和分支；保留目录、用途、期限和资料范围草稿。保存不自动提交提案、确认或执行读取。刷新失败阻止提交并提供重试；刷新时项目权限失效则清除旧项目信息并进入安全回执。项目内新增连接要求只读凭据；历史无认证连接仍可能出现在选择器中，但服务端会拒绝其项目提案。

服务端权限、个人凭据归属、手动和自动读取的独立双确认不变。不修改 Schema、迁移、生产配置或基础设施。

## 验证与发布

定向 Git、个人与项目配置、导航、连接探测测试共 39 项通过；类型检查、受影响文件 ESLint、隔离实际 React 浏览器交互及独立审查通过。浏览器请求为模拟 API，凭据为合成测试输入，不计为真实 Git 连通性验收。生产构建通过；性能预算全部通过（静态资源总计 773.3 / 780 KiB，全局 CSS 14.8 / 15 KiB），部署入口的构建前失败、切换失败隔离和成功记录场景检查通过。

生产入口 `deploy/production/ai-project-os-v079-deploy.py` 从 v0.7.8（`d80aaea590b18dcaa3602c9f7974ffc313dd1615`）更新。沿用用户明确授权的 0.7.x 单机快速发布方式：先构建应用和两个 Worker，保持原 PostgreSQL、140 条迁移和生产配置，再切换并核对内部和公网健康；不做备份、恢复、旧数据演练或迁移，不等待重复完整 CI 作为生产门槛。实际上线以 `V079_DEPLOY_OK` 及公网版本 0.7.9 为准。
