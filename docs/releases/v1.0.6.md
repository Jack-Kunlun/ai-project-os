# v1.0.6 — 复用 CI 镜像与精简正式发布

正式发布继续由用户在 GitHub Actions 点击「发布正式版本」发起。CI 从当前生产源版本到候选提交的累计差异选择测试，使用共享构建图生成应用、Worker 与迁移镜像；浏览器和隔离候选验证复用这些镜像。主分支 CI 成功后，生产只拉取该次 CI 的不可变摘要镜像，不在服务器重新构建。

发布会自动核对精确 SHA、CI 运行、镜像 ID/摘要与版本，验收数据库、Worker 和公网健康后才记录成功并发布 GitHub Release。迁移清单未变时跳过迁移和权限协调。按当前阶段的运维策略，常规发布不创建备份、不验证备份或执行恢复演练；历史备份与业务数据保留。

验收成功后自动保留当前及上一版本应用镜像、所有容器仍引用的镜像，删除更早且无引用的应用镜像，并将生产默认构建器闲置缓存限制到约 2 GB。不会清理数据库、数据卷、用户文件或历史备份；清理失败只提示维护待处理，不停用健康服务。

首次启用此协议需要一次 root 发布工具升级。升级后，正常版本和发布工具更新由受限 Workflow 完成；固定工具文件只能来自精确主分支提交及成功 CI，不开放任意远程命令。镜像使用该次 Workflow 的临时 GitHub 凭据拉取，不新增永久 registry 密码。

本版本没有新增数据库迁移。源码检查、真实 CI、生产部署及外部模型/短信验收分别以实际运行结果为准。
