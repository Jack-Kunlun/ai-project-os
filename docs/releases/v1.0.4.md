# v1.0.4 — 简化正式发布流程

本文件描述待验证候选，生产版本以 `/api/health` 和正式发布回执为准。`v1.0.3` 已创建不可移动的标签，其发布在隔离恢复演练阶段失败，生产迁移尚未开始，源版本恢复为 `1.0.0`。本次修复使用新的前进版本号。

## 本版本变更

- 正式生产发布不再运行隔离恢复演练，包括高风险版本，并停止构建仅供演练使用的 principal-bootstrap 镜像。发布回执明确记录 `restore=skipped-by-policy-<源迁移数>-to-<目标迁移数>`，不宣称已经完成恢复验证。
- 保留精确同 SHA 主分支 CI、annotated 标签与工具哈希核验、停写备份及异地工件校验、生产迁移、权限协调、目标账本与上线健康检查。
- 保留失败保护：迁移尝试前恢复精确源版本；迁移尝试后保持停写并等待人工恢复。低/中风险且迁移清单完全相同的版本继续跳过迁移及权限协调。同版本重试兼容历史演练回执和新的策略回执。

本候选继承尚未上线的 [v1.0.2 账号、个人赠额和知识库修复](v1.0.2.md)与 [v1.0.3 文件导入、资源监控和平台视觉导入优化](v1.0.3.md)。本次没有新增数据库迁移；相对生产 `1.0.0` 为 143→146 条迁移。

## 发布与验证边界

由用户在 **发布正式版本** 选择 `main` 手动发起，代码提交与 CI 不自动发布。发布工具内容发生变化，须先在精确同 SHA CI 成功后完成服务器工具升级。

CI 的隔离数据库和 Compose 验证继续执行；生产备份本次不做完整恢复与升级演练。生产迁移后如需灾难恢复，仍由管理员依据本次备份处理。真实短信、视觉模型等外部服务的现场行为单独记录，不能用 CI 或健康接口代替。
