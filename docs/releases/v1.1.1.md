# v1.1.1 — 认证页面统一与抽取任务反馈修正

统一注册、找回密码和登录页的视觉体验，并修正资料抽取任务的状态、失败原因及通知展示。实际部署结果以本次发布回执和公网 `/api/health` 为准。

## 登录流程

- 登录、注册、找回密码共用白灰蓝页面布局、表单样式和帮助入口，适配桌面及手机。
- 保留已配置的认证方式、验证码和安全校验、失败输入、成功反馈及返回路径。找回密码继续使用现有手机号流程；未启用时明确提示，不增加新的恢复渠道。

## 资料抽取任务

- 模型响应校验失败且调用结果未知的抽取任务显示“抽取未完成”，说明没有完整结果可供确认；其他未知调用继续显示“结果未知”。
- 已人工收口的未知任务显示“任务记录已收口”，区分调用记录核对、候选内容审核和用量结算，不把收口当作抽取成功。
- 任务详情、处理任务列表、工作台、项目概览及新通知使用一致的结果表达，补齐截断、资料过大、无效结构、证据不匹配等失败原因与操作建议。
- 保留已保存的部分候选和历史调用审计，不重写历史通知，不自动重试任务。重新抽取仍须确认当次模型及资料范围。

## 既有后端修复与验证边界

历史无效响应问题对应的 DeepSeek JSON 模式、关闭思考输出及截断响应分类修复，已在 [v1.0.12](v1.0.12.md) 发布，本版本继续包含。当前传输与解析回归验证已通过；历史任务未保留原始供应商响应，无法唯一还原当时的响应分支，不能把旧未知记录改写为确定失败或成功。

本地已通过默认测试与覆盖率、静态检查、共享镜像构建、性能预算、抽取与通知 PostgreSQL 门禁、认证页面及任务页面浏览器与可访问性检查，并完成独立审查。正式发布另行复用精确提交的成功主分支 CI 和同一不可变摘要镜像。

本次不新增依赖或数据库迁移，迁移清单仍为 148 条；保留已有用户、项目、资料、上传文件及审计记录。本地示例数据不进入生产。未重新外发历史七份项目资料，也未发送真实短信；真实供应商与短信端到端流程不属于本次新增现场验收。
