# v1.2.16 — 修复 Git 资料发布超时

文件较多的仓库可能已完成只读读取，却在逐文件写入项目资料时超过 Prisma 默认的 5 秒交互事务限制。事务回滚后没有成功发布的资料，运行保持“结果未知”。

手动资料发布改为批量查找来源、创建新版本、复用已有来源和写入运行清单，减少数据库往返。来源身份、版本键、文件顺序、清单指纹、历史资料退休及发布指针切换继续在同一事务内处理。

手动资料发布和每日自动代码资料发布使用明确的每次事务 60 秒上限、5 秒事务获取等待上限；其他控制面事务沿用原有预算。授权范围、租约、归档、失效校验与发布指针的并发检查不变。自动发布原有的序列化冲突重试继续在每次事务内重新校验租约，不保证整个重试流程在 60 秒内完成。已发出的未知读取仍需核对，不会自动重试或被改写为成功。

发布前需验证较多文件、混合新建与复用来源、清单及指针一致性、失败回滚和现有权限边界，并通过对应源码及镜像门禁。无依赖、Schema 或迁移变化，迁移清单仍为 150 条。正式发布复用精确同 SHA 的不可变镜像；生产结果以发布回执、公网健康和实际仓库读取记录为准。
