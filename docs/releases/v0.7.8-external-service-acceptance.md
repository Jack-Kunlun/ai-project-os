## 两个模拟 MCP 客户端

已使用本机独立 PostgreSQL 和 loopback HTTP，请求进入当前应用的 MCP、令牌及元数据路由。客户端 A 使用 Node `fetch` / `2025-11-25`，客户端 B 使用 Node `http` / `2026-07-28`，各有独立 OAuth 身份、授权及令牌。

实际运行 `node --import tsx scripts/run-mcp-client-acceptance.ts`，140 个迁移成功，1 项集成测试通过、0 失败；自有临时容器和密钥目录均已清理。两份新增文件的定向 ESLint 与差异检查通过，没有运行全仓测试或生产构建。

测试经过实际 localhost HTTP socket 验证：

- 资源和授权服务器元数据、未授权的 401 challenge，以及错误 Host 的 403。
- 两客户端 PKCE 令牌交换和授权码重放拒绝。
- 工具列表只含三项只读工具；没有逐次审批时不能读取。
- A 的未消费审批不能被 B 使用；失败不产生派发审计，A 随后仍能使用自己的审批。
- 每客户端分别读取 `project_summary`、`project_evidence`、`project_plan`，响应项目身份及内容形状正确，每项只产生一条派发审计；六次审批重放均拒绝。
- 两客户端撤权后再次访问均为 401，总计六条成功派发审计。

客户端元数据和 Owner 同意采用测试注入/服务函数，明确为模拟；没有真实 HTTPS 元数据发现、浏览器同意或第三方客户端兼容性证据。路由调用使用隔离测试数据库的专用测试角色，不证明生产数据库权限配置。该测试也不验证生产 Nginx 限流。
