# AI Project OS V4.1.0 发布说明

发布日期：2026-08-30

V4.1.0 把 V4.0 的证据驱动计划扩展为可日常使用的项目运营闭环。项目成员可以在同一页面明确负责人、期限、验收标准和完成证据，核对仓库同步变化，并从 Dashboard 处理跨项目风险。健康计算与提醒是本地确定性能力，不调用模型；系统仍不会自动修改代码、创建 Git 分支或 PR、合并、部署，也不会绕过 Action Engine 的策略与审批。

## 发布能力

- 工作项增加负责人和独立验收标准。负责人只能选择当前项目 Owner/Editor 或工作区 Owner/Admin。
- 工作项进入“进行中”前必须设置负责人和验收标准；进入“已完成”前还必须至少关联一条活动证据。
- 支持关联已确认项目事实、活动项目来源和仓库同步变化。证据保存规范化内容快照与 SHA-256 指纹，后续来源变化会显示需复核。
- “已完成”和“已取消”成为数据库保护的不可改写终态；证据移除采用软移除并保留审计。
- 计划页增加确定性健康卡，统计逾期、受阻、未完成依赖、即将到期、未分配、验收/证据缺口、证据过期、待采纳建议、仓库变化和动作待审批。
- Dashboard 增加“计划风险”指标与“项目运营提醒”，优先把逾期或受阻项目作为推荐下一步；项目创建、搜索和完整列表仍保留在独立“项目”入口。
- 自动化增加“项目计划健康提醒”，支持 1、3、7 或 14 天到期窗口，并可同时提醒相关负责人。

## 仓库变化核对

- “检查最新同步”只读取已经成功、完成对账且包含新增、更新或删除的仓库同步记录。
- 每条变化信号固定同步清单指纹、精确变更计数和最多 500 条有序样本，并明确声明系统不推断它必然影响任何工作项。
- Editor 或 Owner 可以把信号关联到一个非终态工作项，形成不可变仓库同步证据；也可以在人工核对后忽略。
- 关联和忽略都是一次性状态决策，保留操作者、时间和追加式审计；不会自动创建工作项或执行外部动作。

## 权限、证据与通知边界

- Viewer 可以查看计划，但不能创建、分配、关联证据或决策仓库变化。
- 负责人必须具备当前可编辑权限。账户停用、项目授权撤销或降级为 Viewer 后，健康状态会视为未分配，且不能继续启动或完成工作项。
- 已确认事实修订、项目来源退役或仓库同步失效会把关联证据标记为需复核；系统不会静默替换原快照。
- 健康自动化只读取本地计划、证据和审批状态，不调用模型，也不向外发送项目内容。
- 发送健康通知前会重新核对规则创建者和相关负责人的当前项目访问权；已失去权限或被停用的账户不会继续收到项目摘要。

## 升级说明

升级前必须同时备份 PostgreSQL、`ai-project-os-secrets` 和 `ai-project-os-uploads`，并保证来自同一备份窗口。不要执行 `docker compose down -v`。

V4.1.0 的第 47 个迁移会：

- 为现有工作项增加可空负责人和验收标准字段，不猜测或回填业务负责人。
- 新增工作项证据与仓库变化信号表、关系索引和追加式保护触发器。
- 扩展自动化、通知与计划审计枚举。
- 为工作项开始/完成就绪度、完成证据和终态不可变增加数据库门禁。

已有计划数据保持原样。升级后，缺少负责人、验收标准或证据的活动工作项会出现在健康提醒中；用户应在页面核对并补齐。系统不会自动创建健康规则，需要在项目“自动化”页面按需添加。

```bash
git switch main
git pull --ff-only
docker compose config --quiet
docker compose up -d --build
docker compose ps --all
curl --fail http://127.0.0.1:3000/api/health
```

完整使用方式见[操作手册](../operation-manual.md)和页面“使用指南”。
