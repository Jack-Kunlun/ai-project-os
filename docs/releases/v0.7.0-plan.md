## S1b：JavaScript 与站点登录网页的实施门槛

当前 S1a 只对精确公网 HTTPS 地址发起一次带 Bearer 凭据的静态 GET；应用进程不执行网页脚本。S1b 不得把 Playwright 直接加入 Web、通用 Worker 或 Git Worker，也不得把浏览器请求拦截当成唯一网络边界：Service Worker、WebSocket、重定向、下载和子资源都可能绕过页面级拦截。

1. 先交付**无登录的 JavaScript 渲染**：一次性浏览器执行容器使用独立网络命名空间、非 root 用户、只读根文件系统和内存/进程/CPU/时间上限。容器只能访问强制出站代理；代理对每一次请求执行公网地址判定、DNS 钉住、精确允许的 HTTPS 源站、方法和响应体预算，不允许直连外网、私网或云元数据地址。跨源跳转、下载、WebSocket、Service Worker 和浏览器持久化状态先拒绝。最终仅返回有上限的可见正文与规范化来源地址，进入现有待人工审核链，不直接发布到项目资料。
2. 再交付**同源站点表单登录**：项目 Owner 分别确认目标页、登录页、账号范围及凭据外发；凭据在应用侧密封保存，只在独立浏览器任务中解封使用，不写入审计或错误。抓取结果仅供 Owner 私有预览或丢弃，不进入 `ProjectSource`、搜索、AI 或对外 MCP；站点可能用任意变换把凭据写入页面，自动反射检查只能覆盖原文与 URL 编码，不能据此安全发布。每轮创建全新浏览器上下文，登录后的 Cookie 仅用于同一轮同一源站，不复用或导出持久会话。跨源 SSO、MFA、验证码、第三方登录和任意用户脚本不在首个可验收切片内；出现这些流程时明确失败并提示人工处理。
3. 验收按攻击面逐层进行：隔离站点验证脚本渲染、同源表单登录、待审与撤权；恶意页面验证私网/元数据地址、DNS 变化、重定向、子资源、Service Worker、WebSocket、下载、长时间脚本、超量内存及凭据反射均失败关闭；再做浏览器操作与容器重启清理。未取得真实容器网络隔离和上述门禁证据前，生产环境继续硬关闭认证网页能力，不把静态 Bearer 抓取表述为完整的登录/JavaScript 支持。

## 首片：对外 MCP 只读项目能力

外部 MCP 服务保留在现有 Next.js 单体中，不新增独立服务。先固定协议版本、认证方式、授权范围、只读工具目录和响应上限。令牌只在创建时返回一次，数据库只保存摘要；每次请求检查令牌有效期、撤销状态、用户启用状态与项目实时权限。首个端到端用例是外部客户端读取指定项目摘要；无授权、撤权、跨项目和过期请求必须失败关闭，不能把内部模型、Git 或 MCP 凭据向外透传。对外写操作不在首片范围。

当前工作树包含 O1 OAuth 授权纵切片和项目 Owner 管理页：外部客户端使用同站点 `/api/mcp`，仅可调用只读 `project_summary`、`project_evidence` 与 `project_plan`。服务端使用官方 MCP TypeScript SDK 的 Streamable HTTP 入口，并保留现代与旧版协议处理。项目摘要只含项目标识、名称、截断后的描述、描述截断标记、归档状态及更新时间；事实工具最多返回最近 10 条已确认事实及来源版本，计划工具最多返回最近 10 项目标与 10 项工作项，长文本均截断。Owner 可预览内容并明确批准一次读取；批准绑定具体工具、固定空参数输入指纹及内容指纹，五分钟内有效且消费一次，并在同一事务追加不可修改的外发准备记录。Owner 可查看最近 50 条记录及输入、内容指纹；记录表示服务端已准备外发，不证明第三方收到响应。

OAuth 纵切片提供受保护资源元数据、授权服务器元数据、HTTPS CIMD 客户端文档校验、Owner 对项目及 `project:read` 范围的同意、S256 PKCE 一次性授权码和最多 15 分钟的不透明访问令牌。授权请求与令牌绑定固定 HTTPS origin 下的精确资源、客户端、redirect URI、项目、范围及用户账号版本；一次性 code 和 access token 仅以哈希存储。授权页面绑定登录用户与 CSRF，拒绝、批准只回跳至预先验证的 redirect URI。每个 MCP 请求和工具调用会重查令牌、授权、Owner 与项目权限；成功读取仍消费原有 `McpExportApproval` 单次内容批准，并写入原有不可变 `McpExportDispatchAudit`。令牌撤销会立即阻断后续请求。可转移的旧 Bearer 仅供非生产联调，生产环境始终拒绝它。

所有入口默认关闭。生产启用 OAuth 需要同时显式设置 `AI_PROJECT_OS_MCP_EXPORT_ENABLED=true`、`AI_PROJECT_OS_MCP_EXPORT_OAUTH_ENABLED=true` 和固定的 `AI_PROJECT_OS_MCP_EXPORT_PUBLIC_ORIGIN`；生产 origin 必须为 HTTPS。OAuth metadata 和 401 resource challenge 仅在授权链完整启用时发布。当前代码仅接受 HTTPS 或 loopback HTTP 回调，使用跨副本持久化的 client/global 小时预算与未完成请求上限，按已验证的安全字段计算 CIMD 指纹，并在新审批与外发审计中快照精确 OAuth client ID 和完整名称。Worker 每 15 分钟尝试清理超过 24 小时的过期 OAuth 状态，每周期最多 10 个短事务；24 小时是清理资格阈值，停机或积压可能延迟实际删除。第 129 条迁移已通过隔离空库重放；OAuth 与 Worker PostgreSQL 门禁 2/2、OID10、受影响类型检查、生产构建和现有浏览器套件 7/7 通过。第 128→129 条历史审计升级门禁也已通过：旧审计身份保留 NULL，且记录不可修改或删除。独立安全窄复审确认 O1 本地纵切片可冻结。浏览器套件尚未覆盖 OAuth 同意页，真实 MCP 客户端、生产反向代理与部署启用仍未验证；公开启用前仍需可信代理按真实连接来源限制匿名授权请求。DPoP/机密客户端认证、写工具和免内容审批不在本片范围。
