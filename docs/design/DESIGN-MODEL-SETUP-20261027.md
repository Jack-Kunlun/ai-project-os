# 模型与能力 / 测试额度原型修订

日期：2026-10-27
状态：交互原型，供产品实现前评审

## 目标

把模型配置从逐项进入、逐项测试改成同一页面批量选择。让管理员能看懂每项能力当前是否生效、这次会用哪个模型，以及测试额度代表什么。

## 模型与能力

- 按业务名称列出六项能力：向量检索、图片识别、资料整理、资料摘要、项目分析、带资料问答。
- 每行同时展示当前生效配置、本次模型选择和本次测试结果；改变待测模型不会马上替换当前配置。
- 默认勾选尚未启用的五项，已启用的向量检索保持不选中。提供“全选”和“清空”。
- 可将同一文字模型一次应用到已选文字能力，不影响未选能力。
- “测试并启用所选”先确认范围，再逐项测试；某项通过后立即启用。部分失败保留原配置，可只重试已知失败项。结果未知的项目保留待核对状态，不自动重试，并停止后续项目；未执行项不扣额度。
- “仅测试”不改变当前生效配置。通过结果 5 分钟有效且仅能使用一次；之后可单独确认启用。
- 更换向量模型或维度时才要求确认索引影响。
- 单项模型测试只检查连通性，不代表该能力的业务输出质量。每次单项测试最多使用 1 次测试额度；六项一次全测最多 6 次，手动重试另计。模型供应商可能另行收取 Token 费用。

## 测试额度

- 页面名称改为“模型测试额度”，展示可用、已计入、进行中、结果待核对次数。
- 用户可读名称为“最大测试次数”和“有效至”；告警阈值说明达到后会通知管理员，不会自动补充额度。
- 保存配置会立即停用旧周期，并按设置的生效时间启用新周期；若生效时间在未来，到时才可使用。旧周期未使用次数不结转；额度不会自动创建或补充。支持的周期最长 90 天。
- 结果未知的请求会占用额度并留待核对，不自动重新发送。
- 不展示每日自动重置、失败阈值、MCP 探测额度或虚构的探测历史。

## 演示边界

全部供应商连接、测试、预算计数及结果均为本地原型数据，不发起模型或外部服务请求，也不会保存真实配置。页面中的“原型演示：选择模拟结果”仅用于评审全成功、部分失败、结果待核对、未设置额度和额度不足状态。
