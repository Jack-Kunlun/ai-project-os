# 手机号认证、短信配置与账号注销

版本：v0.7.4 新增能力。具体发布和生产升级以[版本说明](releases/v0.7.4.md)、实际 CI、生产健康及迁移账本为准；下方本地增量记录保留当时证据边界，不表示线上 v0.7.3 已具备这些能力。

## 当前能力

- 本地注册可要求中国大陆 +86 手机号及短信验证码；用户名和密码仍由用户设置。
- 登录页提供手机号验证码方式；用户名密码方式也接受已验证手机号（11 位或 +86 格式）。旧账号无需手机号即可沿用原密码、GitHub 或 OIDC 登录。
- 验证码登录在验证通过后，若手机号尚未注册且本地注册开放，则自动创建普通用户与独立的个人 Owner 工作区，并提示「该手机号尚未注册，已自动创建账号和个人工作区。」发送阶段不查询或公开账号是否存在。
- 个人中心提供注销；密码或已绑定手机号的专用注销验证码再次验证身份，输入「注销账号」确认。无密码且未绑定手机号的旧账号可先在个人中心设置密码并重新登录。
- 后台「配置中心 → 短信服务」集中管理阿里云个人短信认证 PNVS（Dypnsapi）、阿里云企业标准短信（Dysmsapi SendSms）和腾讯云短信（SendSms）。供应商使用固定官方地址及各自签名协议，不能填写任意 URL。更换供应商、凭据、签名和模板不需要修改注册或登录表单。

## 一次性部署前置与后台操作

1. 通过正常新版本迁移流程执行五项新增迁移（手机号、短信配置、注销、图形验证码、供应商扩展），并运行数据库 principal reconcile。沿用现有单云主机，无需新增服务或主机。
2. 部署基础设施保持 HTTPS、正确的 `AI_PROJECT_OS_PUBLIC_ORIGIN` 和 Secure Cookie；更新 Nginx 对图片验证码、短信发送、后台发送测试、登录和注销的限流配置。不要直接开放应用端口。
3. 在受保护的部署配置中设置 `PHONE_AUTH_SECRET`：32 字节随机值的规范 base64url 编码，43 个字符；所有实例保持一致。沿用 vault 的独立主密钥文件保护后台短信凭据。两者不可混淆，不写入仓库或聊天。
4. `PHONE_AUTH_ENABLED=true` 启用手机号认证代码。此时若尚未激活可用短信配置，验证码功能显示不可用，本地注册要求手机号且不会降级绕过验证。需要自动建号时同时保持 `LOCAL_REGISTRATION_ENABLED=true`。
5. 平台管理员打开「短信服务」，选择供应商并填写该服务的凭据、已启用签名与模板，字段对照见下表。密钥只写入受保护配置，页面不会回显；后台不接受自定义 endpoint。
6. 填写获授权的 +86 测试手机号，点击发送测试短信，先完成图形验证码，再输入收到的短信验证码并验证；**发送会产生服务商短信费用**。测试通过且当前管理员会话、配置版本未变化时，才能保存并启用。
7. 后续可在后台停用/启用已保存配置，或重新测试新配置后替换。每次配置变更递增版本，废止旧版本未使用验证码与候选配置测试。临时停用供应商会使短信功能不可用；已绑定手机号仍可用手机号和原密码登录。

若 `PHONE_AUTH_ENABLED=false`，保留旧的用户名密码注册路径，短信 UI 不启用。它是部署阶段的总开关，日常供应商启停由后台操作。当前不提供旧账号手机号绑定/换绑、其他国家号码、密码找回或通过验证码修改已有密码。

## 供应商配置字段

| 供应商 | 必填配置 | 验证码模板约定 |
| --- | --- | --- |
| 阿里云个人短信认证 PNVS | AccessKey ID / Secret、签名、模板代码 | 使用号码认证服务模板；由供应商生成与核验验证码 |
| 阿里云企业短信 SendSms | AccessKey ID / Secret、企业短信签名、`SMS_` 模板代码、验证码变量名 | 验证码变量名默认 `code`；有效期变量名可留空，填写后发送值为 `5`（分钟） |
| 腾讯云短信 SendSms | SecretId / SecretKey、SmsSdkAppId、短信签名、TemplateId、地域、模板变量顺序 | 可选择仅验证码、验证码后有效期、有效期后验证码；必须与审核通过模板的参数顺序一致，有效期为 `5`（分钟） |

腾讯云地域仅允许官方短信地域 `ap-beijing`、`ap-guangzhou`、`ap-nanjing`。签名和模板必须属于所填凭据与应用，后台不能替代云厂商审批或权限配置。企业版此处指阿里云标准短信 `SendSms`，不是另一套 PNVS 接口。

PNVS 的 `SchemeName` 是应用用途隔离参数，由服务端自动生成 `aipos-register`、`aipos-login`、`aipos-test`、`aipos-close`，管理员无需填写场景前缀。发送与核验使用同一用途名称；已有加密配置及在途挑战仍沿用其原始名称。官方必填的 `PhoneNumber`（大陆本地号码）、`SignName`、`TemplateCode` 均来自所选号码及供应商配置；`TemplateParam` 固定由系统生成 `{"code":"##code##","min":"5"}`，对应六位数字验证码和五分钟有效期，须使用包含 `code`/`min` 的号码认证模板。

短信服务首页展示当前生效供应商列表；新增或更换通过配置弹窗完成。当前只保存一份生效配置。图形验证码错误在安全验证弹窗内换图重试；配置、供应商调用或限额错误关闭安全验证弹窗，在配置表单显示原因并保留输入。失败后再次发送仍需新的图形验证码。

更换供应商后，未消费验证码、在途验证码发送完成记录和旧版本候选测试按配置版本失效；已发出的短信无法撤回。必须重新测试候选配置，不允许仅选择供应商后直接保存。旧 PNVS 加密配置保持原有认证数据格式与 AAD，升级后无需重输；新供应商的加密上下文同时绑定供应商，篡改供应商字段会导致解密失败。

## 注销规则

注销永久停用旧账号、提升访问版本、撤销全部登录会话、清除账号主记录中的手机号、密码、邮箱及显示名称，并保留不可变注销凭证。管理员不能恢复该账号。

- 手机号释放后可以重新验证并注册；新账号获得新的用户 ID 和个人工作区，不承接旧项目、资料、额度或会员权益。
- 独占的个人工作区封存并拒绝重新开放、加入成员或新建项目。历史项目、文件和审计记录保留，不是物理数据清除。
- 共享工作区保留给其他成员；唯一有效 Owner 必须先转交所有权。最后一位启用的平台管理员不能注销。
- 旧 GitHub/OIDC 身份关联保留在永久停用的旧账号，防止旧身份恢复访问；这些身份不能自动变成新手机号账号的身份。

## 验证与限额

- 注册、验证码登录、注销和管理员短信测试的**每次短信发送**都必须先完成服务端图片验证码；没有免验证发送路径。点击获取后弹窗输入图片中的 6 位字符（不区分大小写），支持换一张。
- 图片由当前服务生成 PNG，不增加独立主机、第三方服务或图形验证码费用；使用现有图片渲染依赖，不依赖系统字体。答案仅保存带密钥摘要，不在 JSON、图片元数据、Cookie 或日志中返回。
- 图形挑战有效期 3 分钟、单次尝试；绑定手机号、用途、HttpOnly 浏览器 Cookie，注销和后台测试另绑定当前账号及访问版本。正确/错误答案均消耗对应挑战，发送失败或触发限额后须重新验证；并发重放只有一次能通过。
- 图片获取使用持久化限额：同浏览器每 10 分钟 40 次、同手机号 20 次、全局 1000 次；Nginx 再按来源 IP 限流。传统图片验证码可能被 OCR 或人工代答绕过，必须与下列短信预算共同使用。

- 短信验证码 6 位、有效期 5 分钟，注册/登录/注销/配置测试分开绑定用途；单次消费、每个挑战最多 5 次验证尝试。
- 同手机号跨用途发送间隔 60 秒，每小时 5 次、每日 10 次；全局每小时 50 次、每日 200 次。验证每手机号每小时 30 次、全局每小时 500 次。失败发送仍保留已预留预算；不是仅靠客户端倒计时限制。
- 关闭新账号注册后，发送阶段仍不区分已注册与未知手机号，避免公开接口枚举账号；未知号码可能消耗一次受限短信费用，验证后才拒绝建号。限额限制费用和请求量，但不能彻底防止分布式攻击耗尽配额；图形验证码是额外屏障，仍不提供运营级风控。
- 密码登录当前主要依赖 Nginx 按来源 IP 的限流，尚未增加账号维度持续失败预算；不宣称已具备完整密码防爆破风控。
- 注销身份验证每账号 15 分钟最多 5 次，失败计数持久化。供应商网络请求在数据库事务外执行，认证结果在消费前重新核对当前配置、账号版本和一次性证明。
- 阿里云使用固定 HTTPS endpoint 和 ACS3 签名，腾讯云使用固定 HTTPS endpoint 和 TC3-HMAC-SHA256 签名；禁止重定向和重试，10 秒超时、响应上限 64 KiB。PNVS 以官方 `PASS` 结果验证；标准短信由应用以密码学安全随机数生成 6 位验证码，数据库只保存绑定挑战、手机号和用途的 HMAC，恒定时间比较后才建立验证证明。明文验证码及 provider 错误响应不会写入日志或持久化。

本地证据：46 项定向单元/回归测试通过；8 项数据库 principal 合同测试通过；完整 138 项迁移与 19 项隔离真实 PostgreSQL 联合测试通过；类型检查和受影响文件 ESLint 通过；两份 Nginx 配置已在隔离容器中用临时证书通过语法检查。本轮 S4 独立源码审查通过，未发现已证实的阻断缺陷；审查不等同于生产验收，注销后 GitHub/OIDC 回调仍需专门回归及真实现场验证。PostgreSQL 中短信网络响应使用测试替身，不表示真实阿里云凭据、模板、资费或送达已经验收。

复现联合数据库检查：`pnpm test:phone-auth-postgres`。工具使用固定 digest 的临时 PostgreSQL 容器及独立凭据/主密钥，结束后清理自己的容器和临时目录；CI 数据库作业已加入此检查，尚未运行远程 CI。它不替代独立完整 OID10 发布门禁。

注册布局由真实组件和 Tailwind 输出的隔离静态预览验证：1366×768 桌面卡片宽 920px，无页面滚动；390×844 手机无横向滚动，内容可纵向浏览。静态布局预览不证明浏览器认证端到端行为。

官方协议依据：[个人短信认证](https://help.aliyun.com/zh/pnvs/use-cases/sms-verify-for-individual-developers)、[发送验证码](https://help.aliyun.com/zh/pnvs/developer-reference/api-dypnsapi-2017-05-25-sendsmsverifycode)、[核验验证码](https://help.aliyun.com/zh/pnvs/developer-reference/api-dypnsapi-2017-05-25-checksmsverifycode)、[ACS3 签名](https://help.aliyun.com/zh/sdk/product-overview/v3-request-structure-and-signature)、[企业短信 SendSms](https://help.aliyun.com/zh/sms/getting-started/use-sms-api/)、[腾讯云 SendSms](https://cloud.tencent.com/document/product/382/55981)、[腾讯云官方 TC3 实现](https://github.com/TencentCloud/tencentcloud-sdk-nodejs/blob/master/src/common/sign.ts)。
