# 外部服务现场验收

本流程用于证明当前部署能够使用真实模型、Git、OIDC 和第三方 MCP 服务。CI 或本地 loopback fake 只能验证代码路径，不能替代第三方现场验收。

当前 `0.2.0-dev.1` 已开放个人 MCP 连接与工具发现、管理员净化快照审核、项目连接委托和只读工具授权控制面；远端动作调用、调用审批、派发、结果查看和结果导入仍未开放。因此本版本不能完成 MCP 远端能力现场验收，也不得把后端 loopback 或隔离门禁结果记为 MCP `ready`。下述 MCP 步骤是远端能力未来开放后的验收合同，不代表当前已可操作。

## 安全边界

- 凭据只在产品页面录入，不写入命令行、仓库、截图或验收日志。
- 使用最小权限测试账号、只读仓库和只读 MCP Token；准备可精确删除的测试项目与资料。
- `pnpm external:acceptance` 只读取状态、时间和成功证据计数，不解密凭据，也不输出连接名称、地址、账号、仓库或工具参数。
- 命令不主动访问外部服务。它核对页面操作在数据库中留下的最新、相互一致证据，因此必须先完成下列真实操作。

## 24 小时现场流程

默认所有证据必须在最近 24 小时内产生，且成功工作流不能早于最近一次连接探测。

1. 模型：系统管理员在 `/admin/models` 配置并执行平台托管模型连接测试；有效会员如需提供个人模型证据，应在个人中心配置自己的连接，并由连接所有者与项目 Owner 完成双确认委托后，在测试项目中完成一次受审计的真实模型工作流。连接测试会验证生成模型，并在配置了向量模型时验证向量维度；视觉能力仍需用真实图片另行人工核对。当前没有真实第三方凭据或现场证据时，不能标记为 `ready`。
2. Git：由连接所有者在个人中心对真实只读仓库执行连接测试，再由项目 Owner 在项目页完成双确认委托，并手动发起一次只读读取。记录单次读取对应的冻结 commit 或安全摘要，但不要在验收材料中泄露私有仓库内容；该步骤不代表完整同步、自动化或写入已开放。
3. OIDC：重新发现真实 IdP 配置，然后由独立测试账号走完 Authorization Code + PKCE 登录。仅发现端点不算登录验收。
4. MCP（远端能力计划验收，当前调用链冻结）：个人连接先重新发现真实 Streamable HTTP 工具，管理员在审核工作台核对净化快照，项目 Owner 完成连接委托和只读工具授权；只有远端调用、调用审批和派发未来明确开放后，才能由 Owner 显式触发一次真实只读调用。旧定义、旧网络或旧凭据指纹上的调用不计入验收；当前版本不得通过直接调用内部 API 绕过页面边界来形成产品验收证据，隔离门禁结果也不能冒充第三方现场结果。

完成后，在连接同一部署数据库且已安装依赖的受保护运维终端运行：

```bash
pnpm external:acceptance
```

退出码含义：

- `0`：所有要求类别均为 `ready`。
- `2`：命令正常完成，但至少一个现场证据门禁未满足。
- `1`：参数、数据库或执行本身失败。

可以缩小本次明确约定的验收范围，例如：

```bash
pnpm external:acceptance -- --expected model,git --max-age-hours 24
```

`--expected` 只允许 `model`、`git`、`oidc`、`mcp`，且不得重复；`--max-age-hours` 允许 1–168。范围排除必须写入发布记录，不能因为门禁未通过而临时删减。

## 结果判读

每类只输出聚合计数与稳定状态：

- `missing`：没有启用的连接。
- `probe_required`：已有连接，但尚未成功测试或发现。
- `stale`：曾成功测试，但证据超过允许时限。
- `workflow_required`：连接探测有效，但缺少发生在该探测之后的真实产品工作流。
- `ready`：连接探测和对应真实工作流均满足。

模型需要受审计的成功供应商调用；Git 需要连接测试后由双确认委托触发的一次成功手动只读读取，不把完整同步或自动化当作当前能力；OIDC 需要成功身份登录。MCP 目前只能验收个人连接、发现、净化审核和项目只读授权控制面，远端调用、审批、派发和结果处理仍未开放，因此不能判为远端 `ready`。

将完整 JSON、执行时间、目标版本和明确的范围排除写入受保护发布记录。不要附带 `.env`、数据库 URL、外部响应正文、Token、Cookie 或截图中的明文凭据。
