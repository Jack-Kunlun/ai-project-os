# v1.2.20 — 统一操作底栏与项目资料上传

弹窗和抽屉统一使用固定标题、可滚动内容与固定底栏；提交、保存、确认等操作移到底栏。按钮继续关联原表单，保留必填校验、回车提交和处理中状态。

文件导入弹窗突出文件选择和已选列表，容量与格式说明默认折叠，上传操作独立放在底栏。公共弹窗操作组件使用共享资源包，保持单页加载约束。

跨页面操作区和资料交互增加了客户端代码。实际构建经共享操作、账户面板、任务呈现与样式去重后，总静态资源从 880.7 KiB 降至 873.2 KiB；额外拆分反而增大的方案已撤回。总静态资源预算按本次新增功能调整为 875 KiB（增加 3.75 KiB，约 0.43%），保留约 1.8 KiB 余量；原未优化构建仍不能通过。共享脚本、最大单文件、全局 CSS 和全部关键单路由预算保持原值，最终数值以精确提交的 CI 构建为准。

项目资料栏目切换直接同步地址与当前视图，减少重复请求并保留浏览器前进、后退。删除被引用的资料失败时，保留资料列表并显示具体原因。图片上传后明确显示识别待确认状态，并直达对应文件。

项目文件选择窗口显示全部文件，选中后按扩展名检查支持情况，兼容 DOCX、PDF 的 WPS MIME 差异。项目上传默认取消单文件、图片文件与请求字节门槛，改为流式写入和下载；大小不符、中断、超时及签名失败会清理文件。JPEG 增量尺寸检查支持较长元数据，同时保留像素与格式校验。

项目、工作区、部署总容量与并发预算仍生效。本地单次解析最多读入 128 MiB，超过处理能力时保留原文件并提示拆分；旧客户端 multipart 兼容入口仍受缓冲上限保护。生产环境已有非零上传字节配置需设为 `0` 才会取消旧门槛。Nginx 仅对项目上传路径关闭请求体大小限制与缓冲，并保留连接数和频率控制。

本次不改变数据库 Schema 或迁移，账本保持 150 条。本地完成定向行为、类型、格式解析和浏览器检查及独立审查，未使用 Docker、真实模型或短信。正式上线以该提交的主分支 CI、不可变镜像、部署回执和公网健康为准。
