# AI Project OS V5.1.0 发布说明

发布日期：待定

状态：发布候选（范围内门禁已通过）

V5.1.0 补齐持续集成、生产浏览器回归、部署安全响应、Worker 运行健康和真实外部服务现场验收。它不扩大 Action Engine 或项目智能体权限：模型仍不能自动认证、授权或调用 MCP 工具，也不能执行 Shell、代码修改、Git 写入、合并或部署。

## 运行与发布保障

- Worker 把启动、心跳、领取和失败事件写为稳定结构化日志，并在数据库保存租约、最后成功时间和连续失败数。
- `/api/health` 独立返回数据库和 Worker 状态；Compose Worker 使用同一运行记录执行容器健康检查。
- GitHub Actions 在 push 和 pull request 上执行 Prisma/迁移校验、Lint、类型检查、默认测试全集、全部一次性 PostgreSQL 门禁和生产浏览器 smoke。
- 生产浏览器门禁使用全新数据库、真实迁移链、standalone 应用和 Worker，检查管理员初始化、受保护页面、版本、安全响应头和浏览器控制台。
- Compose 允许覆盖回环端口和三个持久化卷名，便于在不触碰正式实例的前提下构建与验收隔离候选。

## 部署安全

- 所有页面和 API 返回 CSP、`X-Content-Type-Options`、`X-Frame-Options`、Referrer Policy 和 Permissions Policy，并隐藏框架标识。
- 提供 HTTPS Nginx 反向代理、HSTS 启用条件、请求体边界和登录/OIDC/初始化入口限流基线。
- 真实模型、Git、OIDC 和第三方 MCP 验收只输出聚合状态与计数，不解密或记录凭据、连接标识、外部正文和工具参数。

## 数据库升级

第 50 个迁移增加 Worker 运行健康表与状态枚举。升级前必须在同一停写窗口备份 PostgreSQL、`ai-project-os-secrets` 和 `ai-project-os-uploads`，并在隔离恢复副本上完成 V5.0.1 到 V5.1.0 的迁移、关键记录计数与重启持久性核对。不要执行 `docker compose down -v`。

## 发布验收与范围

- 2026-08-31 本次发布范围明确为代码与数据库门禁、按 CI 工作流同序执行的本地流水线、生产 E2E、容器构建/迁移/重启，以及非托管的本地 Compose 发布。托管部署和 GitHub 托管 Runner 不在本次范围。
- 最终 `5.1.0` 候选已通过 Prisma、迁移目录、默认测试全集、全部 PostgreSQL 门禁、类型检查、Lint、生产构建、隔离 Compose、重启持久性和认证浏览器 smoke。
- GitHub Actions 配置、固定 Action 引用和命令顺序已通过本地验证，候选分支已推送。远端运行 #1–#3 因账户付款失败或支出上限不足而在 Job 启动前被平台拒绝，没有执行任何验收命令；本发布不把这些运行记为通过。
- 真实外部服务现场联调不在本次发布门禁范围。模型与 Git 的最近探测和只读工作流为 `ready`；OIDC 与 MCP 未配置并继续标记为未现场验证。未来纳入实际部署时必须重新运行对应现场验收，不得使用本地替代服务冒充。
- 2026-08-31 本地候选已通过 Prisma/迁移、Lint、类型检查、默认测试全集、23/23 PostgreSQL 门禁、生产构建、V5.0.1 恢复升级、隔离 Compose、数据库重启持久性和认证浏览器 smoke。正式实例仍运行 V5.0.1，未被候选替换。
- 本文件只有在正式本地 Compose 升级和发布后复验通过后才能改为“已发布”；在此之前不得创建 `v5.1.0` 标签或推送 `main`。
