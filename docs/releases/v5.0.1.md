# AI Project OS V5.0.1 发布说明

发布日期：2026-08-31

状态：已发布

V5.0.1 加固来源证明、MCP 工具认证、登录回跳和资源消耗边界。它不扩大 Action Engine 或智能体权限：模型仍不能自动认证、授权或调用 MCP 工具，也不能执行 Shell、代码修改、Git 写入、合并或部署。

## 安全与完整性修复

- `ProjectSource` 在数据库写入时核对正文与 SHA-256；来源身份、修订键、正文、哈希和采集信息在创建后不可改写，仅允许独立维护退役时间。
- 仓库与网页同步按真实正文生成来源哈希；同一来源身份的新远端修订不会复用旧证据行。
- MCP 工具的 `readOnlyHint` 和 `destructiveHint` 继续只作为未受信声明。管理员必须对精确工具定义、网络解析和凭据指纹创建追加式认证，项目 Owner 才能授权。
- MCP 认证可追加撤销记录；定义、DNS、凭据或认证状态变化后，旧授权和待执行动作会失败关闭。
- OIDC 回跳只接受本站单斜杠路径；未消费登录流程按身份源限制容量，并在同一事务内清理和淘汰。
- JSON 与 multipart 请求按实际读取字节数限流；PDF 视觉渲染在分配画布前限制边长和像素预算。
- `yauzl` 升级到包含安全修复的 3.2.1。
- 生产镜像写入 `org.opencontainers.image.version=5.0.1`，可与应用健康接口和迁移账本交叉核对。
- Docker 的 Next.js 构建阶段显式使用 4 GiB Node 堆上限，避免类型检查在默认约 2 GiB 上限下中止；运行镜像和 Worker 不继承该设置。

## 数据库升级

第 49 个迁移增加来源证明写入保护、MCP 工具认证及其追加式审计，并把现有 MCP 项目授权扩展为可绑定认证与三类指纹。迁移不会自动创建认证，也不会替用户信任任何远端工具；升级后，管理员需要在页面重新核对并认证准备开放的工具。

升级前必须在同一停写窗口备份 PostgreSQL、`ai-project-os-secrets` 和 `ai-project-os-uploads`。不要执行 `docker compose down -v`。

```bash
git switch main
git pull --ff-only
docker compose config --quiet
docker compose up -d --build
docker compose ps --all
curl --fail http://127.0.0.1:3000/api/health
```
