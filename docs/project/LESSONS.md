# AI Project OS 复发问题与防复发记录

更新：2026-11-02（Asia/Shanghai）；初始 C-008 / T-018 / E-014；持续改进补充 C-011 / T-029 / E-017。适用于全部功能模块及需求、设计、开发、测试、交接与发布；当前 L-001～L-007 主要来自 UI/验证反馈。本文保存用户纠正、历史问题模式及防复发要求；具体缺陷、执行进展和关闭状态只在 [TASKS](TASKS.md) 维护。

当前是记录与协作约束落地。下列问题主要来自用户报告；除明确列出的源码检查事实外，页面复现、根因和自动回归仍待对应任务完成。没有完整历史事件证据，不填写复发次数或伪造首次发生日期。

## 每次相关工作必须使用

1. **开工**：读取本表及命中条目，在任务卡记下适用 L 编号、受影响组件/页面/状态和准备执行的检查；必要的排除写理由。先核对当前代码和设计版本，不直接复用历史结论。
2. **设计/实现**：沿用有效规范与公共组件。新反馈追加到既有问题模式；同类表象尚未证明同一根因时分别记录，不提前合并缺陷。
3. **修复**：补充实际根因和影响范围，检查同类使用方；能自动断言的复发缺陷建立可识别原错误的回归。仍需视觉判断的项目保留可重复的人工/助手审阅步骤和证据。
4. **交付**：报告每个命中条目的检查结果、候选、证据及未验证项。没有有效回归或审阅证据时，不宣称防复发已完成；明确违反当前批准设计的受影响项不能标为已验收。
5. **再次出现**：保留原记录，追加事件并关联新缺陷任务；核实旧用例是漏场景、断言错误、未执行、基准失效还是其他原因。只在证据否定原验收时重新打开原任务；同类新缺陷使用新任务。

新会话、新工作区从根 [AGENTS](../../AGENTS.md) 进入这里。工作区须带有相应文档提交或显式迁移未提交文档；本地文件存在不等于已同步到远端或其他设备。个人长期记忆只保存协作要求和本项目入口，不代替仓库内规范，也不保存另一份任务状态。

## 问题边界的持续改进与升级

边界是需要随证据修订的工作合同。每个问题记录四项：**发生边界**（版本、角色、页面/模块和输入状态）、**影响边界**（已确认受影响/已排除/待验证）、**责任边界**（主责、协作方和接收方）、**验证边界**（哪些场景与检查能发现它、还不能证明什么）。不要把首次截图位置当作全部影响范围，也不要无证据扩大为全站故障。

保持闭环：`问题 T → 复现与根因/原检查失效原因 → 边界前后变化及 C → 修复/改进 T → 规范或实现/用例 → E 复验 → 实际接收 → 下一次适用交付检查`。L 记录保存可复用的模式，F 记录保存模块合同，A 保存过程；当前状态仍只在 TASKS，不新建另一套“改进状态表”。一次局部修复若未改变合同，不强制新建 C；适用规则未变直接引用。

### 何时升级、升级到哪里

| 触发证据 | 处理和升级范围 | 决策/处理责任与停止条件 |
| --- | --- | --- |
| 新问题、影响尚不明确 | 先登记并复现，区分已知影响和待查假设；不能等根因明确才留记录 | 当前 T 处理者调查，主代理协调；阻塞写解除条件，不把未知报完成 |
| 已有修复/防线后再次发生，或用户明确报告反复出现 | 关联旧 T/L/E，检查旧防线为何漏过；从局部扩到有依据的同类组件/使用方 | 主代理指定主责；用户报告尚无复现时标待核实，不编造复发次数；原错误及同类检查未过不得宣称防复发 |
| 公共组件、跨页面/模块、责任空白或合同冲突 | 沿实际消费者/数据流分析影响；列未验下游，必要时修订 F 合同和设计/接口版本，重新确认接收条件 | 源/目标模块实际承担者协作，主代理裁定证据归属；不各自绕过上游或让问题无人接 |
| 测试/验收曾通过，但后续或上线暴露适用场景错误 | 同时检查实现根因和漏检原因：场景缺失、断言无效、未执行、身份不匹配、过期基准、模拟边界或间歇失败 | 修复归对应模块；测试改进归实际测试任务；新检查要能识别原错误，不能只调整阈值/基准变绿 |
| 权限、安全、额度/支付、数据完整性、外发、迁移、生产/CI 或其他高风险信号 | 重新分类为 S4/high，按当前 AGENTS 做方案、针对验证及必要的高风险独立审查；阻断不安全路径的相关交付 | 主代理评估已授权处置；需用户决定的重大取舍及时升级，已有授权内继续，不默认要求所有步骤再审批 |
| 同一策略修复重试仍失败或新证据否定方案 | 保留失败和停止点，按既有重试预算转调查/方案调整；记录缩小范围、替代或真正阻塞 | 不无证据重复尝试，不自动升级模型或创建 Agent；用户决策只用于实质取舍，实施依然遵守授权 |

升级不自动意味着 P0、全仓测试或重新设计。严重程度按后果，优先级按处理次序；只扩大证据支持的影响面。跨项目问题如 T-027，保留待确认归属和移交记录，不擅自在其他仓库修复。

### 从修复升级到预防

1. **先说明原因。** 分开写实现根因、未被前序阶段发现的原因、复发条件；未查清写待核实。不能用“AI 粗心”“加强自测”替代可验证原因。
2. **更新最小有效防线。** 按根因选择需求/设计约束、组件或服务合同、运行防护、行为/集成/视觉回归、交接清单及文档版本；并非每次都改全部层次。涉及行为、依赖或 CI 的修改另按实际风险立项，不由本轮文档授权自动实施。
3. **记录边界变化。** 写旧范围/旧规则、改变依据、新范围/规则、受影响消费者和需重新验证的证据。修改唯一权威文件并链接 C/T；旧规则保留被替代原因，后续工作区核对版本。不得复制多份相互冲突的规范。
4. **把改进落在任务。** 规模小且同一验收范围可并入修复 T；跨模块、单独交付或跨版本观察须建/关联明确 T，写负责人、产物、验收和检查时点。仅写“后续注意”不算任务；决定延期写原因、风险、责任人与恢复触发，不能把改进一起悄悄关闭。
5. **验证防线有效。** 条件允许时在隔离环境用原失败输入/旧行为证明检查会失败，再确认修复后通过；不能复现原错误时说明限制，不编造红绿结果。视觉审阅使用已确认基准与可重复场景。同类使用方和直接下游按影响清单验证，不默认重跑全仓。
6. **接收并看后效。** 本次必需的修复与预防检查过后才能验收；确可分离的后续观察保留关联任务和触发条件。修复验收、预防实现、后续效果是不同证据，不能由某一项推定其他项。无适用事件/版本出现时记录未观察，不以“暂未收到投诉”证明有效。

### 复验时点、度量和规则维护

- 每次修复交付：检查原场景、同类使用方、命中 L/F、漏检原因和改进证据；未满足的必需项保留原 T 未完成。
- 下一次触碰同类组件/模块：开工复读规则并检查旧用例仍被实际执行、基准/候选未漂移；新事件可追溯到原改进。需要跨任务观察时由关联 T 承接，写明“下一次适用变更/指定候选”等实际触发，目标版本未知就写待定及由谁确定。
- 里程碑验收/每次发布准备：主代理汇总未关闭的重复问题、跨模块争议、漏测和改进任务；依据当前证据调整范围/优先级，保留决策。未发生发布不虚构复盘；本约定没有启动定时自动巡检或消息提醒。
- 统计必须带候选/时间窗口、筛选条件及分母：适用已验证场景数/确认应验场景数（执行覆盖）、验收后发现的已确认缺陷数/该窗口已确认缺陷总数（逃逸比例）、关联既有模式且确认复发的缺陷数/该窗口已确认缺陷总数（复发比例）。用户报告未复现、重复归并和范围外问题单列；分母为零或缺失写不适用/未知，不填 0% 或 100%。数量和趋势帮助决策，不替代严重程度及个案证据。
- 规则可升级也可收缩：新证据证明规则不适用、已被更有效防线取代或成本失衡时，记录依据、影响、替代版本及接收结论；保留历史，不删旧失败。不能为让当前失败通过而降低已确认标准。

## L-001 图标与文字对齐

- 来源：用户报告“文字图标不对齐”且相同问题频繁出现；2026-11-02 归档，历史发生日期/次数待补。
- 已核实：[现有辅助](../../e2e/support/icon-label-alignment.ts)仅测部分按钮/链接/summary 中的单图标和文字，遇到多行会返回空集合。这是检查盲区，尚不能认定某个页面错位的代码根因。
- 约束：单行文字居中/基线、多行文字对齐首行或文本块由有效设计分别定义；统一图标尺寸、文字行高及必要的明确变体。不得把单行检查通过推导成多行通过，不用每页任意偏移代替共同原因修复。
- 防复发检查：覆盖单行、两行、长英文、数字、禁用/加载及有无图标的适用状态；记录预期位置和实际渲染。适用目标不存在或检查器跳过必须显式报告，不能计为通过。
- 接续：T-004 定位复现及设计规则，T-005/T-008 修复，T-009 建立有效回归；2026-11-02 尚未新增这些回归；后续 C7 新增范围见文末 E-022。

## L-002 列表列线与间距

- 来源：用户报告“list 列表间距不对齐”；具体页面、角色与数据待 T-004 主动遍历定位，不要求用户逐一提供截图。
- 根因：待复现；有无图标、描述、标签、操作按钮导致布局变化只是待检查条件，未认定为实际根因。
- 约束：同类列表行共用列结构、内容起点、左右留白和操作区；允许按设计使用不同高度/密度，不强行把多行内容压成单行。表格各列按用途和批准设计对齐，不一律居中。
- 防复发检查：相邻行、首末行、空值、缺少描述、长名称、多行、分页/加载后和窄屏；比较列起点、操作列位置及行内/行间间距，保留截图审阅。
- 接续：T-004～T-009；每个实际缺陷关联具体复现与回归，不以“列表已统一”批量关闭。

## L-003 边距缺失或重复

- 来源：用户报告“边距丢失，边距异常”；[已有局部检查](../../e2e/feedback-layout-parity.spec.ts)检查部分展开面板底部留白，[操作容器检查](../../e2e/01-system-dialog-surfaces.spec.ts)检查部分重复 padding，不能据此代表所有页面。
- 根因：具体页面待核实；父子重复提供间距、容器替换后间距无人负责等作为检查方向，不能写成已证实结论。
- 约束：每层容器的外部间距和内部留白明确归属；取值来自当前设计变量/批准样板。不能只判断值为偶数，或无依据叠加外边距来遮盖问题。
- 防复发检查：空/有内容、首末项、折叠/展开、滚动到底、短屏/长内容、底栏显示；测量实际内容到容器边缘距离，检查遗漏、重复留白与正文遮挡。
- 接续：T-004、T-005、T-008、T-009；局部历史证据只支持其候选和场景。
