# 弹窗与抽屉统一操作区 · 2026-10-28

在产品实现前更新原型。沿用现有视觉规范，所有示例操作只影响本地原型数据。

- 所有弹窗与抽屉都采用同一结构：header / content / footer。标题与关闭入口在 header，仅 content 独立滚动；footer 是布局中的固定兄弟节点，不覆盖正文。
- 保存、提交、确认、删除、预览下一步、取消及整批执行等当前操作的按钮统一在 footer 中靠右排列。智能问答属于同一个 footer 的辅助入口，位于左侧，与操作按钮同一行，不单独占一整行；选择数量等状态放在中间。窄屏可将状态移到操作上方，但智能问答与主操作保持同一底行。
- 全选、搜索、字段切换、添加一行、单行处理和验证码发送等内容内的辅助操作仍与对应内容相邻；涉及整张表单或整个弹窗的确认放在 footer。
- 短表单不保留多余空白。长表单与详情列表在 content 中滚动，header 和 footer 始终可见。底部保留正文内边距，不用绝对定位或固定高度挤占正文。
- 手机宽度下操作组换行、按钮文字完整；深浅主题沿用现有表面与边框变量。
- 迁移按钮时保留原生 form 归属、required 校验、回车提交、pending/disabled 和当次确认；不改变 API、权限或外发范围。

## 代表状态

“项目计划 → 新建工作项”更新为“添加人工工作项”：content 只包含说明及表单字段，“取消 / 加入项目计划”位于 footer。该规范同样应用于目标创建、资料、连接与设置、成员及管理表单。

## 资料页切换与上传后状态

- “资料 / 整理结果 / 识别任务”立即切换当前栏目并保留可复制地址、浏览器前进后退；只为当前栏目加载必需列表，初次读取仍保留整理结果的数量提示。
- 已被项目记录引用的资料不能删除，拒绝删除不会隐藏列表或将列表标记为读取失败。
- 图片保存后明确显示“等待图片识别”，尚未发起识别请求；下一步指向刚上传的文件，而不是无定位的文件列表。用户在该文件读取摘要、确认发送后才创建识别任务。
- 按文件区分本地解析中、等待图片识别、等待核对、失败和已形成资料，混合上传逐项显示；图片识别并不等同于资料整理。
- 文件定位视图只展示目标文件，并提供“查看全部文件”；后台识别状态可手动刷新，不自动重发模型请求。
- 添加资料抽屉的保存文本、上传文件、继续识别等末端操作同样进入 footer；正文只保留输入、文件选择和状态说明。
# 文件选择与大文件上传补充

- 文件选择窗口展示全部文件，选择后按真实支持的扩展名提示；DOCX/PDF 不依赖 Windows/WPS 的 MIME 关联。
- 项目上传取消默认单文件、图片文件和上传请求的字节门槛，采用流式存储。容量预算、并发和格式/解析保护继续生效。
- 保持现有 header/content/footer 布局；上传区分别说明文件保存与解析能力，超出解析能力时明确保留原文件并提示拆分。


## 文件导入弹窗布局补充

- 主问题是“本次要导入哪些文件”，content 首先展示一个中性文件选择区，文件和文件夹是同一组选择操作；不再并排放两个大色块。
- 已选文件逐行展示名称、大小与移除操作。空状态不给大段容量和服务端实现规则，保留一句“原文件先保存，图片识别需要单独确认”。
- 格式、当前项目容量与真实处理限制收进“格式与容量说明”，默认展开、允许手动收起；删除部署总量、保留对象和请求实现术语的平铺统计卡。
- 固定 footer 左侧为智能问答，邻近位置显示本次选择数量，右侧放“取消 / 上传并解析”，问答入口与主按钮同排；上传中禁用再次选择和移除。content 再长也不影响主操作位置。
- 沿用当前产品字体、配色和基础组件，只调整本弹窗的信息层级与密度。
