# AI Project OS V2.3.0 操作手册

本文档面向 AI Project OS V2.3.0 本地管理员，说明从首次启动、Dashboard、个人中心、模型与 GitHub 配置，到项目记忆、治理审核、项目归档、安全导出、只读智能体、备份和故障排查的完整操作流程。

页面内的简明指南位于：<http://127.0.0.1:3000/guide>

## 1. 当前版本能做什么

V2.3.0 提供以下页面能力：

- 本地单管理员登录与会话保护。
- 使用 Dashboard 汇总配置进度、项目指标、最近任务和推荐下一步。
- 在独立“项目”页面搜索、创建或直接进入项目工作区。
- 在个人中心查看账户与会话状态、修改登录名、轮换密码和退出登录。
- 在页面配置、测试和轮换 OpenAI、DeepSeek、Qwen、GLM API Key。
- 为每个项目分别配置自动抽取、语义向量和引用式生成路由，并在切换前预览对历史结果和活动索引的影响。
- 手工录入原始项目资料，创建并审核可追溯条目。
- 使用只读 GitHub PAT 连接多个仓库，冻结 commit 后扫描代码并同步仓库资料。
- 自动抽取 decision、progress、issue、risk 候选，人工审核后进入已确认事实。
- 对项目资料、多仓库资料和代码快照建立统一语义索引。
- 执行语义搜索、带引用 RAG、项目当前状态简报和单次只读智能体调查。
- 保存任务、传输授权、供应商调用、Token 用量、调查计划、工具轨迹和证据快照。
- 在治理与审核中心统一处理候选审核、未知任务收口、路由审计和 7/30/90 天模型用量。
- 在项目页归档或恢复项目，并生成不包含凭据、向量和原始任务载荷的受限 JSON 导出。

V2.3.0 不提供自动改代码、Shell、文件系统操作、GitHub 写入、定时自主运行、MCP、部署执行、多用户、RBAC 或 SSO。

## 2. 推荐使用顺序

首次使用按以下顺序完成：

1. 启动 Docker Compose，并创建本地管理员。
2. 在“模型与系统设置”添加供应商并通过连接测试。
3. 进入 Dashboard，根据“推荐下一步”和“工作空间就绪度”完成初始配置。
4. 进入顶部“项目”页面创建项目，并从项目卡直接进入“智能控制台”配置三条 AI 路由。
5. 手工录入项目资料，或连接并扫描 GitHub 仓库。
6. 在“智能记忆”自动抽取候选并人工审核。
7. 在“治理与审核”统一检查待审核候选、未知任务和路由变更。
8. 建立统一语义索引。
9. 执行语义检索、引用式问答或项目智能体调查。

日常更新建议遵循：

```text
新资料或代码变化
→ 扫描/同步仓库
→ 自动抽取
→ 人工审核
→ 重建语义索引
→ 生成项目简报或提问
→ 核对引用和不确定性
```

## 3. 启动和首次初始化

### 3.1 启动服务

在项目目录执行：

```bash
docker compose config --quiet
docker compose up -d --build
docker compose ps --all
```

正常状态应满足：

- `postgres` 为 `healthy`。
- `migrate` 为 `Exited (0)`。
- `app` 为 `healthy`。

健康检查：

```bash
curl --fail http://127.0.0.1:3000/api/health
```

响应中的 `status` 应为 `ok`，`database` 应为 `up`，`version` 应与当前版本一致。

### 3.2 创建管理员

首次打开 <http://127.0.0.1:3000> 会进入初始化页：

- 用户名长度为 3–64 位。
- 密码长度为 12–128 位，并同时包含字母和数字。
- 当前版本只支持一个本地管理员。

管理员密码不会明文保存。忘记密码时当前版本没有页面化找回流程，因此应自行安全保管。

### 3.3 保护持久化数据

Compose 使用两个关键命名卷：

- `ai-project-os-pgdata`：PostgreSQL 项目数据。
- `ai-project-os-secrets`：用于解密已保存 API Key 和 PAT 的主密钥。

不要执行：

```bash
docker compose down -v
```

删除数据库卷会丢失项目数据；删除 secrets 卷会导致数据库中的既有凭据无法解密。

### 3.4 使用 Dashboard

登录后默认进入 <http://127.0.0.1:3000/dashboard>。Dashboard 是日常工作的起点：

- 顶部“推荐下一步”根据模型连接、项目、路由和智能记忆状态给出当前最需要完成的操作。
- 指标卡汇总项目、已确认事实、已连接仓库和有活动索引的项目数量。
- “工作空间就绪度”展示模型、项目、路由和索引四个阶段的完成情况。
- “最近任务”展示仓库扫描、资料同步、索引、抽取、问答、简报和智能体调查状态。

所有登录后的主要页面顶部使用同一套全局导航。主导航只包含 Dashboard、项目和模型设置；使用指南从头像旁边的“帮助”入口打开，不占用业务 Tab。进入项目后还会显示固定的项目内导航，便于在五个工作区之间切换，并可从右侧“查看指引”进入当前任务对应的说明。

### 3.5 使用项目页

点击顶部“项目”进入 <http://127.0.0.1:3000/projects>：

- 按名称、描述或 slug 搜索项目。
- 创建新的项目空间。
- 从项目卡直接进入“资料”“控制台”“记忆”或“智能体”。
- 在“进行中”和“已归档”之间切换；归档前需要输入项目名称确认，恢复不删除历史记录。
- 为进行中或已归档项目下载受限 JSON；下载后页面会显示文件 SHA-256 前缀以便核对。
- 进入项目详情后，顶部“项目”Tab 继续保持选中，项目内导航用于切换资料、智能控制台、智能记忆、项目智能体和治理与审核五个工作区。

### 3.6 使用个人中心

点击顶部右侧头像进入 <http://127.0.0.1:3000/profile>：

- 查看账户类型、创建时间、最近活动、活动会话数量和最近活动会话的到期时间。
- 修改登录名。新登录名必须为 3–64 位，以字母或数字开头，只能包含字母、数字、点、下划线和连字符。
- 在“登录与安全”中展开“修改密码”后轮换密码。必须先验证当前密码；新密码至少 12 位，并同时包含字母和数字，且不能与当前密码相同。
- 密码修改成功后，系统会撤销该账户全部会话并清除当前 Cookie，必须使用新密码重新登录。
- 模型 API Key 在“模型设置”中管理；GitHub PAT 在具体项目的“智能控制台”中管理，不会出现在个人中心。

## 4. 配置模型供应商

进入顶部全局导航的“模型设置”。

### 4.1 供应商能力

| 供应商 | 生成 | 向量 | 页面内置建议 |
| --- | --- | --- | --- |
| OpenAI | 支持 | 支持 | `gpt-4.1-mini`、`text-embedding-3-small` 等 |
| DeepSeek | 支持 | 不支持 | `deepseek-chat`、`deepseek-reasoner` |
| Qwen（阿里云百炼） | 支持 | 支持 | `qwen-plus`、`text-embedding-v4` 等 |
| GLM（智谱开放平台） | 支持 | 支持 | `glm-4-flash`、`embedding-3` 等 |

如果使用 DeepSeek 生成，还需要额外配置 OpenAI、Qwen 或 GLM 连接承担向量能力。

### 4.2 新增连接

填写：

1. 供应商类型。
2. 便于识别的连接名称。
3. API Key。
4. 生成模型 ID。
5. 供应商支持时填写向量模型 ID 和维度。

保存后执行“测试连接”。只有测试成功、状态为“已验证”的连接才能在项目路由中使用。

注意：

- 页面不会回显 API Key，只显示尾号。
- 网络请求只会发送到产品内置的供应商官方地址，不能配置任意 Base URL。
- 模型 ID 必须是供应商账号实际可用的模型。
- 向量模型维度必须准确，否则索引构建或查询会失败。
- 轮换 Key 后应重新测试连接。

## 5. 创建项目和手工资料

### 5.1 创建项目

在顶部“项目”页面点击“新建项目”，填写项目名称和可选描述。项目是资料、条目、仓库、索引、简报和智能体运行记录的隔离边界。

### 5.2 录入原始资料

进入项目“资料与条目”：

1. 新增项目资料。
2. 填写原始内容，不要只写二次摘要。
3. 可选填写安全的 `http(s)` 来源链接和采集时间。
4. 不要录入密码、Token、数据库连接串或带凭据 URL。

资料保存后会记录精确内容和 SHA-256。资料是候选证据，不自动等同于已确认事实。

### 5.3 创建并确认条目

创建条目时：

1. 选择类型：decision、progress、issue 或 risk。
2. 选择同项目 Source。
3. 填写标题和内容。
4. `sourceExcerpt` 必须是 Source 原文中的非空、连续、精确片段。
5. 保存后检查内容，再执行“确认”。

只有状态为“已确认”的条目才属于人工确认项目事实。编辑已确认条目会重新进入候选状态，需要再次确认。

### 5.4 生成人工快照

Project Snapshot 固定当前全部已确认条目的状态，用于人工确认读取点。条目变化后页面会提示快照过期，需要手动重新生成。

## 6. 配置项目 AI 路由

进入项目“智能控制台”，分别保存：

| 路由 | 用途 | 要求 |
| --- | --- | --- |
| 语义向量 | 建立索引、处理查询向量 | 供应商支持 embeddings，模型和维度准确 |
| 自动抽取 | 从原始资料抽取候选条目 | 已验证的生成模型 |
| 引用式问答 | RAG、项目简报、智能体规划与回答 | 已验证的生成模型 |

每个项目独立保存路由。保存前页面会先显示影响预览：更换自动抽取或引用式生成路由只影响后续任务，历史结果仍保留原供应商和模型来源；更换向量连接、模型或维度会暂停语义搜索、RAG 和项目智能体，必须勾选确认并重建索引。若预览后路由已被其他操作更新，保存会被拒绝并刷新预览，不会覆盖较新的配置。

## 7. 连接 GitHub 多仓库

### 7.1 准备 PAT

使用 GitHub fine-grained PAT：

- 只选择本项目需要读取的仓库。
- 只授予已启用内容类型所需的读取权限。
- 代码扫描至少需要读取仓库内容。
- 不授予写入、管理、工作流修改等无关权限。

### 7.2 连接仓库

在“智能控制台”填写：

- Owner 和 Repository。
- 首次连接时的 fine-grained PAT；已有同一项目凭据时可复用。
- 跟踪分支。
- 仓库角色，例如主仓库、应用、基础设施或文档。
- 代码扫描根目录。
- 可选 Markdown 路径。
- 要同步的 README、Issue、PR、Release 等内容类型。

一个项目可以继续添加多个仓库。

### 7.3 扫描和同步

- “扫描全部代码仓库”会冻结明确 commit，读取配置范围内代码，并按仓库级原子发布。
- “同步仓库资料”按单仓库同步启用的 README、Markdown、Issue、PR 和 Release。
- 失败时不会用不完整结果替换上一代已发布内容。
- 在页面底部“最近任务”检查状态、阶段和安全失败码。

GitHub 连接器只执行固定 `api.github.com` GET 请求，不创建分支、评论、Issue 或 PR。

## 8. 自动抽取与人工审核

进入项目“智能记忆”。

### 8.1 自动抽取

1. 选择需要处理的 Source。
2. 阅读传输说明。
3. 勾选本次传输确认。
4. 执行自动抽取。

模型会尝试返回 decision、progress、issue 和 risk 候选。以下情况会整次拒绝：

- 返回结构不符合严格 schema。
- 引用了未选择 Source。
- `sourceExcerpt` 不是原文中的精确连续片段。
- 返回未知字段、越界内容或无效状态。

### 8.2 审核候选

逐条核对模型、标题、内容、Source 和原文摘录：

- 接受：候选条目变为已确认事实，并保留作业、模型和修订记录。
- 驳回：保留审核记录，但不进入已确认事实。

不要批量接受未经核对的模型结果。

## 9. 建立统一语义索引

### 9.1 索引内容

活动索引包含当次输入清单中的：

- 项目人工资料。
- 当前已发布的仓库资料生成。
- 当前项目代码快照中的仓库代码。

### 9.2 构建索引

1. 确认语义向量路由已配置并通过测试。
2. 确认项目已有可索引资料。
3. 选择“全量构建”或“增量构建”。页面会先计算本次计划，显示供应商、模型、维度、待生成数量、可复用数量、删除数量和预计向量请求次数。
4. 阅读索引专用传输确认：所有待生成片段会发送给供应商，已复用的兼容向量不会再次外发；全量构建不复用旧向量，增量构建只复用兼容基线中的向量。
5. 勾选本次确认并点击建立或重建索引。

系统分批生成向量，全部成功后才原子切换活动索引。构建失败时保留上一代活动索引。

切换构建模式、计划刷新或服务端返回“计划已过期”时，确认勾选会自动清空，必须重新查看计划并重新确认。任何失败或未知结果都不会自动重试模型；未知结果需在页面执行人工收口。

### 9.3 何时重建

以下变化后应重建：

- 新增或更新项目资料。
- 新的仓库扫描成功发布。
- 新的仓库资料同步成功发布。
- 更换向量供应商连接。
- 更换向量模型或维度。

如果页面显示“索引需要重建”，语义查询和项目智能体会保持禁用，直至当前路由生成新索引。

## 10. 语义搜索和引用式问答

### 10.1 语义搜索

输入明确问题并确认本次传输。结果会显示：

- 命中原文。
- 内容路径或外部引用。
- 仓库内容对应的冻结 commit。
- 语义、关键词和综合分数。

### 10.2 引用式问答

引用式问答只把本次命中的证据片段发送给生成模型。模型返回的引用 UUID 必须属于本次检索集合；引用越界时回答会被拒绝保存。

回答用于理解项目，不会自动创建已确认 ProjectItem。需要成为项目事实时，应回到资料与条目流程人工录入和确认。

## 11. 项目状态简报和只读智能体

进入项目“项目智能体”。

### 11.1 就绪条件

页面必须同时确认：

- 生成模型路由可用。
- 向量模型路由可用。
- 存在与当前向量连接、模型和维度完全兼容的活动索引。

### 11.2 生成当前状态简报

1. 勾选本次传输确认。
2. 点击“生成当前状态简报”。
3. 检查状态、标题、摘要、进展、决策、问题、风险、关注事项和待确认问题。
4. 展开“证据快照”核对来源。

简报只基于当次收集到的项目概览、已确认条目、仓库状态和语义记忆。

### 11.3 向智能体提问

适合的问题示例：

- 当前最需要关注的风险是什么？
- 哪些关键决策仍缺少证据？
- 最近完成了哪些可验证进展？
- 当前仓库和项目事实之间有什么不一致？

智能体先返回受约束计划，服务端只允许四个工具：

- 项目概览。
- 已确认条目。
- 语义记忆检索。
- 仓库状态。

未知工具、写入工具、重复单例工具、额外字段或越界引用都会被拒绝。

### 11.4 核对回答

重点查看：

- 回答正文和证据编号。
- 建议是否有证据支持。
- “证据不足与不确定性”。
- 只读调查轨迹和每个工具的结果数量。
- 固定保存的证据快照和 SHA-256。

证据不足时应补充资料、确认条目或重新扫描仓库，不应把模型推测直接转成事实。

## 12. 治理与审核中心

进入项目“治理与审核”，可以从使用者角度统一检查四类需要关注的状态：

- 待审核候选：同时显示网页自动抽取候选和已验证 AI 运行候选，仍需逐条接受或驳回。
- 任务异常：区分失败、部分完成、限流和未知结果；未知不等同成功或失败。
- GitHub 与索引风险：显示项目同步异常和当前语义索引是否需要重建，并提供原业务页面入口。
- 模型路由记录：只读展示原路由、新路由、操作人、时间以及是否使索引失效。

### 12.1 审核候选

候选卡只显示审核需要的条目内容、精确原文摘录、Source 类型和内容哈希，不展示完整 Source 原文。接受或驳回后页面会重新读取服务器状态；如果条目已被其他操作修改，会提示刷新，不会在浏览器中伪造成功。

治理中心不提供批量接受。已接受候选才进入确认事实；已驳回候选保留审核记录。

### 12.2 收口未知结果

- 通用 AI 任务、项目级 GitHub 同步和语义索引只在具备对应不可变审计证据时显示“人工收口”。
- 人工收口不会重新调用模型、GitHub 或向量接口，也不会把未知状态改写为成功或失败。
- 旧式单仓库代码扫描或资料同步若仍有未知子运行，会明确显示“需要专用收口”，当前不能用通用动作解除阻塞。
- 需要重新执行时，应进入原业务页面重新选择范围、重新确认传输并创建新任务。

### 12.3 只读审计边界

治理页面的读取请求不会触发模型调用、GitHub 访问、索引构建或自动重试。模型路由历史只能查看，不能在治理页面编辑或回滚；如果路由切换使索引失效，应进入“智能记忆”显式重建。

### 12.4 查看模型用量

“模型用量”可切换最近 7、30 或 90 天，并按供应商、模型和能力查看调用次数、输入 Token、输出 Token、失败和未知请求。

- 现行页面工作流读取 `ProviderCallAudit`，每次受审计的供应商调用尝试计一条。
- 旧运行台账读取 `AiRun.requestCount`，不把运行记录数误当作请求数，也不与现行审计重复。
- 页面没有供应商价格快照，因此不会把 Token 估算为金额。费用以对应供应商账单为准。

## 13. 项目归档、恢复与安全导出

### 13.1 归档项目

在顶部“项目”页面点击项目卡中的“归档”，输入完整项目名称后确认。归档会把项目移入“已归档”列表，并拒绝项目修改和新任务，但不会删除资料、事实、仓库记录、索引、AI 结果或审计记录。

存在排队中、等待确认、运行中或仍需人工收口的任务时，系统会拒绝归档。应先等待任务结束、取消尚未执行的任务，或在“治理与审核”完成允许的人工收口。

每次归档或恢复都会写入不可变生命周期审计。归档项目可在“已归档”列表点击“恢复项目”重新启用。

### 13.2 导出受限 JSON

进行中和已归档项目都可以从项目卡点击“导出 JSON”。导出包含项目元数据、Source 正文、事实及其版本与证据、仓库身份、AI 路由历史、生命周期历史、安全任务状态和已保存的问答/简报/智能体结果。

导出明确排除：

- 系统凭据库中的模型 API Key、GitHub PAT、密文、nonce、认证标签和密钥指纹。
- 向量、索引内部记录及仓库扫描中间账本。
- 原始任务 payload/result、幂等键、租约令牌和供应商请求 ID。
- 仓库代码文件正文及完整数据库恢复所需数据。

导出在一个一致性事务内生成，最大 20 MiB，并写入包含字节数和 SHA-256 的不可变审计。JSON 会原样包含项目正文；如果使用者曾把密码或 Token 错误录入 Source 或条目，它们也会随正文出现，因此导出文件必须保存在可信位置。

受限 JSON 用于核对和迁移核心项目内容，不是数据库备份，也不能恢复加密凭据、索引或完整运行状态。灾难恢复仍应使用第 16 节的 PostgreSQL 与主密钥备份流程。

## 14. 外部模型传输边界

每一次自动抽取、索引构建、语义查询、RAG、简报或智能体调查都要求页面当次确认。

确认前应理解：

- 操作会使用自己的供应商额度并可能产生费用。
- 只发送当前操作明确选择或检索命中的内容，不发送未命中的完整项目库。
- 索引构建会发送计划中所有待生成向量的片段；增量构建复用的向量不会外发，全量构建不会复用旧向量。
- 项目资料和仓库内容被视为不可信文本，其中的提示词或命令不会获得系统权限。
- 授权记录绑定项目、operation、provider、model、输入清单指纹、用户和有效期。

## 15. 常见问题排查

### 15.1 供应商未出现在路由选项

检查：

- 连接是否已经执行测试。
- 状态是否为“已验证”。
- 供应商是否支持目标能力；DeepSeek 不能用于向量路由。
- 模型 ID 和向量维度是否填写完整。

### 15.2 显示“请先使用当前向量模型建立项目索引”

常见原因：

- 尚未建立索引。
- 向量连接已经改变。
- 模型 ID 或维度已经改变。
- 旧索引为空或发布未完成。

使用当前语义向量路由重新建立索引。

### 15.3 模型输出无法验证

系统会拒绝不符合结构、摘录或引用边界的响应，不会保存为可信结果。可以：

- 重试一次。
- 检查输入 Source 是否包含足够的明确原文。
- 使用结构化输出更稳定的生成模型。
- 缩小问题范围。

### 15.4 GitHub 无法读取

检查：

- PAT 是否覆盖正确仓库。
- 目标仓库是否已改名、归档或转移。
- 跟踪分支是否存在。
- 所需读取权限是否开启。
- API 是否限流。

应用不会自动扩大 PAT 权限或改用其他仓库。

### 15.5 页面任务失败

页面任务在 Next.js 单体进程中执行。运行期间应保持应用服务可用。刷新后在“最近任务”查看持久化状态；安全错误只返回稳定 code/message，不回显供应商原始错误体或凭据。

### 15.6 应用不健康

执行：

```bash
docker compose ps --all
docker compose logs --since 10m migrate
docker compose logs --since 10m app
curl --fail http://127.0.0.1:3000/api/health
```

不要在没有备份的情况下删除卷或重建数据库。

## 16. 数据库备份

升级或进行高风险维护前，先创建 PostgreSQL custom-format 备份。以下命令使用 Compose 默认数据库用户名和数据库名；如果 `.env` 自定义了 `POSTGRES_USER` 或 `POSTGRES_DB`，请替换为实际值。

```bash
docker compose exec -T postgres \
  pg_dump -U ai_project_os -d ai_project_os -Fc \
  -f /tmp/ai-project-os-backup.dump

docker compose exec -T postgres \
  pg_restore -l /tmp/ai-project-os-backup.dump

docker compose cp \
  postgres:/tmp/ai-project-os-backup.dump \
  ./ai-project-os-backup.dump
```

验证主机文件存在且大小非零：

```bash
ls -lh ./ai-project-os-backup.dump
```

备份文件包含项目资料和加密凭据，但不包含 secrets 卷中的主密钥。若要保留凭据可恢复性，还必须安全备份主密钥卷；主密钥属于敏感材料，不应提交到 Git 或传入项目资料。

数据库恢复会覆盖或合并数据，属于破坏性操作。本手册不提供可直接复制执行的恢复命令；应先停止应用、核对目标数据库并保留现有备份，再按 PostgreSQL 恢复流程操作。

## 17. 更新应用

更新代码前：

1. 确认工作区和目标版本。
2. 备份数据库和主密钥。
3. 阅读目标版本迁移说明。

更新后执行：

```bash
docker compose up -d --build
docker compose ps --all
curl --fail http://127.0.0.1:3000/api/health
```

Compose 会等待 PostgreSQL 健康，运行一次 `prisma migrate deploy`，迁移成功后才启动新应用。

## 18. 删除与保留边界

- 当前版本提供项目软归档和恢复，但不提供项目永久删除 API 或页面入口。
- 页面只允许删除尚未被任何 Item 引用的候选 Source；被引用的资料会拒绝删除。
- 仓库连接和供应商连接可在对应页面删除；删除前应确认没有仍需保留的项目配置。
- 全局供应商连接和加密凭据独立于单个项目保存。
- 受限 JSON 不包含凭据、向量或完整数据库状态；当前版本没有页面化备份恢复、回收站和凭据导出功能。
- 执行任何删除前都应确认精确对象，并保留必要备份。

- [ ] 至少一个生成供应商已验证。
- [ ] 至少一个向量供应商已验证。
- [ ] 项目三条 AI 路由已保存。
- [ ] 至少一条手工资料可读取。
- [ ] 至少一个候选条目已经人工确认。
- [ ] “治理与审核”可以读取待审核候选、任务异常和只读路由历史，且不会自动执行外部操作。

- [ ] 进行中和已归档项目均可下载受限 JSON，响应包含导出审计 ID 与 SHA-256，文件不含凭据或向量。

只有容器健康并不代表 AI 能力已经配置完成；模型路由、索引、页面行为和证据引用都通过后，才算完成实际使用验收。
