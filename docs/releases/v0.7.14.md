# v0.7.14 — OAuth 同意回调策略修复候选

## 修复范围

- Next 16 会保留全局响应头而不以 Route Handler 的同名头覆盖它。现在精确路径 `/mcp/authorize` 不接收全局 CSP；其他路径继续保留原有 CSP 与安全响应头。
- OAuth 成功同意页根据已绑定、严格校验的注册回调 URI 设置精确 `form-action` 来源，避免跨端口回调被浏览器 CSP 阻止。Origin、CSRF、PKCE 和回调 URI 精确匹配校验保持不变；含通配符的回调主机名拒绝。
- 对 CSP 无法准确表达的 IP 字面量和主机名，同意后返回无脚本、严格 CSP 的安全确认页，由用户通过 `rel="noreferrer"` 链接继续到已验证回调。批准和拒绝响应都会清除本次 CSRF Cookie；授权码仍单次使用。

## 生产与本地证据

- v0.7.13 已上线并通过健康检查。生产两次原生同意提交均创建了 grant，但浏览器没有发出回调请求；没有 token 交换或 MCP 项目读取。相关 grants 已撤销，验收 runner 已停止。
- 隔离的 Next 16 与 Chromium 验证确认：对 127.0.0.1，成功页精确 CSP 保留在实际响应中，原生表单 303 到不同端口后到达回调，且不发送 Referer。对 IPv6，严格静态 CSP 下的手动确认链接到达回调，且不发送 Referer。这些是本地协议验证，不代表生产 OAuth 闭环已通过。
- 生产 OAuth 回调、token 交换和 MCP 读取仍待此候选上线后重新验收。GitHub README 自动读取的现场验收也仍未完成；本版本不改变 Git 凭据或读取逻辑。
