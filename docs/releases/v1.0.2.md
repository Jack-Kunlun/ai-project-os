# v1.0.2 — 账号与个人知识修复

本版本基于 `v1.0.0` / `f57d050fffa445a6ef9eb3d7e692e6df06fac98d`。发布复用同 SHA 的主分支 CI，线上状态以公网 `/api/health` 和生产发布回执为准。

## 本版本变更

- 短信发送先验证图形验证码；图形验证码错误不会消耗短信发送预算，短信应用限流、图形码错误和边缘代理 429 会显示各自的错误，不会错误启动短信倒计时。
- 注册、登录、改密和恢复密码统一接受 8–128 位并继续要求字母与数字。8 位密码可用，既有符合原策略的密码继续有效。
- 完成邮箱或手机号验证的本地自助注册（含短信登录自动注册）在创建账号的同一事务中按当前启用策略激活赠送权益。默认策略为 500,000 Token、有效期 30 天；策略停用或缺失时不发放。未验证的旧用户名注册路径及历史漏发账号不补发。
- 个人知识库把浏览/搜索与新建/编辑分区；个人语义检索可选择经验证可用的平台向量模型或个人 BYOK 连接，并在发送前确认范围与额度。平台托管额度属于用户账号；BYOK 仍由用户承担对应供应商用量。

本版本新增两条 Prisma 迁移：`20261015010000_add_local_registration_entitlement_source` 和 `20261015020000_bind_personal_semantic_token_reservations`。迁移清单由 `v1.0.0` 的 143 条增至 145 条。是否已应用生产数据库迁移，以现场数据库账本及发布回执为准。

## 发布验收要求

发布目标必须是主分支与 annotated `v1.0.2` 标签指向的同一 SHA。本次包含认证、额度、迁移和发布工具变化，按高风险运行一次完整主分支 CI，包括 PostgreSQL 迁移、平台个人语义、BYOK 语义和账号认证门禁；发布复用此结果，不重复标签全套测试。生产切换前核对 `v1.0.0` 来源回执、健康状态、数据库 143 条迁移账本、运行配置及当前活动模型路由和额度策略。

正式版本通过 [release-stable.yml](../../.github/workflows/release-stable.yml) 手动发布，由用户在 GitHub Actions 点击 Run workflow，选择 `main`。工作流复用该提交覆盖实际生产源版本与累计风险的成功主分支 CI，创建或复用指向同一 SHA 的 annotated 版本标签，再调用永久受限发布器 `deploy/production/ai-project-os-release-stable.py`。提交代码或 CI 通过不会自动上线。日常版本由工作流完成构建、备份和切换，数据库操作按风险及迁移差异执行，操作说明见[正式版本发布](../production-release.md)。

永久发布通道首次接入属于管理员的一次性基础设施配置：只安装经同 SHA 主分支完整 CI 验证的发布器、备份脚本、备份产物检查器、sudoers 与 SSH gateway，不构建或切换应用。后续版本复用该通道；修改主机工具、网关或基础设施契约时仍需单独的运维升级。当前通道是否已接入、此版本是否已上线，分别以服务器工具状态和实际发布回执为准。

生产切换会先固定目标镜像 ID，再停止三个写入服务和 Nginx，完成停写备份，并在无外部网络和无发布端口的隔离 PostgreSQL 中恢复备份、从 143 条迁移升级至 145 条并运行权限协调。备份和恢复检查成功后才会尝试生产迁移。迁移尝试前失败时，部署器恢复精确源版本及原 Nginx 配置；迁移尝试后失败时保持服务停写并要求人工恢复。完整生产结果以目标迁移账本、部署回执和公网 `/api/health` 为准；源文件或隔离验证本身不表示生产已上线。
