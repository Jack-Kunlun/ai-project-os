# AI Project OS 0.1.0-dev.1 内部开发版操作手册

本文档面向本地管理员、工作区管理员和项目成员，说明 AI Project OS 0.1.0-dev.1 内部开发版的本地部署、页面配置、资料接入、智能记忆、时态项目世界模型、自动化、受控动作、远程只读 MCP 工具、证据驱动项目运营、团队权限、OIDC、备份和排错。

当前状态：`INTERNAL_DEVELOPMENT`。正式发布基线为空，首个正式公开版本计划为 `1.0.0`。生产部署入口在首个正式 `v1.0.0` 前静态禁用，`0.1.0-dev.1` 不得进入生产 tag 通道。

页面内简明指南：<http://127.0.0.1:3000/guide>

## 1. 先理解三个边界

### 1.1 资料、候选与事实不同

- 文件、网页、仓库和手工原文是 `ProjectSource`，表示可追溯证据。
- AI 自动抽取先产生候选，不会直接成为可信事实。
- 人工确认后的 `ProjectItem` 才进入项目事实视图。
- 语义搜索和 RAG 会返回证据，但模型回答仍需要人核对。

### 1.2 页面配置与部署配置不同

模型 API Key、Git Token/密码/SSH Key、MCP Bearer Token、OIDC Client Secret 都在页面录入。`.env` 只用于数据库、端口和安全 Cookie 等部署基础设施参数。

### 1.3 自动化不会绕过模型外发确认

仓库同步、网页刷新和确定性记忆质量检查可以由 Worker 自动执行。记忆索引和项目简报会把任务停在“需要确认”，由用户在页面核对供应商、模型和输入范围后再发送。

### 1.4 受控动作不是任意智能体执行

“动作与审批”调用产品内置白名单中的三个现有能力：仓库同步、网页刷新和记忆质量检查；还可调用经过管理员验证、项目 Owner 逐项授权且逐次审批的远程只读 MCP 工具。动作不由模型生成；MCP 不支持 stdio、执行中交互输入或自动执行，也没有 MCP 写操作、Shell、代码写入、Git 写入或部署权限。

### 1.5 项目计划不是自动执行器

项目目标、工作项、负责人、期限、验收标准、证据、状态和依赖都由用户维护。智能体建议只有在 Editor 或 Owner 核对引用后才能纳入为 `proposed` 工作项；仓库变化只生成待评估信号。二者都不会自动成为执行动作，也不会触发代码修改、Git 操作、Shell 或部署。

### 1.6 项目世界状态不是 AI 判断

“项目状态”只读取当前有效、已确认事实、人工关系、开放冲突和项目计划健康度，并用本地确定性规则计算。AI 不会自动确认事实、建立关系、替代旧事实或固化快照；项目简报和只读智能体只能读取这份状态，不能覆盖它。

## 2. 启动与升级

### 2.1 首次启动

```bash
cp .env.example .env
# 编辑 .env，至少设置 POSTGRES_PASSWORD
docker compose config --quiet
docker compose up -d --build
docker compose ps --all
```

预期状态：

- `postgres`：`healthy`
- `migrate`：`Exited (0)`
- `app`：`healthy`
- `worker`：`healthy`

健康检查：

```bash
curl --fail http://127.0.0.1:3000/api/health
```

响应应包含 `status: ok`、`database: up`、`worker.status: up` 和 `version: 0.1.0-dev.1`。应用存活与 Worker 健康是两个独立信号：Worker 缺失、停止、降级或心跳超过 45 秒时，接口仍可返回应用 `status: ok`，但 `worker.status` 会明确显示异常状态，Worker 容器健康检查也会失败。

### 2.2 初始化管理员

首次打开 <http://127.0.0.1:3000> 会进入初始化页。管理员用户名为 3–64 位；密码为 12–128 位，并且同时包含字母和数字。

初始化完成后，系统建立默认工作区，并把管理员加入为 Owner。当前内部开发版页面只管理这个默认工作区，不提供工作区创建或切换。

### 2.3 更新现有部署

更新前先备份数据库、主密钥和上传文件，然后执行：

```bash
docker compose up -d --build
docker compose ps --all
curl --fail http://127.0.0.1:3000/api/health
```

Compose 会先执行所有未应用迁移，再启动应用和 Worker。不要执行 `docker compose down -v`。

### 2.4 对外提供服务

默认 Compose 绑定本机端口，适合本地使用。面向局域网或公网提供服务前，必须使用受信任的 HTTPS 反向代理，设置 `AI_PROJECT_OS_SECURE_COOKIES=true`，限制应用和数据库端口只允许必要来源访问，并为登录、OIDC 发起和初始化接口配置入口限流。完整核对项和 Nginx 示例见[部署安全基线](deployment-security.md)。

响应头由应用统一提供；HSTS 只能由确认全站 HTTPS 的入口代理启用。不要在仍需 HTTP 访问的环境中提前启用 HSTS。

### 2.5 持续集成

仓库的 GitHub Actions 工作流会在 push 和 pull request 上执行 Prisma/迁移校验、Lint、类型检查、覆盖率、全部一次性 PostgreSQL 门禁、生产模式浏览器与无障碍 E2E、性能预算，以及隔离 Compose 候选构建/迁移/重启门禁。工作流不读取真实模型、Git、OIDC 或 MCP 凭据；完整顺序、失败产物和本地复现方式见[持续集成与浏览器门禁](continuous-integration.md)，容器候选边界见[本地持续交付候选门禁](local-release.md)。

绿色 CI 不代表正式部署、备份恢复或外部服务已经验收。使用 Gitee、公司自建 Git 或其他 CI 平台时，应移植同一组仓库命令和隔离边界，而不是把 GitHub 当作唯一代码托管能力。

## 4. 账户、团队与权限

### 4.1 角色含义

工作区角色：

| 角色 | 权限 |
| --- | --- |
| Owner | 管理成员、邀请、OIDC 和工作区内全部项目；可授予 Owner |
| Admin | 管理成员、邀请、OIDC 和工作区内全部项目；不能修改 Owner |
| Member | 只访问单独授权的项目 |
| Viewer | 只读访问单独授权的项目 |

项目角色：

| 角色 | 权限 |
| --- | --- |
| Owner | 读取、编辑和项目归档/恢复 |
| Editor | 读取并修改项目内容，不能归档/恢复 |
| Viewer | 只读 |

系统始终保留至少一个启用状态的工作区 Owner。低权限邀请不会降低已有成员的工作区或项目角色。

### 4.2 创建本地成员

在“团队 → 成员”填写登录名、显示名称、邮箱、初始密码和工作区角色；可同时授予一个初始项目。密码请通过独立安全渠道交付。

成员邮箱用于邀请校验。OIDC 身份不会仅凭相同邮箱自动合并到已有本地账号。

### 4.3 邀请成员

在“团队 → 邀请”填写限定邮箱、工作区角色和可选项目。链接有效期为 7 天，只在创建响应中显示一次，应立即复制并通过安全渠道发送。

被邀请者需要先登录已有账户，或先通过允许自动建号的 OIDC 登录，再打开邀请链接。邮箱限定邀请要求账户邮箱完全匹配。

### 4.4 停用成员

停用会立即撤销该用户的活动会话。再次启用不会恢复已撤销会话，用户需要重新登录。停用用户不会删除其历史操作、证据或审计记录。

## 5. 配置 OIDC 企业登录

在身份提供商中创建 Web/OIDC 应用，并登记回调地址：

```text
http://127.0.0.1:3000/api/auth/oidc/callback
```

生产环境应使用站点的 HTTPS 域名，例如：

```text
https://project-os.example.com/api/auth/oidc/callback
```

然后在“团队 → 企业登录”填写：

- 名称和 Issuer URL
- Client ID 与 Client Secret
- Scopes，必须包含 `openid`
- Token 端点认证方式：`client_secret_post` 或 `client_secret_basic`
- 自动加入后的 Viewer/Member 角色
- 是否允许自动创建新账户，以及允许的邮箱域名
- 公司内网身份源才开启“允许受信任内网 OIDC”

保存时系统会读取 Discovery，检查 Code Flow、PKCE 和签名算法，解析并固定 Discovery、Token 与 JWKS 端点网络地址。公网端点默认必须是 HTTPS；云元数据地址始终拒绝。

登录回跳只接受单个前导斜杠的本站路径；绝对 URL、协议相对路径、反斜线以及编码或双重编码的路径分隔符都会安全降级到 Dashboard。每个身份源最多保留 200 条未消费登录流程；创建新流程时会在同一事务中清理过期流程，并淘汰最旧流程，不会因为匿名请求把所有用户锁死。匿名请求的速率限制仍应由反向代理或部署平台负责。

登录时系统校验 issuer、audience、nonce、过期时间和 JWKS 签名。相同邮箱的已有本地账户不会自动绑定；系统会拒绝这次 OIDC 登录，避免身份劫持。当前内部开发版尚无页面化显式绑定流程。

## 6. 配置模型供应商

在“模型设置”添加 OpenAI、DeepSeek、Qwen（阿里云百炼）或 GLM（智谱开放平台）：

1. 填写连接名称和 API Key。
2. 填写生成模型。
3. 按需填写图片识别模型。
4. 供应商支持 embeddings 时填写向量模型和实际维度。
5. 保存后执行连接测试。

只有状态为“已验证”且具备对应模型能力的连接，才能在项目 AI 路由中选择。网络目标固定为内置供应商官方 API，不开放任意 Base URL。

DeepSeek 当前不承担向量路由；语义索引可使用 OpenAI、Qwen 或 GLM。模型 ID 和向量维度必须与供应商实际配置一致。

## 7. 配置 Git 连接

在顶部“连接器”创建 Git 服务。支持：

- GitHub、Gitee、GitLab
- 自建 GitLab
- Gitea、Forgejo
- 通用 Git 服务

HTTPS 可使用无认证、Token 或 Basic；SSH 使用 SSH 私钥和精确的 known_hosts 行。自签 HTTPS 可以填写受信任 CA 证书。公司内网服务必须显式开启内网访问。

建议：

- 为连接创建只读、最小权限凭据。
- GitHub fine-grained PAT 只授权需要的仓库和 Contents Read。
- 不要使用个人主 SSH Key；为 AI Project OS 单独创建只读 Deploy Key。
- known_hosts 必须由可信渠道获取，不要在首次连接提示中盲目接受。

保存时系统验证地址、凭据和远端可达性。DNS 地址变化后会停止读取并要求重新确认。Git 执行关闭交互提示、系统/全局配置、非目标协议和重定向。

### 7.1 配置远程 MCP 只读工具

进入“连接器 → MCP 只读工具”：

1. 填写连接名称和 Streamable HTTP 端点。
2. 选择无认证或 Bearer Token；Token 会使用与其他凭据相同的 AES-256-GCM 机制加密保存。
3. 公网端点必须使用 HTTPS。公司内网端点需要明确开启“允许受信内网地址”；云元数据地址始终拒绝。
4. 保存后执行“发现并固化工具”。系统只使用当前 `2026-07-28` Streamable HTTP 协议，不启动 stdio、本地子进程或旧式 HTTP+SSE。

工具目录会按页读取并限制总数、Schema 深度和响应大小。每个有效定义保存为追加式快照，包含输入/输出 Schema、annotations 和 SHA-256 指纹。只有同时声明 `readOnlyHint=true` 与 `destructiveHint=false` 的定义才可申请管理员认证；这些 annotations 仍属于未受信提示，即使被伪造也不能直接获得授权资格。

5. 对每个需要开放的当前工具点击“管理员认证”，核对精确的工具定义、当前网络解析和凭据指纹，并留下说明/证据。认证和撤销都会写入不可改写的追加式审计。
6. 发现、网络解析或凭据轮换使任一指纹变化时，旧认证自动失效；管理员需要重新发现并重新认证。主动撤销认证后，关联项目授权和待调用动作也会失败关闭。

进入项目“工具权限”：

1. Owner 核对连接、工具说明、输入 Schema、定义指纹和管理员认证状态，并逐项确认授权。
2. Editor 或 Owner 为有效授权填写 JSON 参数并创建调用动作；没有当前管理员认证的工具会失败关闭。
3. 参数按固化 Schema 校验，动作同时绑定项目、授权、管理员认证、工具定义、网络和凭据指纹。
4. Owner 到“动作与审批”展开完整参数并逐次批准。MCP 能力不能改成自动执行。
5. Worker 执行前再次核对全部指纹和认证状态。工具更新、DNS 变化、凭据轮换、连接停用、认证撤销或项目授权撤销都会失败关闭，必须重新发现、认证、授权和创建动作。

MCP 响应有限时和大小上限；只保留受限文本与结构化结果，图片、音频和资源链接不会自动展开。成功动作的结果可在“动作与审批”中由 Editor 或 Owner 人工纳入，系统会核对并固定动作、输入、结果和内容指纹，创建一份未审核的 `mcp` 项目资料。纳入不会自动创建事实、重建索引、调用模型或让结果进入智能体；仍需按资料审核和索引流程处理。

## 8. 创建项目并接入资料

### 8.1 手工资料

进入“项目 → 资料与条目”：

1. 录入原始资料和可选来源链接。
2. 创建条目时选择同项目资料。
3. 引用资料中的精确连续原文。
4. 确认候选条目后，它才成为项目事实。

人工资料会按正文内容拒绝活动重复；仓库、网页和文件允许相同正文保留不同来源身份。

### 8.2 文件与本地文件夹

进入“文件资料”。支持 TXT、Markdown、JSON、CSV、PDF、DOCX、PPTX、XLSX、PNG、JPEG、WebP。一次最多选择 10 个文件，页面会逐个提交，服务端每个请求只接收一个文件；单文件最大 25 MiB，图片最大 10 MiB / 2000 万像素，单次 multipart 请求（含封装）最大 30 MiB。请求体即使没有 Content-Length，也会按实际读取字节数限制，并在 2 分钟总读取期限后终止；超过上限会返回稳定的 413，超时会返回 408。

上传策略由服务端统一执行：已登记版本与持久化上传预留的上传 blob 预算为每项目最多 1 GiB、每工作区 5 GiB、整套部署 20 GiB、每项目最多 100 个活动文件；项目、工作区和部署保留对象数分别最多 1000、5000 和 20000。每用户每分钟最多 20 次上传请求、同时最多 2 个，整套部署同时最多 2 个；全部署门禁在读取正文前通过 PostgreSQL 串行核验，用于限制多实例共同占用的请求内存。项目文件页和 API `GET /api/projects/:projectId/assets` 只向当前项目成员返回项目用量、项目保留对象数、活动文件数和当前用户进行中的上传；工作区与部署实际总量只在服务端用于校验，不向普通项目成员公开。软删除但仍保留的 blob 也继续计费；恢复或重复提交同一内容不会重复计费。崩溃遗留的上传预留会在租约到期后由 worker 有界核验；只有确认没有已登记版本，并且临时 blob 已删除或本来就不存在，才会释放预算。实际磁盘水位、目录元数据、服务器备份和物理 purge 仍需运维监控与处理。这些上限可由部署 `.env` 中的 `AI_PROJECT_OS_UPLOAD_*` 变量覆盖，变量必须是正整数且满足层级关系；错误配置会使上传接口失败关闭。

软删除只停止活动资料参与后续处理，不会立即物理删除上传卷中的 blob；只要 blob 仍存在，就继续计入项目、工作区和部署字节额度。重新上传同一文件恢复原资产，不会重复计费。物理 purge 与服务器备份清理由运维按保留策略另行执行，当前应用不会自动删除它们。

文件登记与一条本地解析任务在同一个数据库事务中提交。上传请求会立即尝试解析；如果进程在提交后退出，worker 会领取排队任务，或在 30 分钟解析租约过期后恢复中断任务。确定性解析失败会保留原文件和失败代码，不会无限自动重试；Editor 或 Owner 可在文件卡片中点击“重新解析”。

浏览器可以选择整个本地文件夹。系统只上传用户明确选择、格式受支持且满足大小限制的文件；不会获得任意本地文件系统访问权。

文本和 Office 文档优先在本地提取。原始图片和缺少文本层的 PDF 扫描页需要：

1. 在智能控制台配置视觉路由。
2. 核对待发送片段数量。
3. 勾选本次模型传输确认。
4. 逐片段编辑、接受或驳回。
5. 全部处理完成后原子发布接受的内容。

PDF 视觉渲染会先限制页面边长和像素预算；巨幅 MediaBox 会在分配渲染画布前被拒绝，不会触发视觉供应商调用。

Office 内嵌图片、音频和视频当前不会识别。

### 8.3 网页来源

进入“外部资料 → 添加网页来源”。公开网页默认要求 HTTPS；公司内网页面需要单独开启内网访问。系统会：

- 固定 DNS 地址并逐跳检查重定向
- 阻止云元数据与未授权私网地址
- 限制响应体和文本大小
- 移除脚本、样式与不可执行内容
- 新版本完整成功后再切换活动指针

网页抓取不执行 JavaScript，不登录站点，也不支持自定义 Cookie 或请求头。

### 8.4 多代码仓库

进入“代码仓库”：

1. 选择顶部“连接器”中已验证的 Git 服务。
2. 填写仓库路径、跟踪分支和项目角色。
3. 设置扫描根目录和排除模式。
4. 执行首次扫描。
5. 检查冻结 commit、文件数、字节数和结果状态。

一个项目可连接多个服务上的多个仓库。每次扫描先解析并固定提交，再读取允许的文本文件，整批校验成功后原子发布。失败不会污染上一代活动快照。

GitHub 的 Issue、PR、Release 和仓库 Markdown 扩展同步仍通过既有 GitHub 专用入口使用；通用 Git 连接器只读取代码与文本快照。

## 9. 配置项目 AI 路由

进入“智能控制台”，分别配置：

- 图片与扫描件识别
- 自动抽取
- 语义向量
- 引用式生成

切换生成或视觉模型只影响后续任务，历史来源保留原供应商和模型。切换向量供应商、模型或维度会让活动索引失配，语义搜索、RAG 和智能体会暂停，直到重建索引。

## 10. 建立和使用智能记忆

### 10.1 自动抽取

在“智能记忆”选择资料，核对输入清单并确认外发。所有待生成片段会发送给供应商；只有完成当次明确确认后才会发起请求。模型输出必须满足严格结构，且引用摘录必须真实存在于原文；验证失败会整次拒绝。

### 10.2 人工审核

逐条检查标题、内容、类型和引用。接受后成为已确认事实；驳回后保留审核记录，但不进入可信事实视图。

### 10.3 统一语义索引

索引覆盖当前活动的人工资料、文件片段、网页修订、仓库文本和代码快照。可以增量复用兼容向量，也可以全量重建。只有全部向量成功持久化后才切换活动索引。

以下变化需要重建索引：

- 新增或更新资料、网页或文件
- 重新扫描仓库
- 接受或撤销影响语义内容的来源
- 更换向量供应商、模型或维度

### 10.4 搜索、RAG 与智能体

语义搜索返回原文片段、路径、冻结 commit 和分数。RAG 只允许引用本次检索集合中的证据 UUID。

只读智能体可以读取确定性项目状态、当前有效事实、语义记忆和仓库状态。它不能覆盖项目状态，也不能执行 Shell、任意文件读取、代码修改、Git 写入或部署。

## 11. 记忆质量与生命周期

进入“记忆质量”并执行检查。检查为本地确定性规则，不调用模型，识别：

- 可能重复
- 内容冲突
- 长期未复核或已过有效期
- 缺少证据
- 低置信度

每条事实可以维护置信度、重要性、有效截止、长期置顶和“本次已复核”时间。处理问题后选择“已处理”或“不适用”，并填写的处置记录会保留。

## 12. 时态项目世界模型

进入项目“项目状态”。Viewer 可以读取当前状态、事实、关系、快照和审计；Editor 或 Owner 可以建立关系、退役关系、建立替代链和固化状态。

### 12.1 当前状态如何计算

系统只把同时满足以下条件的事实纳入当前状态：已经人工确认、来源未退役、已到生效时间且尚未过有效截止、未被其他事实替代。状态规则为：

- 没有当前事实：`资料不足`。
- 有当前问题、当前事实冲突，或计划健康为高风险：`存在风险`。
- 有当前风险、陈旧关系，或计划有待处理事项：`需要关注`。
- 其他情况：`运行正常`。

状态同时保存输入清单指纹和状态指纹。Dashboard、项目简报与只读智能体读取同一份确定性状态；模型输出不能把系统状态改成另一个结论。

### 12.2 建立和退役事实关系

关系支持“支持、冲突、依赖、阻断、由此导致、解决、相关”七种类型。创建关系时必须选择同项目的两条当前已确认事实并填写依据。系统固定双方当时的精确修订和证据清单；任何一端后来修订、过期、来源退役或被替代时，关系显示为“版本已变化”，不再进入当前状态。

关系不能直接修改或删除。需要调整时先填写理由并退役旧关系，再按当前事实建立新关系。退役记录和原始关系仍保留。

### 12.3 建立事实替代链

当新事实明确取代旧事实时，选择两条同类型当前事实并填写替代理由。系统会：

1. 把旧事实标记为“已被替代”，但保留确认时间、来源、证据和全部修订。
2. 在新事实上记录被替代事实，并为双方各追加一条修订。
3. 拒绝重复后继、跨类型替代、过期页面提交、分叉和循环链。
4. 让仍绑定旧版本的关系显示为陈旧，等待人工退役或重建。

替代是时态治理，不是删除，也不是自动合并内容。旧事实不能恢复为当前版本；如业务再次变化，应创建新的已确认事实并继续向前建立替代链。

### 12.4 固化状态快照与核对审计

“固化当前状态”保存当前有效事实的修订/证据指纹、活动关系、质量摘要和计划健康度。输入没有变化时重复点击只返回已有快照，不制造重复历史。快照与世界模型审计只追加、不覆盖，记录操作者和发生时间。

原“资料与条目”中的 Project Snapshot 继续作为已确认条目的兼容读取点；V5 的“项目状态”快照是包含生命周期、关系、冲突和计划健康度的综合状态，两者用途不同。

## 13. 自动化与通知

进入“自动化”创建规则：

| 类型 | 到期行为 |
| --- | --- |
| 仓库同步 | Worker 读取活动仓库并原子发布新快照 |
| 网页刷新 | Worker 刷新活动网页来源 |
| 记忆质量 | Worker 运行本地确定性检查 |
| 项目计划健康 | Worker 按期限、受阻、依赖、负责人、验收、证据、建议、仓库变化与待审批动作运行本地确定性检查并通知当前有权限的接收者 |
| 记忆索引 | 创建需要页面确认的模型外发通知 |
| 项目简报 | 创建需要页面确认的模型外发通知 |

规则支持每小时、每 6 小时、每 12 小时、每天或每周，也可立即运行。运行状态、租约、失败码和连续失败次数会持久化；连续失败三次后规则自动暂停。

归档项目时，活动自动化规则会暂停。恢复项目后不会自动启用，必须人工检查后再开启。

“项目计划健康”可配置 1、3、7 或 14 天的即将到期窗口，并决定是否同时提醒相关负责人。它只读取本地数据库，不调用模型，也不向外发送项目内容。发送前会重新核对规则创建者和负责人的当前项目访问权；失去权限或被停用的账户不会继续接收项目摘要。

通知中心显示成功、失败、记忆质量、项目计划健康和外发待确认消息。通知只说明可观察结果；涉及模型的消息需要进入对应项目页面继续操作。

## 14. 动作策略、审批与审计

进入项目“动作与审批”。每项能力都有独立策略：

| 策略 | 行为 |
| --- | --- |
| 自动执行 | Editor 或 Owner 创建后直接进入 Worker 队列 |
| 每次审批 | 创建后等待项目 Owner 核对，批准后才进入队列 |
| 禁止执行 | 不允许创建新的该类动作 |

当前能力与安全默认值：

| 能力 | 访问范围 | 默认策略 |
| --- | --- | --- |
| 同步代码仓库 | 只读外部访问 | 每次审批 |
| 刷新网页来源 | 只读外部访问 | 每次审批 |
| 检查记忆质量 | 仅本地数据库 | 自动执行 |
| 调用 MCP 只读工具 | 受控远程只读访问 | 每次审批（不可自动执行） |

动作创建时会固定项目、能力、规范化输入、SHA-256 输入指纹、风险级别和当时的策略快照。MCP 动作还固定项目授权、工具定义、网络和凭据指纹。后续修改项目策略不会改变已经创建的动作。

等待审批的动作有效期为 24 小时。项目 Owner 批准或拒绝时必须同时核对当前动作版本和输入指纹；过期动作必须重新创建。申请人可以取消自己尚未执行的动作，Owner 可以取消项目内尚未执行的动作。

Worker 使用持久化租约和心跳领取动作。运行中租约过期时，动作会失败关闭并记录 `ACTION_LEASE_EXPIRED`，系统不会自动重复外部读取。MCP 调用发生定义或安全快照漂移时同样失败关闭。动作的申请、排队、审批、领取和终态都进入不可变审计；审批记录、策略修订、MCP 工具定义快照和授权审计同样不可修改。

项目归档会取消等待审批或排队中的动作。运行中的动作会阻止归档，归档项目不能创建、审批或领取新动作。

## 15. 证据驱动项目运营

进入项目“项目计划”。Viewer 可以查看；Editor 或 Owner 可以维护计划。

### 15.1 手工建立目标和工作项

- 手工目标从“草稿”开始，可依次进入“进行中”“已完成”或“已取消”。
- 手工工作项从“已计划”开始，可进入“进行中”“已阻塞”“已完成”或“已取消”。
- 每个工作项可以设置优先级、说明、所属目标、期限、负责人和独立验收标准。负责人只能选择当前项目 Owner/Editor 或工作区 Owner/Admin。
- 工作项进入“进行中”前必须已有负责人和非空验收标准；进入“已完成”前还必须至少关联一条活动证据。
- “已完成”和“已取消”是数据库保护的终态，不能再改写标题、负责人、验收标准、状态或证据关联。
- 状态与证据变更使用当前更新时间进行并发保护，过期页面不会覆盖他人的更新。

### 15.2 纳入智能体建议

项目智能体运行完成且建议包含有效引用时，计划页会显示可纳入建议。Editor 或 Owner 点击“纳入计划”后：

1. 系统固定智能体运行、建议序号、建议正文、引用快照和运行输入清单指纹。
2. 系统计算证据 SHA-256，并创建一条 `agent_recommendation` 来源的 `proposed` 工作项。
3. 同一建议重复提交只返回已有工作项，不会创建重复记录。
4. 用户核对建议证据后，必须手工“接受为已计划”，再补齐负责人、验收标准和完成证据，才可继续推进状态。

建议证据和来源字段由数据库保护，不能事后改写。计划页不会自动运行新的智能体、调用模型或创建 Action Engine 动作。

### 15.3 关联完成证据

工作项可以关联两类人工可核对证据：

- 已确认项目事实：固定事实内容、来源、更新时间和来源内容哈希。
- 当前活动项目来源：固定来源类型、地址、内容哈希、纳入时间和受限摘录。

仓库变化信号关联到工作项后会形成第三类 `repository_sync` 证据。所有证据都保存规范化快照和 SHA-256 指纹；后续事实修订、来源退役或同步失效会显示“需复核”。移除证据采用软移除，原始记录和审计仍保留。

### 15.4 核对仓库变化信号

点击“检查最新同步”后，系统只读取已经成功、完成对账且包含新增/更新/删除记录的仓库同步。每条信号固定同步清单指纹、变更计数和最多 500 条有序样本，并明确不推断它必然影响任何工作项。

Editor 或 Owner 必须人工选择相关工作项并“关联并确认”，或在核对后“忽略”。两种决策都只能执行一次并进入追加式审计；不会自动生成工作项、修改代码或触发动作。

### 15.5 维护依赖、健康和审计

工作项可以依赖同项目的其他工作项。系统拒绝自依赖、重复活动依赖和循环依赖；只有前置项“已完成”才视为依赖满足，前置项取消仍需要人工重新评估。移除依赖采用软移除，历史仍保留。

计划页健康状态与 Dashboard 运营提醒由本地规则确定性计算：逾期或受阻为“需要立即处理”；即将到期、依赖未完成、负责人/验收/证据缺失、证据过期、待采纳建议、仓库变化或动作待审批为“存在待处理事项”。目标、工作项、状态、依赖、证据和变化决策都会写入追加式计划审计。

## 16. 治理、归档与导出

“治理与审核”用于：

- 审核 AI 候选
- 区分明确失败与未知外部结果
- 在具备不可变证据时人工收口未知任务
- 查看模型路由历史
- 核对 7/30/90 天调用与 Token 用量

人工收口不会再次调用外部服务，也不会把未知状态伪装成成功。

归档前，系统要求没有排队中、等待确认、运行中或需人工收口的后台任务，也没有运行中的自动化或动作。归档是软归档，不删除数据；尚未执行的动作会被取消并保留审计。

受限 JSON 导出包含项目正文、文件元数据和审核文本，但不包含上传二进制、系统存储路径、凭据、向量和完整运行载荷。它不是灾难恢复备份。

## 17. 备份与恢复

### 17.1 数据库

```bash
docker compose exec -T postgres pg_dump -U ai_project_os -d ai_project_os -Fc > ai-project-os.dump
pg_restore -l ai-project-os.dump
```

如果 `.env` 使用了不同的数据库用户或库名，请替换命令参数。

### 17.2 主密钥与上传文件

还必须备份：

- `ai-project-os-secrets` 卷：丢失后已保存模型、Git、MCP 与 OIDC 凭据无法解密。
- `ai-project-os-uploads` 卷：包含上传文件原件。

数据库、主密钥和上传文件必须来自一致的备份窗口，并一起恢复。不要单独重建主密钥后继续使用旧数据库。

生产单节点可使用[生产异地备份](production-backup.md)中的 root-only 脚本和 systemd timer，在同一停写窗口生成三类数据、以 age 公钥加密并上传 COS。只有远端长度和 CRC64 验证通过的本地目录才参与保留期清理；项目 JSON 导出、健康接口或仅看到 COS 对象都不能替代独立恢复演练。

## 18. 常见问题

### 18.1 模型连接无法选择

回到“模型设置”执行连接测试，确认状态为“已验证”，并检查该供应商是否配置了目标能力所需模型。

### 18.2 Git 仓库无法读取

检查连接状态、仓库路径、分支、凭据权限、CA 或 known_hosts。若提示网络地址变化，确认 DNS/基础设施变更后，在页面重新验证连接。

### 18.3 网页抓取失败

确认网页无需浏览器登录或 JavaScript 渲染。内网页面需显式允许私网；DNS 地址变化必须重新确认。云元数据地址不可放行。

### 18.4 OIDC 登录失败

检查回调地址、Issuer、Client ID、Secret、Token 认证方式和 scopes。如果日志/页面提示账号不允许，可能是自动建号关闭、邮箱域名不匹配，或该邮箱已经属于尚未显式绑定的本地账户。

### 18.5 自动化没有运行

确认 `worker` 容器为 `healthy`，并在 `/api/health` 中看到 `worker.status: up`；随后检查规则为“运行中”、项目未归档且下次运行时间已到。`worker.status: stale` 表示心跳超过 45 秒，`degraded` 表示最近一次数据库领取循环发生基础设施异常。连续失败三次的规则会自动暂停。

使用 `docker compose logs worker` 查看单行 JSON 事件。建议对容器非健康、`worker.status` 非 `up`、`worker.*_failed` 事件和连续重启分别告警；字段语义、采集边界和建议阈值见[运行监控基线](monitoring.md)。

### 18.6 动作一直等待或执行失败

等待审批时由项目 Owner 在“动作与审批”核对并决策；超过 24 小时需要重新创建。排队后仍未执行时检查 `worker` 容器。失败动作不会自动重试，请先查看安全错误码和审计，再决定是否创建新动作。

### 18.6.1 MCP 工具无法授权或调用

先确认管理员已经成功执行工具发现，连接状态为“已验证”，工具同时声明只读和非破坏性，并且当前工具卡片显示“管理员已认证”。远端 annotations 只是提示，伪造或修改它们不能代替认证。若工具定义、DNS、凭据、认证或授权变化，旧授权或已创建动作会失败关闭；管理员应重新发现并认证，项目 Owner 再重新确认授权，最后创建新的调用动作。第三方服务返回 `input_required` 时当前版本会拒绝，不会在 Worker 中继续交互。

### 18.7 索引要求重建

当前资料清单或向量路由与活动索引不一致。使用当前向量供应商、模型和维度重新建立索引。

### 18.8 项目无法归档

先处理后台任务、自动化和运行中动作。`waitingConsent`、`running`、`unknown` 或需人工收口状态都会阻止归档；等待审批和排队中的动作会在归档事务中取消。

### 18.9 页面显示的用量与账单不同

系统记录受审计的调用尝试和 Token，不维护供应商价格、折扣或缓存计费规则。最终金额以供应商账单为准。
