# v0.8.0-dev.4 — 邮箱认证开发候选

新增邮箱验证码注册、个人资料中已保存邮箱的验证，以及已验证邮箱账号的设置/修改密码邮件验证。发送前需要图形验证码；邮件验证码绑定用途、浏览器、账号与邮箱版本，具有过期、尝试次数、频率和单次使用限制。修改密码仍要求当前密码，成功后撤销旧会话。启用邮件功能时，已验证邮箱可以作为密码登录别名。

已验证邮箱的个人资料修改与移除在本轮锁定，邮箱换绑、邮箱找回、账号合并和人工绕过不在范围内。既有可信 OAuth 邮箱同步与账号注销保留原有服务端路径。关闭邮件功能时，登录页面与认证接口保持用户名/手机号行为。

修复短信代理返回 HTML 429 时的提示与冷却，以及 Office 图片识别成功后被空白旧草稿遮盖的问题。依赖采用 Next.js 16.3.8 与兼容的传递依赖安全修复；仍保留限定的 deepmerge-ts 风险，见[依赖安全例外](../security-dependency-exceptions.md)。

新增一条邮件迁移，142→143；迁移前检查规范化邮箱重复，不自动合并或改写旧账号。候选发布使用固定的 `dev.3 → dev.4` 入口，要求精确主分支和带注释标签的完整 CI，先构建后停写，迁移后协调数据库权限。数据库迁移一旦尝试后失败，保持 writer 停止并要求明确恢复，不自动启动旧代码。备份、恢复演练与旧数据验收继续按用户决定豁免，不作为通过证据。

状态：开发候选源码。局部数据库与隔离检查、独立审查、完整候选 CI、生产配置注入、真实收信和浏览器验收分别记录；本文不代表已上线或正式 1.0 已完成。生产实际版本以 `/api/health` 和部署回执为准。
