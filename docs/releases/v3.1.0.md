# AI Project OS V3.1.0 发布说明

发布日期：2026-08-29

V3.1.0 在既有项目记忆、RAG、只读智能体和持久化自动化之上增加受控 Action Engine。用户可以在项目页面决定某项内置动作是自动执行、逐次审批还是禁止执行，并从申请、审批、领取到终态查看完整审计。该能力没有扩大智能体权限，也不允许模型自行创建或批准动作。

## 发布能力

- 项目“动作与审批”页面展示能力注册表、项目策略、动作账本、审批信息、安全错误码和不可变审计轨迹。
- 当前开放“同步代码仓库”“刷新网页来源”“检查记忆质量”三项内置能力。
- 仓库同步和网页刷新属于外部只读访问，默认每次由项目 Owner 审批；记忆质量检查仅访问本地数据库，默认自动排队。
- Editor 或 Owner 可以创建动作；只有 Owner 可以修改策略、批准或拒绝。申请人和 Owner 可以取消尚未执行的动作。
- 动作固定项目、能力、规范化输入、SHA-256 输入指纹、风险级别和策略快照。策略后续变化不会改写已有动作。
- 审批窗口为 24 小时；Worker 使用持久化租约和心跳。租约过期时失败关闭，不自动重复外部读取。
- 通知中心展示待审批、完成、失败和过期结果。

完整使用方式见[操作手册](../operation-manual.md)和页面“使用指南”。

## 能力边界

- Action Engine 不是通用 Agent 工具平台。本版动作只接受空参数，并且只能调用三项服务端白名单能力。
- 模型不会生成、创建或批准动作；只读项目智能体不能进入动作执行链路。
- 本版不提供 MCP、Shell、任意文件系统、代码修改、Git 写入、分支/PR、合并、部署或任何外部写操作。
- 仓库同步和网页刷新会读取用户已经在页面启用的来源；不会扩展连接范围或写入第三方服务。
- 失败动作不会自动重试。管理员应先检查安全错误码和审计，再人工决定是否创建新动作。

## 升级前准备

升级前必须同时保存以下三类数据，并保证它们来自同一备份窗口：

1. PostgreSQL 数据库备份。
2. `ai-project-os-secrets` 卷，其中包含解密模型、Git 与 OIDC 凭据所需的主密钥。
3. `ai-project-os-uploads` 卷，其中包含上传文件原件。

不要执行 `docker compose down -v`。项目 JSON 导出不能代替数据库和持久化卷备份。

## Docker Compose 升级

```bash
git switch main
git pull --ff-only
docker compose config --quiet
docker compose up -d --build
docker compose ps --all
curl --fail http://127.0.0.1:3000/api/health
```

期望状态：

- `postgres` 为 `healthy`。
- `migrate` 为 `Exited (0)`。
- `app` 为 `healthy`，健康接口返回 `version: 3.1.0`。
- `worker` 为 `running`。

迁移任务使用 `prisma migrate deploy` 应用第 43 个迁移 `20260829220000_add_project_action_engine`，创建五张动作表、数据库约束和不可变记录触发器。

## 回滚原则

- 先停止 `app` 与 `worker`，避免旧代码继续写入 V3.1 数据结构。
- 同时恢复升级前代码、数据库、凭据主密钥卷和上传卷；不要把 V3.0 代码直接连接到已升级数据库。
- 恢复后先执行数据库只读核对和 `docker compose ps --all`，再开放页面。
- 若没有匹配时间点的主密钥或上传卷，凭据和文件原件可能无法恢复，不能把这种状态视为成功回滚。

## 外部服务验证边界

本次没有在现有正式项目中创建演示动作，也没有为了验收而触发真实 Git 或网页读取，避免污染动作账本、消耗第三方资源或改变项目快照。执行语义在隔离 PostgreSQL 中使用本地记忆质量动作完成闭环；真实 Git 和网页动作应由管理员在自己的连接与网络边界内，以最小范围从页面试运行。

OpenAI、DeepSeek、Qwen、GLM、外部 Git 服务和企业 OIDC 的第三方现场连接边界与 V3.0.0 相同，本次没有新增或声称完成真实凭据验收。

## 已知限制

- 页面尚不支持创建和切换多个工作区。
- OIDC 不会按邮箱自动绑定已有本地账户。
- Action Engine 只有三项内置、无参数动作，不支持模型生成动作或任意工具调用。
- Issue、PR 和 Release 等扩展资料仍是 GitHub 专用能力。
- 网页来源不执行 JavaScript，也不支持登录态或自定义请求头。
- 涉及模型内容外发的自动化仍只创建待确认通知，不绕过用户当次授权。
