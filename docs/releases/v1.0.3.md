# v1.0.3 — 文件导入与服务器资源体验优化

本文件描述待验证候选。生产版本以 `/api/health` 和正式发布回执为准。`v1.0.2` 标签保留其原提交，本版本使用新的前进版本号。

## 本版本变更

- 项目概览的资料来源、文件、已确认事实和待处理统计卡可直接进入对应页面或明细；已确认事实使用明确的审核状态筛选。待处理明细包含审核、失败和待核对任务、仓库风险以及实际记忆索引就绪状态。
- 文件上传、提取和原文查看统一处理 UTF-8、带 BOM 的 UTF-16 和受限文本类型的 GB18030。下载保留原始字节并声明对应字符集；不能确认的内容作为附件下载。JSON 维持 UTF-8 要求。已经在上传前写坏的文字无法由编码识别恢复。
- 初始超级管理员的备份运维页面增加只读资源监控：Linux 内核报告的内存、应用和上传目录所属磁盘、inode、容器内存与应用进程内存分别展示，包含更新时间和容量告警。数据来源和范围见[服务器资源监控](../server-resource-monitoring.md)。
- 个人知识图片或扫描 PDF 导入可选择当前经验证启用的平台视觉模型，默认优先使用平台配置，并保留个人模型选项。发送前展示模型、页清单、额度倍率及每页输出上限；平台额度属于用户账号，按页结算。识别结果先作为人工核对预览，确认保存后才进入知识库。
- 平台视觉输出遵守管理员上限和个人导入每页 2,048 token 上限中的较小值；模型、计费倍率或输出上限变化后需要重新确认。并发使用同一确认返回明确的冲突提示；资料列表切换筛选时忽略旧请求结果。
- 发布工具对备份目录单独校验目录类型和 `0700` 权限，修复合法目录被普通文件校验器拒绝的问题；备份工件仍要求普通文件和 `0600` 权限。已知校验错误保留安全错误码，避免统一报错掩盖原因。

本候选同时包含尚未上线的 v1.0.2 账号、个人赠额及个人语义检索修复。实际发布应按线上来源到本提交的累计差异选择高风险验证，不把本次最后一笔界面改动当作整个版本的风险。

## 发布要求

先完成精确同 SHA 主分支 CI 与一次独立审查，再由用户在 **发布正式版本** 手动发起。不得移动已存在的版本标签。生产切换仍需来源核对、停写备份、隔离恢复迁移验证、目标账本、发布回执与应用/数据库/Worker 健康证据。

当前 v1.0.2 生产发布在迁移前失败，源版本已恢复。只读诊断与固定辅助函数复现确认：备份目录被误按普通文件校验，导致发布失败；主机配置备份本身校验通过。本候选修正了该逻辑，正式发布前需在精确同 SHA CI 成功后更新服务器发布工具。

服务器只读诊断显示 Docker 构建缓存约 49.89 GB，其中约 44.26 GB 标记为可回收；该次备份的上传压缩包约 82 KB、数据库转储约 4 MB。目录汇总因超时没有结果；Docker 镜像和构建缓存存在共享数据，不能将各项简单相加。尚未执行生产缓存清理，不据此宣称已释放空间。
