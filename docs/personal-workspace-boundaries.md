# 我的空间、项目与记忆边界

我的空间是当前用户可访问项目的统一入口，也管理当前用户独有的知识和连接。它是展示与管理容器，不是将所有项目资料合并成一个知识池。

| 维度 | 约定 |
| --- | --- |
| 展示层级 | 我的空间包含“我的项目”，可汇总当前用户有权查看的项目进度、任务和风险。 |
| 数据归属 | 个人知识与个人默认记忆归个人；项目资料、事实、状态和记忆归各自项目。每条搜索结果、引用和图谱关系都保留来源归属。 |
| 访问权限 | 先校验当前用户权限；外部 MCP 请求还要与有效授权范围取交集；最后按本次请求明确的项目作用域收窄。展示层级不授予读取权。 |
| 检索作用域 | 具体项目请求只检索当前项目获准内容。跨项目汇总或检索必须由用户明确发起，逐项目校验权限并分别展示来源；不得自动把项目 A 的规则带入项目 B。 |
| 记忆优先级 | 仅在已获准使用且适用于当前项目的默认约定之间解决冲突：当前项目的有效约定优先，个人通用约定补充。该优先关系只在当前项目内生效，不改变资料归属和权限。 |

## 回答与证据

先确定请求的项目作用域，再取得该作用域中有权限的资料与记忆。项目约定优先用于偏好、规范等约定冲突；不能仅因“项目优先”就把旧事实、候选记忆或未经核对的内容当成最新事实。事实结论必须保留来源、时间、版本与审核状态，并以可核对的证据为准。检索不到时说明未找到，不从其他项目静默补答案。

## 当前实现边界

- “我的项目”位于我的空间导航下；个人知识文档和项目资料分开保存。
- 我的空间的项目搜索默认选中一个可访问项目；用户可明确选择多个项目或“全部可访问项目”，结果保留项目来源。项目内语义检索、RAG 和只读智能体仍走项目作用域，不读取其他项目资料。
- 个人知识文档可由所有者显式标记为“个人通用记忆”（最多 8 条，每条不超过 2,000 字符）；既有文档默认不参与。项目问答、简报和只读分析在本次发起者具有项目编辑权限时自动装配其个人通用记忆，准备确认时显示条数并绑定版本指纹，发送给模型前再次核对。普通个人资料不参与。
- 个人通用记忆只作为偏好与约定，不作为项目事实或可引用的项目证据。项目资料与个人默认约定分开传给模型；当前项目约定优先。原始个人文档仍归所有者管理，生成结果可由项目成员共享，且可能复述个人默认记忆中的内容。
- 取消个人通用记忆标记会阻止后续请求使用该文档，不会自动删除此前已经生成并保存在项目中的共享回答或报告。
- MCP 能否读取个人或项目内容由具体工具的授权与服务端项目作用域共同决定，不能仅因为工具连接属于个人就继承所有项目权限。

模型对自然语言约定的冲突识别仍需以实际场景验收；项目事实不得因为个人默认值而改写。外部 MCP 工具没有自动继承这组默认记忆，须继续按工具授权与项目作用域单独接入和验证。
