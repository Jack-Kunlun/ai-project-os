# AI Project OS V3.2.0 发布说明

发布日期：2026-08-30

V3.2.0 在 V3.1 Action Engine 上增加受控 MCP Capability Model。管理员可以完全从页面接入远程 Streamable HTTP 服务并固化工具定义，项目 Owner 再逐项授权；Editor 或 Owner 创建调用动作后，必须由 Owner 核对完整参数和安全指纹并逐次批准。该能力不会扩大项目智能体权限，也不会把远端结果自动写入记忆或模型上下文。

## 发布能力

- 顶部“连接器”增加 Git 与 MCP 同级分类；管理员可配置远程端点、无认证或 Bearer Token、显式内网访问并执行工具发现。
- MCP Bearer Token 使用现有 AES-256-GCM 凭据库加密保存，不写入环境变量，也不通过 API 回显。
- 当前使用 `2026-07-28` Streamable HTTP 协议；支持 JSON 与请求范围 SSE 响应、工具目录分页和受限工具调用结果。
- 工具定义按名称、输入/输出 Schema、annotations 和 SHA-256 指纹保存为追加式快照。定义更新会让旧项目授权过期，不会静默替换授权依据。
- 只有同时声明 `readOnlyHint=true` 与 `destructiveHint=false` 的定义可以授权。项目 Owner 必须逐项确认；Editor 或 Owner 可以填写符合固化 Schema 的 JSON 参数并创建动作。
- MCP 动作始终为高风险、逐次审批；数据库和服务层都不允许把该能力设为自动执行。
- 动作固定项目、授权、连接、工具名、定义指纹、规范化参数、DNS 指纹和凭据指纹。Worker 执行前重新核对全部状态，任何漂移都失败关闭。
- 成功结果只在动作账本中保存最多受限文本、结构化内容、遗漏内容数量和结果指纹。

完整使用方式见[操作手册](../operation-manual.md)和页面“使用指南”。

## 能力边界

- MCP annotations 来自第三方服务，属于未受信提示，不能证明工具真实只读。管理员必须只接入可信服务，并为 AI Project OS 配置最小权限只读凭据。
- 当前只支持远程 Streamable HTTP；不支持 stdio、本地进程、旧式 HTTP+SSE、执行中继续索取输入或任意 MCP 资源展开。
- 当前不支持 MCP 写操作，也不提供 Shell、任意文件系统、代码修改、Git 写入、分支/PR、合并或部署能力。
- 模型和项目智能体不能发现、授权、创建、批准或调用 MCP 工具；调用动作只能由具备项目权限的用户在页面发起。
- MCP 结果不会自动进入项目事实、候选、RAG 索引或模型上下文。用户需要使用结果时必须另行核对并通过已有受控资料流程导入。
- 连接停用、工具定义变化、DNS 变化、凭据轮换或项目授权撤销后，已经批准但尚未执行的动作也会失败关闭，不会自动重试。

## 升级前准备

升级前必须同时保存以下三类数据，并保证来自同一备份窗口：

1. PostgreSQL 数据库备份。
2. `ai-project-os-secrets` 卷，其中包含解密模型、Git、MCP 与 OIDC 凭据所需的主密钥。
3. `ai-project-os-uploads` 卷，其中包含上传文件原件。

不要执行 `docker compose down -v`。项目 JSON 导出不能代替数据库和持久化卷备份。

## Docker Compose 升级

```bash
git switch main
git pull --ff-only
docker compose config --quiet
docker compose up -d --build
docker compose ps --all
curl --fail http://127.0.0.1:3000/api/health
```

期望状态：

- `postgres` 为 `healthy`。
- `migrate` 为 `Exited (0)`。
- `app` 为 `healthy`，健康接口返回 `version: 3.2.0`。
- `worker` 为 `running`。

迁移任务使用 `prisma migrate deploy` 应用第 44 个迁移 `20260829230000_add_controlled_mcp_capabilities`，创建 MCP 连接、工具定义、项目工具授权和授权审计表，并扩展 Action Engine 数据库约束。

## 回滚原则

- 先停止 `app` 与 `worker`，避免旧代码继续写入 V3.2 数据结构。
- 同时恢复升级前代码、数据库、凭据主密钥卷和上传卷；不要把 V3.1 代码直接连接到已升级数据库。
- 恢复后先执行数据库只读核对和 `docker compose ps --all`，再开放页面。
- 若没有匹配时间点的主密钥或上传卷，凭据和文件原件可能无法恢复，不能把这种状态视为成功回滚。

## 外部服务验证边界

本次没有在正式项目中创建演示 MCP 连接、项目授权或调用动作，避免保存虚假配置、污染审计账本或向未知第三方发送数据。协议、鉴权请求头、JSON/SSE 响应、Schema 校验和 Worker 调用在隔离本地 MCP 服务与真实 PostgreSQL 中完成闭环。

当前没有使用用户自己的第三方 MCP 凭据进行现场连接，因此不能把任意外部 MCP 服务宣称为已验证。OpenAI、DeepSeek、Qwen、GLM、外部 Git 服务和企业 OIDC 的第三方现场连接边界与 V3.1.0 相同，本次也没有新增真实凭据验收。

## 已知限制

- 页面尚不支持创建和切换多个工作区。
- OIDC 不会按邮箱自动绑定已有本地账户。
- MCP 只支持远程 Streamable HTTP 只读工具；不支持 stdio、本地进程、旧式 HTTP+SSE、交互式续参、资源展开、写操作或自动执行。
- MCP 结果只保存在动作记录中，不会自动进入项目记忆、RAG 或模型上下文。
- Issue、PR 和 Release 等扩展资料仍是 GitHub 专用能力。
- 网页来源不执行 JavaScript，也不支持登录态或自定义请求头。
- 涉及模型内容外发的自动化仍只创建待确认通知，不绕过用户当次授权。
