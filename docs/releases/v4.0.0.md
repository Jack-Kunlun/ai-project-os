# AI Project OS V4.0.0 内部研发里程碑记录（非正式发布）

记录日期：2026-08-30

状态：内部研发里程碑（非正式发布）

V4.0.0 在 V3.2 受控 MCP 能力上补齐“结果进入项目证据”和“证据进入项目计划”两段人工治理链。成功的 MCP 只读结果可以由项目成员人工固化为未审核资料；只读智能体建议可以由项目成员固化为带引用快照的待采纳工作项。两种入口都不会自动确认事实、建立索引、执行动作、修改代码或推进计划状态。

## 发布能力

- “动作与审批”增加“MCP 结果纳入项目资料”。只有成功完成的 `project.mcp.read-tool.invoke` 动作可以纳入；Editor 或 Owner 必须在页面明确操作。
- 导入服务重新核对动作输入指纹和结果指纹，并固定动作、输入、结果、内容和来源身份。相同动作重复提交返回已有导入，不创建重复资料。
- 纳入结果创建 `mcp` 类型的未审核 `ProjectSource`。它不会自动成为事实、触发模型调用或进入活动索引；用户仍需按资料审核和索引流程处理。
- 项目导航增加独立“项目计划”页面，支持目标、工作项、优先级、状态、目标归属、依赖和最近审计。
- 手工目标从草稿开始，手工工作项从已计划开始；Viewer 只读，Editor 或 Owner 可以创建和推进。
- 只读智能体建议可纳入为 `agent_recommendation` 来源的 `proposed` 工作项。系统固定运行、建议序号、建议正文、完整引用快照、输入清单指纹和证据 SHA-256。
- 同一条智能体建议只能纳入一次；用户必须再次明确接受，工作项才从待采纳进入已计划。
- 工作项依赖拒绝自依赖、重复活动依赖和直接或传递循环。移除依赖采用软移除，历史仍保留。
- 项目受限 JSON 导出升级到 Schema V3，包含 MCP 结果导入、目标、工作项、依赖和计划审计的安全字段。

完整使用方式见[操作手册](../operation-manual.md)和页面“使用指南”。

## 人工治理与安全边界

- MCP 结果纳入记录为不可变追加记录。数据库阻止更新或删除，且只接受成功动作和固定的 `mcp` 来源身份。
- 项目计划状态机由服务端与数据库共同约束。过期页面不能覆盖较新的目标或工作项状态。
- 智能体建议的来源、运行、建议序号、引用快照、输入清单指纹和证据指纹不可事后改写。
- 计划审计不可修改或删除；依赖记录只允许一次软移除，不能删除或重新指向其他工作项。
- 项目归档后计划保持只读；项目权限仍在服务端执行，页面隐藏不是授权依据。
- 智能体仍然只有固定项目内只读工具。项目计划不会自动创建 Action Engine 动作，也不会调用 MCP、模型、Shell、代码写入、Git 写入、分支/PR、合并或部署。

## 升级前准备

升级前必须同时保存以下三类数据，并保证来自同一备份窗口：

1. PostgreSQL 数据库备份。
2. `ai-project-os-secrets` 卷，其中包含解密模型、Git、MCP 与 OIDC 凭据所需的主密钥。
3. `ai-project-os-uploads` 卷，其中包含上传文件原件。

不要执行 `docker compose down -v`。项目 JSON 导出不能代替数据库和持久化卷备份。

## Docker Compose 升级

```bash
git switch main
git pull --ff-only
docker compose config --quiet
docker compose up -d --build
docker compose ps --all
curl --fail http://127.0.0.1:3000/api/health
```

期望状态：

- `postgres` 为 `healthy`。
- `migrate` 为 `Exited (0)`。
- `app` 为 `healthy`，健康接口返回 `version: 4.0.0`。
- `worker` 为 `running`。

迁移任务使用 `prisma migrate deploy` 应用迁移 `20260830010000_add_action_result_intake` 与 `20260830020000_add_evidence_driven_project_plan`。升级后总迁移数为 46，并增加 5 张 V4 表与 5 个数据库保护触发器。

## 回滚原则

- 先停止 `app` 与 `worker`，避免旧代码继续写入 V4 数据结构。
- 同时恢复升级前代码、数据库、凭据主密钥卷和上传卷；不要把 V3.2 代码直接连接到已升级数据库。
- 恢复后先执行数据库只读核对和 `docker compose ps --all`，再开放页面。
- 若没有匹配时间点的主密钥或上传卷，凭据和文件原件可能无法恢复，不能把这种状态视为成功回滚。

## 外部服务验证边界

本次没有在正式项目中创建演示模型、Git、OIDC 或 MCP 配置，也没有向未知第三方发送项目数据。MCP 协议、Bearer 请求头、JSON/SSE、Schema、逐次审批、Worker 执行和结果纳入在隔离本地服务与真实 PostgreSQL 中完成闭环；智能体建议纳入使用隔离模型响应和真实 PostgreSQL 验证。

当前没有使用用户自己的 OpenAI、DeepSeek、Qwen、GLM、外部 Git、企业 OIDC 或第三方 MCP 凭据进行现场连接，因此不能把这些外部服务宣称为已验证。

## 已知限制

- 页面尚不支持创建和切换多个工作区。
- OIDC 不会按邮箱自动绑定已有本地账户。
- MCP 只支持远程 Streamable HTTP 只读工具；不支持 stdio、本地进程、旧式 HTTP+SSE、交互式续参、资源展开、写操作或自动执行。
- MCP 成功结果只能人工纳入为未审核资料；不会自动成为事实、重建索引或进入模型上下文。
- 项目计划不会自动执行工作项，也不提供代码、Git、Shell、部署或任意工具写权限。
- Issue、PR 和 Release 等扩展资料仍是 GitHub 专用能力。
- 网页来源不执行 JavaScript，也不支持登录态或自定义请求头。
- 涉及模型内容外发的自动化仍只创建待确认通知，不绕过用户当次授权。
