# v0.4.0-dev.1

状态：`CONTROLLED_PRERELEASE`

v0.4.0-dev.1 是管理台可用性基线预发布，仍不是稳定版或 GitHub Latest。

## 生产发布边界

本版本只支持一次性的 `clean-deploy v0.4.0-dev.1 <40 位 SHA> CONFIRM_CLEAN_RESET_V1`。它会在删除 PostgreSQL 数据卷前强制完成加密异地备份，但不会把 v0.3 用户、配置、额度、审计、供应商连接或其他数据库记录带入 v0.4；管理员必须访问 `/setup` 重新初始化。`secrets`、`uploads`、`.env` 和备份目录保留不变；PostgreSQL 卷删除后没有自动回滚，失败时必须由管理员按已验证的备份恢复或修复现场。

## 已实现能力

- `/admin` 使用固定 Header、固定侧栏和唯一正文滚动区；五个一级入口聚合为 Dashboard、用户与权益、配置中心、安全中心和运维中心，既有深链保持不变。
- Dashboard 提供 Asia/Shanghai 今日指标与 7/30 天趋势，按普通用户、平台托管调用和已结算平台额度做安全聚合；个人 BYOK 不计入平台指标，读取失败显示未取得而不伪造为零。
- GitHub 登录、个人账号绑定和 OAuth 开始页统一区分未配置、配置无效、平台初始化待完成和可用四种状态；Secret 继续只从部署环境读取，真实 GitHub OAuth 未现场验证。
- 平台连接探测预算默认从当前本地时间立即生效；平台模型连接测试会先检查预算生命周期和可用单位，并提供直接配置入口。服务端预算闸门、拒绝审计和幂等流程保持不变。
- 管理台冗余职责文案和大 Hero 已移除，待办卡片标题、状态和入口保持单行，空间不足时自适应降列。

## 验收边界

真实第三方 GitHub OAuth、模型供应商和生产部署仍需在目标环境独立现场验收；本地测试、构建或 loopback 证据不能替代外部服务结果。
