# AI Project OS v0.7.3

本补丁修复标签 CI 跳过完整数据库作业的问题：每个发布标签都强制运行源码覆盖率、完整 PostgreSQL 门禁、浏览器与无障碍检查、性能预算及隔离版构建，并核对同一提交的主分支 CI。生产发布以标签 CI 中实际成功的数据库作业为门槛。产品功能与 [v0.7.0](v0.7.0.md) 相同，停写备份合同修复沿用 [v0.7.2](v0.7.2.md) 的源码。

`v0.7.0` 工具安装失败，`v0.7.1` 升级在停写备份入口失败，`v0.7.2` 标签 CI 跳过数据库作业；这些历史标签保持不变，也不用于生产迁移。生产当前仍运行 `0.6.0-dev.14`，以公网 `/api/health` 的实时结果为准。

首次生产升级从通过完整数据库主分支 CI 和完整数据库标签 CI 的带注释 `v0.7.3` 标签取得安装器。现有 `v0.7.1` 网关无法自助安装新标签，须由可信主机运维在 root 会话中先保存主机与工具状态，再直装并核对 `v0.7.3` 工具；本次经用户明确决定跳过隔离主机演练。`tooling-v07-status` 返回 `TOOLING_V07_READY` 及精确标签和提交后，从 `main` 手动运行 **Deploy v0.7 with database migration**。工作流必须验证停写异地备份、117→135 迁移和公网应用及 Worker 健康；GitHub Release 不代表生产已升级。

本次发布继续豁免专用 Linux broker 主机、授权真实站点、真实外部服务和两个 MCP 客户端的现场验收；未验收能力在生产中保持关闭。
