# AI 记忆能力实施合同

状态：已批准的实施范围合同，尚未交付任何 V1 运行能力。

本文档是后续开发的安全边界和验收入口，不是当前产品说明，也不表示模型、连接器、检索、RAG 或代理已经可用。当前产品真相以 README 和 `docs/v0-scope.md` 为准。

## 当前产品真相

当前版本是单体 Next.js 人工工作台：用户手工录入 `ProjectSource`，人工创建并确认 `ProjectItem`，再生成确定性的 Project Snapshot。Source、Item 和 Snapshot 之间保留项目范围、`sourceId`、`sourceExcerpt` 和稳定错误语义。

当前版本不调用模型，不自动抽取、总结、纠错、排序或判断优先级；也没有语义检索、向量记忆、RAG、GitHub 连接器、代理、上传、队列、pgvector、MCP、认证授权或自动改代码能力。当前 V0 文案不得因本合同而改写成 V1 已交付。

## 已批准的后续能力范围

以下能力可以在完成各自的设计、固定评测、实现和验收后逐项开发。每项能力都必须沿用项目隔离、来源可追溯、人工可纠正和稳定错误的基础约束：

- 受控模型处理：只处理明确授权的项目资料，输出可校验的结构化候选，不直接写入已确认事实；每个候选必须绑定精确来源和摘录，并经过人工审核。
- 只读 GitHub 连接器：只读取用户明确授权的仓库、分支或提交，保存可复核的内容快照和来源指针；不得创建、修改、删除、评论、合并或触发仓库写操作。
- 混合检索与 RAG：允许在同一项目的受控文本检索和语义检索结果上回答；答案必须带证据，证据不足必须拒答，互斥证据必须显式报告冲突，不得跨项目泄露。
- 只读项目记忆代理：只可调用显式允许的读取工具和受控模型处理，不能执行 Shell、任意网络、文件系统操作、MCP 操作或任何写入动作。

## 明确禁止

在对应能力验收前，或任何能力超出本合同范围时，禁止：

- 将候选模型输出直接当作已确认 Item 或 Snapshot 事实；
- 自动修改代码、自动修改 GitHub、自动提交/合并、发送外部消息或触发外部副作用；
- 任意网络访问、未声明的文件系统读取/写入、Shell、未授权 MCP 工具和隐式工具发现；
- 引入独立 API 服务、worker、MCP server 或 monorepo；
- 在源码、日志、fixture、提交或文档中写入密钥、个人数据、真实项目私密资料、数据库连接串或可复用凭据；
- 以演示数据、静态 fixture 或测试通过为理由宣称生产模型质量、语义搜索质量或 V1 已可用。

## 共同发布门

任何后续能力进入产品运行时前，必须同时满足：

1. 能力合同明确输入、输出、来源、权限、失败和纠正语义，并由实现保持；
2. 固定版本评测集完成技术审阅和产品负责人确认，评测结果可复现、可审计；
3. 通过证据绑定、冲突处理、无答案拒答、提示注入和跨项目隔离检查；
4. 在显式的 token/request 预算和成本报告口径内运行，不把易变真实单价写入代码或 fixture；
5. README、V0 范围、产品 UI 和发布说明只陈述已经完成并验收的能力；
6. 保留人工纠正、回滚或禁用路径，并记录未通过的门或残余风险。

固定评测基线的结构、版本和审阅状态见 [AI 记忆评测基线](ai-memory-evaluation.md)。候选评测集本身也不是质量通过证明；技术审阅和产品负责人确认发生前，状态必须保持为候选或待确认。

## 变更规则

新增模型、数据源、写操作、工具权限、跨项目访问、部署形态或数据不变量时，必须先更新本合同和评测范围，再实现代码。合同范围之外的变更需要单独决策，不得通过修改文案或放宽 fixture 测试来绕过验收。
