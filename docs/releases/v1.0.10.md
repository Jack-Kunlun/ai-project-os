# v1.0.10 — 受限生产缓存与历史镜像维护

本源码候选为现有「发布正式版本」Workflow 增加缓存与已授权历史镜像检查、清理模式，复用 production 环境中的 SSH 凭据、精确主分支 CI、固定工具更新入口及生产发布锁。维护模式不创建版本标签或 GitHub Release，不切换应用、不运行迁移。本次维护保持线上 1.0.9；未来如需发布 1.0.10 应用，仍由用户选择默认 `release` 模式手动发起。

缓存检查分别报告共享/私有与可回收/受保护四类记录。清理只处理 root 保存的短期计划中、再次核对后仍可回收的精确记录 ID；新出现、变为占用中或内容变化的记录不会自动纳入。共享记录的标称大小与文件系统可用空间净变化分别记录，不将缓存元数据删除声称为等量磁盘释放。

正式发布在部署健康和回执通过后，自动串行执行缓存检查、超过 2 GB 时的定向清理及最终复查。目标固定为 2,000,000,000 bytes；`budget.json`、`budget.md` 和 Actions Summary 记录实际占用、四类明细、保护身份与逐项保留原因。超额明确警告；估算或检查失败不能报告精确达标。发布维护产物为 `production-release-cache-maintenance`，与发布回执分别保存；不会因缓存维护停掉健康应用。

正式发布的旧镜像回收改为冻结归属明确的候选，保留当前/上一版本以及所有运行中或已停止容器的引用，仅删除严格更早的完整不可变 ID，不删除父镜像或改用标签。清理前后验证镜像、容器、数据卷、配置、数据库账本与健康，变化即停止。缓存清理复用同一受限入口和短期计划，不使用无范围 prune，不扩展容器清理范围；执行保持串行，Node 堆限制为 512 MB，不新增本地容器。

维护前后验证当前和上一版本镜像、既有容器、数据卷、配置、应用版本及数据库账本；缓存模式不删除镜像，缓存/镜像维护不删除容器；指定旧版容器维护仅回收两个固定任务容器，所有维护均不删除数据卷或业务数据。来源、工具、保护快照或计划有效期不符时停止清理。原始命令描述、环境变量和 SSH 凭据不进入诊断报告。

标签不完整或不匹配的历史镜像单独列入额外保护快照，以 ID 和元数据哈希核对，报告只输出固定原因码；不能将它们视作当前或上一版本的可信镜像。

`images-inspect` 和 `images-clean` 针对已授权的固定 17 个历史镜像 ID，核对项目标签、明确仓库名、版本及运行中/已停止容器引用。仅归属确认、早于上一版本且无引用的记录进入短期清理计划；删除使用完整 ID、非强制且保留父镜像。历史发布与回滚仓库只有在固定 ID、版本、服务及完整引用精确匹配时才确认归属。未知归属、容器引用或引擎拒绝均保留，不通过标签删除或强制删除扩大范围。报告分别记录镜像大小、实际删除数量与磁盘可用空间净变化。

源码版本推进是现有工具更新协议要求的前进候选，不表示 1.0.10 已上线。无新增数据库迁移，清单仍为 146 条。实际分类、删除数量、空间变化和保护结果以维护 Workflow 的 `production-cache-maintenance`、`production-image-maintenance` 产物与公网健康为准。

增加两个固定旧版已停止容器的受控检查与回收入口。只处理已核对的一次性迁移/数据库角色校准任务，先验证成功退出、无挂载/依赖及无未知可写数据，再以非强制且保留卷的方式删除。之后复用历史镜像维护重新验证引用并清理；不停止业务服务，不删除业务数据。
