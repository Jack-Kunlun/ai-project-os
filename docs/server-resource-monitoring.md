# 服务器资源监控

初始超级管理员可在“生产备份与 COS 同步”页面查看当前资源快照。接口只支持读取；页面打开时读取一次，页面可见时每 30 秒刷新，也可手动刷新。失败时保留上次快照并标明读取时间。

内存来自 Linux `/proc/meminfo` 的 `MemTotal` 和 `MemAvailable`，使用 `MemTotal - MemAvailable` 计算已用量，因此不会把可回收缓存当作已耗尽内存。这个数字的范围由当前 Linux 内核提供；Docker 默认 procfs 通常报告宿主机范围，但如果容器使用虚拟化或隔离后的 procfs，应用无法据此证明它等于宿主机物理内存。容器 cgroup 内存只在检测到 Docker、cgroup v2 且当前进程映射明确为 cgroup 根目录时读取；其余情况显示不可读取。应用进程 RSS 单独展示，不代表容器或主机内存。

磁盘来自 Node `statfs`，只检查应用部署目录和配置的上传存储目录各自所属文件系统，不扫描目录内容，也不等于用户文件占用量。已用按 `(blocks - bfree) × bsize` 计算，可用按 `bavail × bsize` 计算，预留按总量减已用和可用计算；inode 数按 `files` 和 `ffree` 计算。文件系统不报告 inode 总量（`files` 为 0）时，inode 指标显示不可读取。若两个目录所属同一设备，页面提示容量相同且不可相加。无法读取的指标显示为空，不会显示成零；超出 JavaScript 安全整数范围的容量也会标为不可读取。

80% 起提醒，90% 起告警，磁盘可用空间低于 5 GiB 时也告警。监控不执行 `du`、目录遍历、Docker API、系统清理或历史采样。
