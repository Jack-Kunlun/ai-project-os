# v0.7.10：修复 Git 与 MCP 连接安全预览

共享连接治理页面改用短 UUID 作为请求编号。原页面生成的长编号被服务端接受，却违反数据库隐私约束，使只读 Git 探测成功后生成影响预览仍返回 500。Git 和 MCP 服务端现在提前拒绝数据库不允许的编号，返回既有输入错误；保留合法短编号和含分隔符的历史编号、幂等重放、数据库隐私约束和独立确认。不修改权限、凭据、Schema 或迁移。

应用包、健康接口和 Docker 镜像版本标签统一为 0.7.10，加入版本一致性检查。v0.7.9 的应用与健康版本正确，但镜像标签漏改，仍为 0.7.8；本次生产入口以精确的 v0.7.9 部署记录和健康版本绑定这一已知来源，并要求更新后的三个应用写入方镜像标签为 0.7.10。

## 验证

隔离 PostgreSQL 完整应用 140 条迁移，修复前复现 `GitConnectionMutationPreview_request_key_check` / SQLSTATE `23514`；修复后 Git/MCP 请求编号、预览幂等、配置修改证明绑定、凭据轮换和治理边界共 4 项集成测试通过。定向输入与治理合同测试 13 项通过，包含输入错误到 HTTP 400 的映射；切换及版本一致性检查 2 项通过。旧长编号在进入数据库之前失败关闭。类型检查、定向 ESLint、生产构建和全部性能预算通过（静态资源 773.3 / 780 KiB，CSS 14.8 / 15 KiB）。

## 生产更新与验收

沿用用户授权的单机快速更新：先构建应用及两个 Worker，再切换并检查内部与公网健康、镜像版本、原 PostgreSQL 和 140 条迁移账本；不做备份、恢复、旧数据演练、迁移或生产权限变更，不等待重复完整 CI。实际上线以 `V0710_DEPLOY_OK`、目标提交和公网版本 0.7.10 为准。

v0.7.9 的线上诊断已确认现有 Git 连接探测成功、主密钥可读及核心表权限正常。v0.7.10 更新后仍需通过页面重新生成预览、完成原有确认，再验收项目读取流程。模拟 MCP 客户端证据与真实服务、生产代理及 OIDC 现场验收分别记录，不据此宣称全部外部服务验收完成。
