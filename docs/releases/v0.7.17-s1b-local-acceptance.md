## 应用、broker、浏览器和数据库组合验收

新增 opt-in 用例 `composed S1b path crosses PostgreSQL, TLS/HMAC broker, Chromium fixture, cancellation and cleanup` 已通过。真实执行链为应用服务 → 带 HMAC 的 HTTPS broker → 测试执行适配器 → 隔离 Chromium / HTTPS 来源 fixture → 应用服务 → PostgreSQL。返回的正文来自实际浏览器，不是硬编码 broker 响应。

1. JavaScript 生成的合成标记进入待审核修订，Editor 审核后建立发布指针和 `ProjectSource`。
2. 同源表单真实提交后携带临时 cookie 访问受保护的 JavaScript 页面，Owner 能预览；Editor / Viewer 被拒绝，Owner 也不能接受发布，通用资料和发布指针均为零。
3. 来源 fixture 收到 `/hold` 请求后，通过真实签名 `/v1/cancel` 禁用运行中的来源；取消确认后，任务浏览器、代理和隔离网络均已移除，修订无正文、无发布指针、无 `ProjectSource`。

测试专用执行适配器允许解析合成来源到 Docker 私网，使用原型标签，并在 broker 请求/结果中使用合成的镜像配置指纹。它不运行生产 `hostRunner` / one-shot CLI，不验证生产 `RepoDigests`，也不表示公网 DNS/TLS 已验收。生产 guard 未加入测试例外。

## 验收发现与修复

- 首次组合测试因实际正文保留换行而预期使用空格失败；断言改为核对实际 JavaScript 标记，未修改产品正文处理。
- 修正测试资源清理：来源资源随机命名，只清理本次创建的对象；删除执行适配器中残留的固定资源名清理，避免操作其他同名对象。
- 修复 broker 的取消确认：此前执行器清理失败仍会完成 `done`，取消接口可能错误返回 200。现在正常任务失败只有在清理成功后传播专用内部错误；清理失败或未知执行器错误会锁定 broker 为不可用，当前取消返回 503，排队和后续任务被拒绝。`markReady()` 不能清除该状态，须由运维完成清理并重新启动 broker；生产启动流程仍先清理孤儿任务再接受请求。
- 新增两项负向回归覆盖明确清理失败与未知执行器失败、拒绝取消、排队任务不执行、拒绝后续请求及重建实例后的恢复。重建用例不替代实际宿主机崩溃与孤儿资源恢复验收。

修复后的定向单测和完整组合 gate 均已重新通过。此次只修改本地代码和测试，未提交、推送、发布或修改生产配置；broker 修复尚未部署生产。
