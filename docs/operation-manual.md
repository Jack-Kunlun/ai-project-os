# AI Project OS V3.0.0 操作手册

本文档面向本地管理员、工作区管理员和项目成员，说明 AI Project OS V3.0.0 的部署、页面配置、资料接入、智能记忆、自动化、团队权限、OIDC、备份和排错。

页面内简明指南：<http://127.0.0.1:3000/guide>

## 1. 先理解三个边界

### 1.1 资料、候选与事实不同

- 文件、网页、仓库和手工原文是 `ProjectSource`，表示可追溯证据。
- AI 自动抽取先产生候选，不会直接成为可信事实。
- 人工确认后的 `ProjectItem` 才进入项目事实视图。
- 语义搜索和 RAG 会返回证据，但模型回答仍需要人核对。

### 1.2 页面配置与部署配置不同

模型 API Key、Git Token/密码/SSH Key、OIDC Client Secret 都在页面录入。`.env` 只用于数据库、端口和安全 Cookie 等部署基础设施参数。

### 1.3 自动化不会绕过模型外发确认

仓库同步、网页刷新和确定性记忆质量检查可以由 Worker 自动执行。记忆索引和项目简报会把任务停在“需要确认”，由用户在页面核对供应商、模型和输入范围后再发送。

## 2. 启动与升级

### 2.1 首次启动

```bash
cp .env.example .env
# 编辑 .env，至少设置 POSTGRES_PASSWORD
docker compose config --quiet
docker compose up -d --build
docker compose ps --all
```

预期状态：

- `postgres`：`healthy`
- `migrate`：`Exited (0)`
- `app`：`healthy`
- `worker`：`running`

健康检查：

```bash
curl --fail http://127.0.0.1:3000/api/health
```

响应应包含 `status: ok`、`database: up` 和 `version: 3.0.0`。

### 2.2 初始化管理员

首次打开 <http://127.0.0.1:3000> 会进入初始化页。管理员用户名为 3–64 位；密码为 12–128 位，并且同时包含字母和数字。

初始化完成后，系统建立默认工作区，并把管理员加入为 Owner。V3.0.0 页面当前只管理这个默认工作区，不提供工作区创建或切换。

### 2.3 更新现有部署

更新前先备份数据库、主密钥和上传文件，然后执行：

```bash
docker compose up -d --build
docker compose ps --all
curl --fail http://127.0.0.1:3000/api/health
```

Compose 会先执行所有未应用迁移，再启动应用和 Worker。不要执行 `docker compose down -v`。

## 3. 页面导航

顶部主导航：

- `Dashboard`：跨项目状态、推荐下一步和最近任务。
- `项目`：创建、搜索、归档、恢复和进入项目工作区。
- `模型设置`：模型供应商、API Key 和模型 ID。
- `连接器`：Git 服务连接与凭据。
- `团队`：成员、邀请和 OIDC。
- 右上角铃铛：通知中心。
- 右上角头像：个人中心。
- 右上角帮助：页面使用指南。

进入项目后，第二行项目导航提供：资料与条目、文件资料、外部资料、代码仓库、自动化、智能控制台、智能记忆、记忆质量、项目智能体、治理与审核。

## 4. 账户、团队与权限

### 4.1 角色含义

工作区角色：

| 角色 | 权限 |
| --- | --- |
| Owner | 管理成员、邀请、OIDC 和工作区内全部项目；可授予 Owner |
| Admin | 管理成员、邀请、OIDC 和工作区内全部项目；不能修改 Owner |
| Member | 只访问单独授权的项目 |
| Viewer | 只读访问单独授权的项目 |

项目角色：

| 角色 | 权限 |
| --- | --- |
| Owner | 读取、编辑和项目归档/恢复 |
| Editor | 读取并修改项目内容，不能归档/恢复 |
| Viewer | 只读 |

系统始终保留至少一个启用状态的工作区 Owner。低权限邀请不会降低已有成员的工作区或项目角色。

### 4.2 创建本地成员

在“团队 → 成员”填写登录名、显示名称、邮箱、初始密码和工作区角色；可同时授予一个初始项目。密码请通过独立安全渠道交付。

成员邮箱用于邀请校验。OIDC 身份不会仅凭相同邮箱自动合并到已有本地账号。

### 4.3 邀请成员

在“团队 → 邀请”填写限定邮箱、工作区角色和可选项目。链接有效期为 7 天，只在创建响应中显示一次，应立即复制并通过安全渠道发送。

被邀请者需要先登录已有账户，或先通过允许自动建号的 OIDC 登录，再打开邀请链接。邮箱限定邀请要求账户邮箱完全匹配。

### 4.4 停用成员

停用会立即撤销该用户的活动会话。再次启用不会恢复已撤销会话，用户需要重新登录。停用用户不会删除其历史操作、证据或审计记录。

## 5. 配置 OIDC 企业登录

在身份提供商中创建 Web/OIDC 应用，并登记回调地址：

```text
http://127.0.0.1:3000/api/auth/oidc/callback
```

生产环境应使用站点的 HTTPS 域名，例如：

```text
https://project-os.example.com/api/auth/oidc/callback
```

然后在“团队 → 企业登录”填写：

- 名称和 Issuer URL
- Client ID 与 Client Secret
- Scopes，必须包含 `openid`
- Token 端点认证方式：`client_secret_post` 或 `client_secret_basic`
- 自动加入后的 Viewer/Member 角色
- 是否允许自动创建新账户，以及允许的邮箱域名
- 公司内网身份源才开启“允许受信任内网 OIDC”

保存时系统会读取 Discovery，检查 Code Flow、PKCE 和签名算法，解析并固定 Discovery、Token 与 JWKS 端点网络地址。公网端点默认必须是 HTTPS；云元数据地址始终拒绝。

登录时系统校验 issuer、audience、nonce、过期时间和 JWKS 签名。相同邮箱的已有本地账户不会自动绑定；系统会拒绝这次 OIDC 登录，避免身份劫持。V3.0.0 尚无页面化显式绑定流程。

## 6. 配置模型供应商

在“模型设置”添加 OpenAI、DeepSeek、Qwen（阿里云百炼）或 GLM（智谱开放平台）：

1. 填写连接名称和 API Key。
2. 填写生成模型。
3. 按需填写图片识别模型。
4. 供应商支持 embeddings 时填写向量模型和实际维度。
5. 保存后执行连接测试。

只有状态为“已验证”且具备对应模型能力的连接，才能在项目 AI 路由中选择。网络目标固定为内置供应商官方 API，不开放任意 Base URL。

DeepSeek 当前不承担向量路由；语义索引可使用 OpenAI、Qwen 或 GLM。模型 ID 和向量维度必须与供应商实际配置一致。

## 7. 配置 Git 连接

在顶部“连接器”创建 Git 服务。支持：

- GitHub、Gitee、GitLab
- 自建 GitLab
- Gitea、Forgejo
- 通用 Git 服务

HTTPS 可使用无认证、Token 或 Basic；SSH 使用 SSH 私钥和精确的 known_hosts 行。自签 HTTPS 可以填写受信任 CA 证书。公司内网服务必须显式开启内网访问。

建议：

- 为连接创建只读、最小权限凭据。
- GitHub fine-grained PAT 只授权需要的仓库和 Contents Read。
- 不要使用个人主 SSH Key；为 AI Project OS 单独创建只读 Deploy Key。
- known_hosts 必须由可信渠道获取，不要在首次连接提示中盲目接受。

保存时系统验证地址、凭据和远端可达性。DNS 地址变化后会停止读取并要求重新确认。Git 执行关闭交互提示、系统/全局配置、非目标协议和重定向。

## 8. 创建项目并接入资料

### 8.1 手工资料

进入“项目 → 资料与条目”：

1. 录入原始资料和可选来源链接。
2. 创建条目时选择同项目资料。
3. 引用资料中的精确连续原文。
4. 确认候选条目后，它才成为项目事实。

人工资料会按正文内容拒绝活动重复；仓库、网页和文件允许相同正文保留不同来源身份。

### 8.2 文件与本地文件夹

进入“文件资料”。支持 TXT、Markdown、JSON、CSV、PDF、DOCX、PPTX、XLSX、PNG、JPEG、WebP。一次最多选择 10 个文件，单文件最大 25 MiB。

浏览器可以选择整个本地文件夹。系统只上传用户明确选择、格式受支持且满足大小限制的文件；不会获得任意本地文件系统访问权。

文本和 Office 文档优先在本地提取。原始图片和缺少文本层的 PDF 扫描页需要：

1. 在智能控制台配置视觉路由。
2. 核对待发送片段数量。
3. 勾选本次模型传输确认。
4. 逐片段编辑、接受或驳回。
5. 全部处理完成后原子发布接受的内容。

Office 内嵌图片、音频和视频当前不会识别。

### 8.3 网页来源

进入“外部资料 → 添加网页来源”。公开网页默认要求 HTTPS；公司内网页面需要单独开启内网访问。系统会：

- 固定 DNS 地址并逐跳检查重定向
- 阻止云元数据与未授权私网地址
- 限制响应体和文本大小
- 移除脚本、样式与不可执行内容
- 新版本完整成功后再切换活动指针

网页抓取不执行 JavaScript，不登录站点，也不支持自定义 Cookie 或请求头。

### 8.4 多代码仓库

进入“代码仓库”：

1. 选择顶部“连接器”中已验证的 Git 服务。
2. 填写仓库路径、跟踪分支和项目角色。
3. 设置扫描根目录和排除模式。
4. 执行首次扫描。
5. 检查冻结 commit、文件数、字节数和结果状态。

一个项目可连接多个服务上的多个仓库。每次扫描先解析并固定提交，再读取允许的文本文件，整批校验成功后原子发布。失败不会污染上一代活动快照。

GitHub 的 Issue、PR、Release 和仓库 Markdown 扩展同步仍通过既有 GitHub 专用入口使用；通用 Git 连接器只读取代码与文本快照。

## 9. 配置项目 AI 路由

进入“智能控制台”，分别配置：

- 图片与扫描件识别
- 自动抽取
- 语义向量
- 引用式生成

切换生成或视觉模型只影响后续任务，历史来源保留原供应商和模型。切换向量供应商、模型或维度会让活动索引失配，语义搜索、RAG 和智能体会暂停，直到重建索引。

## 10. 建立和使用智能记忆

### 10.1 自动抽取

在“智能记忆”选择资料，核对输入清单并确认外发。所有待生成片段会发送给供应商；只有完成当次明确确认后才会发起请求。模型输出必须满足严格结构，且引用摘录必须真实存在于原文；验证失败会整次拒绝。

### 10.2 人工审核

逐条检查标题、内容、类型和引用。接受后成为已确认事实；驳回后保留审核记录，但不进入可信事实视图。

### 10.3 统一语义索引

索引覆盖当前活动的人工资料、文件片段、网页修订、仓库文本和代码快照。可以增量复用兼容向量，也可以全量重建。只有全部向量成功持久化后才切换活动索引。

以下变化需要重建索引：

- 新增或更新资料、网页或文件
- 重新扫描仓库
- 接受或撤销影响语义内容的来源
- 更换向量供应商、模型或维度

### 10.4 搜索、RAG 与智能体

语义搜索返回原文片段、路径、冻结 commit 和分数。RAG 只允许引用本次检索集合中的证据 UUID。

只读智能体可以读取项目概览、已确认条目、语义记忆和仓库状态。它不能执行 Shell、任意文件读取、代码修改、Git 写入或部署。

## 11. 记忆质量与生命周期

进入“记忆质量”并执行检查。检查为本地确定性规则，不调用模型，识别：

- 可能重复
- 内容冲突
- 长期未复核或已过有效期
- 缺少证据
- 低置信度

每条事实可以维护置信度、重要性、有效截止、长期置顶和“本次已复核”时间。处理问题后选择“已处理”或“不适用”，并填写的处置记录会保留。

## 12. 自动化与通知

进入“自动化”创建规则：

| 类型 | 到期行为 |
| --- | --- |
| 仓库同步 | Worker 读取活动仓库并原子发布新快照 |
| 网页刷新 | Worker 刷新活动网页来源 |
| 记忆质量 | Worker 运行本地确定性检查 |
| 记忆索引 | 创建需要页面确认的模型外发通知 |
| 项目简报 | 创建需要页面确认的模型外发通知 |

规则支持每小时、每 6 小时、每 12 小时、每天或每周，也可立即运行。运行状态、租约、失败码和连续失败次数会持久化；连续失败三次后规则自动暂停。

归档项目时，活动自动化规则会暂停。恢复项目后不会自动启用，必须人工检查后再开启。

通知中心显示成功、失败、记忆质量和外发待确认消息。通知只说明可观察结果；涉及模型的消息需要进入对应项目页面继续操作。

## 13. 治理、归档与导出

“治理与审核”用于：

- 审核 AI 候选
- 区分明确失败与未知外部结果
- 在具备不可变证据时人工收口未知任务
- 查看模型路由历史
- 核对 7/30/90 天调用与 Token 用量

人工收口不会再次调用外部服务，也不会把未知状态伪装成成功。

归档前，系统要求没有排队中、等待确认、运行中或需人工收口的后台任务，也没有运行中的自动化。归档是软归档，不删除数据。

受限 JSON 导出包含项目正文、文件元数据和审核文本，但不包含上传二进制、系统存储路径、凭据、向量和完整运行载荷。它不是灾难恢复备份。

## 14. 备份与恢复

### 14.1 数据库

```bash
docker compose exec -T postgres pg_dump -U ai_project_os -d ai_project_os -Fc > ai-project-os.dump
pg_restore -l ai-project-os.dump
```

如果 `.env` 使用了不同的数据库用户或库名，请替换命令参数。

### 14.2 主密钥与上传文件

还必须备份：

- `ai-project-os-secrets` 卷：丢失后已保存模型、Git 与 OIDC 凭据无法解密。
- `ai-project-os-uploads` 卷：包含上传文件原件。

数据库、主密钥和上传文件必须来自一致的备份窗口，并一起恢复。不要单独重建主密钥后继续使用旧数据库。

## 15. 常见问题

### 15.1 模型连接无法选择

回到“模型设置”执行连接测试，确认状态为“已验证”，并检查该供应商是否配置了目标能力所需模型。

### 15.2 Git 仓库无法读取

检查连接状态、仓库路径、分支、凭据权限、CA 或 known_hosts。若提示网络地址变化，确认 DNS/基础设施变更后，在页面重新验证连接。

### 15.3 网页抓取失败

确认网页无需浏览器登录或 JavaScript 渲染。内网页面需显式允许私网；DNS 地址变化必须重新确认。云元数据地址不可放行。

### 15.4 OIDC 登录失败

检查回调地址、Issuer、Client ID、Secret、Token 认证方式和 scopes。如果日志/页面提示账号不允许，可能是自动建号关闭、邮箱域名不匹配，或该邮箱已经属于尚未显式绑定的本地账户。

### 15.5 自动化没有运行

确认 `worker` 容器正在运行、规则为“运行中”、项目未归档且下次运行时间已到。连续失败三次的规则会自动暂停。

### 15.6 索引要求重建

当前资料清单或向量路由与活动索引不一致。使用当前向量供应商、模型和维度重新建立索引。

### 15.7 项目无法归档

先处理后台任务和自动化运行。`waitingConsent`、`running`、`unknown` 或需人工收口状态都会阻止归档。

### 15.8 页面显示的用量与账单不同

系统记录受审计的调用尝试和 Token，不维护供应商价格、折扣或缓存计费规则。最终金额以供应商账单为准。

## 16. 验收清单

- [ ] `/api/health` 显示版本 3.0.0、数据库正常。
- [ ] `postgres`、`app` 健康，`migrate` 成功退出，`worker` 运行。
- [ ] 管理员可登录，个人中心可轮换密码。
- [ ] 模型连接在页面测试通过。
- [ ] Git 连接验证通过，项目仓库能固定 commit 并发布快照。
- [ ] 文件/网页资料保留来源，图片识别需要当次确认与人工审核。
- [ ] 自动抽取候选不会绕过人工确认。
- [ ] 语义搜索和 RAG 返回项目内引用。
- [ ] 记忆质量检查可发现并处置问题。
- [ ] 自动化运行记录和通知可见，模型任务停在待确认。
- [ ] Viewer/Editor/Owner 权限边界符合预期。
- [ ] OIDC 测试账号可以登录，未知身份和邮箱冲突被拒绝。
- [ ] PostgreSQL、主密钥和上传文件都有可恢复备份。
