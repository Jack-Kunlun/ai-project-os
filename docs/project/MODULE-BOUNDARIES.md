# AI Project OS 功能模块与交接边界

核查日期：2026-11-02；源码基线：`992126540130e2f4591a32ce2ad7e4e86c5ea415` / v1.2.25。来源与核查记录见 [E-016](EVIDENCE.md)、[本轮核查](verification-boundaries-20261102.md)。关联 R-013、C-010、T-028。

本文是现有单体应用的维护和交接合同，沿用 [DELIVERED](DELIVERED.md) 的 F-001～F-012，未拆服务、改数据库或增加运行能力。“实现依据”描述本次读到的代码；“交接门槛”是后续任务必须满足的协作要求，不能反推所有运行场景已经通过。领域归属不等于某目录独占写权限：跨域写入仍须走现有服务、事务与权限控制。

## 谁交、交给谁、何时算接住

- 主代理负责跨模块协调与最终验收；每个 T 任务开工时填实际的交付者、接收者和验收者。同一人可以承担多个职责，但仍需分别留交付和验收记录；不得虚构团队成员或已运行的 Agent。模块联络暂由主代理承担，实施责任在任务中认领。
- 每次交接在对应 T 卡使用 [交接模板](TEMPLATES.md)，关联源模块/目标模块、需求及设计版本、服务/接口与数据合同、候选身份、实际产物、检查结果、遗留问题和恢复点。没有变更的已有合同直接引用，不复制第二套接口或状态定义。
- 交付方负责输入依据、自己产生的数据与状态、异常说明及可复用证据；接收方核对前置条件和合同，记录接受或拒收及理由；主代理处理职责争议。下游不能悄悄补写上游数据、放宽权限或自行改业务语义来“接通”。
- `实现完成 → 待验收 → 接收方按范围核对 → 已验收`。移交代码、接口返回 200、截图或口头“已完成”都不能代替接收检查。下游集成未通过时，整个功能仍未交付；上游可保留范围明确的单模块验收，不能宣称端到端成功。
- 阻塞/拒收留在原 T 状态及阻塞字段，追加 A 事件；合同不符由产出方修正，合法输出的消费错误由接收方修正，归属不明由主代理组织复现。相关缺陷另有 T 编号，跨模块双方关联同一问题，避免重复计算。
- 合同变更登记 C，列所有消费者、兼容方案和受影响证据。上游变动不能自动使下游“通过”；取消/延期交接也保留目标、原因和恢复条件。涉及权限、数据、额度或外发时按高风险流程重新分类。

## 模块合同

数据模型的完整字段和约束以 [Prisma Schema](../../prisma/schema.prisma) 及实际服务为准；以下列关键归属，不声称穷尽所有表或接口。所有模块都遵守 F-001 权限边界，涉及模型调用再遵守 F-010 的路由、外发和额度边界。

### F-001 账号与团队协作

- **负责 / 不负责：** 身份、会话、账号访问、工作区/项目成员、邀请、角色与凭据保护；不决定资料是否可信、计划是否完成，也不以 UI 隐藏替代服务端授权。
- **数据与状态：** `AppUser`、`AppSession`、`WorkspaceMembership`、`ProjectMembership`、邀请及访问审计；身份/角色变更由访问和成员治理服务负责。`ExternalCredential` 的密文封装归凭据服务，模型/Git/MCP 连接的业务用途分别归对应模块。
- **输入 → 输出：** 身份/会话、目标工作区/项目、请求操作 → 已核对的 actor 与权限范围，或安全错误；不给下游传递可随意信任的客户端角色。下游仍在操作时按现有路径复核账户、成员和资源访问。
- **上下游：** 登录/成员界面 F-011 → 权限服务 → F-002～F-010；账号关闭、成员撤销与跨模块资源处理须保留相应审计，不能只删界面条目。
- **交接门槛 / 失败归属：** 合法角色、越权、撤权后访问、最后 Owner 保护及跨账号状态隔离列入适用验收。身份判断错误由 F-001 处理；业务接口遗漏权限调用由该接口模块处理；无法验证身份时不能继续敏感操作。
- **实现依据：** [access-control](../../src/lib/access-control.ts) 的 `authorizeApiRequest`/`assertProjectAccess`、[membership-governance](../../src/lib/membership-governance.ts)、[credential-vault](../../src/lib/credential-vault.ts)、[account-closure-service](../../src/lib/account-closure-service.ts)。

### F-002 项目与计划

- **负责 / 不负责：** 项目生命周期、目标、工作项、优先级、依赖、证据和人工状态推进；不自动改代码、执行工具、写 Git 或部署。本仓库研发 TASKS 不属于产品计划数据库。
- **数据与状态：** `Project`、`ProjectLifecycleRevision`、`ProjectObjective`、`ProjectWorkItem`、依赖/证据链接和 `ProjectPlanAudit`；工作项状态以计划服务为准，不由通知、问答或自动化改写完成。
- **输入 → 输出：** 有权限的人工操作、合法依赖、F-006 的建议与引用快照 → 计划条目和审计。智能体建议人工纳入后先为 `proposed`，不是已承诺或已完成。
- **上下游：** F-004/F-006 提供证据，F-011 提供操作界面；F-008 读取计划用于简报/提醒；生命周期约束资料任务、Git 运行和动作模块。归档会检查未决任务，暂停活动规则；恢复不自动重启规则。
- **交接门槛 / 失败归属：** 人工接受建议、依赖环路、状态前置条件、过期版本冲突和归档遇未决作业需有检查。F-002 负责生命周期决策和协调；F-004/F-007/F-008/F-009 各自处理未决运行，不能由计划模块伪造其完成或擅自清账。
- **实现依据：** [project-plan](../../src/lib/project-plan.ts) 的 `createProjectPlanEntry`/`updateProjectPlanEntry`、[project-lifecycle](../../src/lib/project-lifecycle.ts) 的 `updateProjectLifecycle`、[project-operations](../../src/lib/project-operations.ts)。

### F-003 个人知识

- **负责 / 不负责：** 个人文档导入、编辑、版本、关系、搜索与导出；不把个人资料自动转为团队共享，不将项目文件图文能力等同于个人导入能力。
- **数据与状态：** `PersonalKnowledgeDocument`、`PersonalKnowledgeRevision`、`PersonalKnowledgeRelation` 与审计，归所属用户；图谱候选与语义索引等派生状态归 F-006。
- **输入 → 输出：** 当前用户、正文/导入结果、预期版本 → 带 owner、revision、hash 的文档和可核对内容；导出为经版本核对的 Markdown/text 与审计，不代表“发送至项目”。
- **上下游：** F-011 编辑/导入界面 → F-003；F-005 可在权限范围内选取个人资料，F-006 消费特定文档版本建立图谱/索引。资料变更后的派生结果必须重新核对版本；共享/转入项目若无明确合同不得默认为已有能力。
- **交接门槛 / 失败归属：** 所有人隔离、版本冲突、删除后可见性和导出内容版本一致；F-003 负责文档版本，F-006 负责过期派生物的可用性，F-005 负责当次选材及引用隔离。
- **实现依据：** [personal-knowledge-service](../../src/lib/personal-knowledge-service.ts) 的 `revisePersonalKnowledgeDocument`/`exportPersonalKnowledgeDocument`、[personal-knowledge-qa-service](../../src/lib/personal-knowledge-qa-service.ts)。

### F-004 项目资料、整理与事实

- **负责 / 不负责：** 资料原件、解析/图文核对、ProjectSource 来源、整理候选、事实审核及修订；不把上传、解析、模型生成和事实确认当作同一个成功状态，不负责索引可用性。
- **数据与状态：** `ProjectAsset`/版本/片段/解析运行、`ProjectSource`、`ProjectItem`/证据/修订、`AiCandidateBatch`/`AiCandidateClaim`；来源创建也可由 F-007/F-009 的专用导入事务完成，必须保留来源类型、不可变版本及指纹，不能直接绕过审核写事实。
- **输入 → 输出：** 上传/手输或已授权外部来源 → 可定位来源及处理状态 → 经规定准入的事实与证据。图文片段核对与候选事实审核是两道不同门槛；模型外发交 F-010，后台执行框架交 F-008。
- **上下游：** F-007/F-009 提供外部输入；F-005 可依其选材规则使用来源和已确认事实，不要求每次问答先形成事实；F-006 消费匹配版本的来源/事实，F-002 链接证据。
- **交接门槛 / 失败归属：** 原件写入成功不等于解析完成，解析完成不等于事实确认，事实确认不等于索引已就绪。只有符合 `source-grounded:v1` 来源、原文和无冲突条件的候选可按既有策略自动准入；网页/Git/MCP 等仍按各自人工审核边界处理。F-004 负责解析/准入失败及可重试状态；来源错误退回来源模块，不能吞错后标 ready。
- **实现依据：** [asset service](../../src/lib/project-assets/service.ts) 的 `uploadProjectAsset`/`reviewProjectAssetSegment`、[parser](../../src/lib/project-assets/parser.ts)、[vision](../../src/lib/project-assets/vision.ts)、[candidates](../../src/lib/ai-memory/candidates.ts)、[auto-fact-admission](../../src/lib/auto-fact-admission.ts)、[project-world](../../src/lib/project-world.ts)。

### F-005 统一问答

- **负责 / 不负责：** 个人/项目/可访问范围内的当次选材、外发确认、会话及轮次、引用快照、历史展示；不自动审核事实、接受项目建议或执行动作，不能宣称主入口已经采用所有高级语义检索。
- **数据与状态：** `UnifiedQuestionConversation`、`UnifiedQuestionTurn`、`UnifiedQuestionConfirmation`、展示修订及审计。正文来源仍属 F-003/F-004；额度和 Token 记录仍属 F-010。
- **输入 → 输出：** actor、问题、范围、当次模型/输入清单确认 → 回答或明确失败、绑定来源版本的引用和轮次结果。当前 `projectCandidates` 按关键词选来源/已确认事实，并排除 MCP 来源；引用不是新的已确认事实。
- **上下游：** F-003/F-004 供资料，F-001 控访问，F-010 供模型和用量，F-011 展示正文/引用/浮窗。F-006 是另一条高级检索/调查路径，不能给主入口套用其验收结果。
- **交接门槛 / 失败归属：** 范围/来源变化后重核确认；无证据、失败、过期、切账号、归档会话、旧响应回流均有适用场景。F-005 负责会话及引用映射；F-010 负责调用和计量事实；接收方不能凭 HTTP 成功把拒答或未知轮次显示为成功。
- **实现依据：** [unified-question-service](../../src/lib/unified-question-service.ts) 的 `prepareUnifiedQuestion`/`executeUnifiedQuestion`、[contract](../../src/lib/unified-question-contract.ts)。
- **流式合同（T-075 / C-022，E-032 本地验收通过、未发布）：** `prepare` 沿用 JSON；`execute` 可通过 `Accept: application/x-ndjson` 选择 `delta` / `complete` / `error` 事件。正文增量只作当前请求的临时预览，每批输出前复核现有访问与来源边界；仅最终模型结构、引用、权限、用量及持久化成功后发出 `complete`。断流或 `error` 清除临时预览并保留问题草稿，不自动重试。旧 JSON 调用保持完整结果语义；浏览器离开后服务继续本次审计/计量收口，不重新派发模型。

### F-006 图谱、高级检索与只读调查

- **负责 / 不负责：** 图谱派生/审核、语义索引及检索、带引用 RAG、只读调查与记忆质量结果；不修改原始事实来迁就索引，不接受或执行计划工作。
- **数据与状态：** 个人图谱候选/语义 generation，项目 corpus/index generation、pointer、RAG snapshot、`RagAnswer`、`ProjectAgentRun`、`MemoryQualityIssue` 等派生产物；原始文档/事实分别归 F-003/F-004。
- **输入 → 输出：** 当前权限、来源/事实版本、索引配置与指定范围 → 有身份和可用状态的索引、检索结果、证据限定的回答/调查或不足证据拒答。图谱建议审核会检查源文档版本，索引更换 provider/model/dimensions 不能直接沿用旧结果。
- **上下游：** F-003/F-004/F-007 供受控数据，F-010 供所需模型；F-011 展示，建议由 F-002 人工纳入计划。F-005 主入口不是本模块全部能力的统一消费层。
- **交接门槛 / 失败归属：** 来源变更、索引未就绪、无结果、跨项目、模型/维度变化、引用不在本次集合等场景按实际变更覆盖。F-006 负责派生状态和引用验证；不能用旧索引伪装新配置可用或把调查建议标为计划已完成。
- **实现依据：** [personal graph](../../src/lib/personal-knowledge-graph.ts)、[personal semantic](../../src/lib/personal-knowledge-semantic-service.ts)、[corpus-index](../../src/lib/ai-memory/corpus-index.ts)、[grounded-rag-service](../../src/lib/ai-memory/grounded-rag-service.ts)、[read-only-agent](../../src/lib/ai-memory/read-only-agent.ts)。

### F-007 外部资料与 Git

- **负责 / 不负责：** 网页/明确选定文件夹/Git 的连接、读取、来源版本和发布；不写 Git，不因连接可用而认为来源已审核或已进入检索。网页不同接入方式不能混用上线声明。
- **数据与状态：** `WebSource`/修订/审核/指针、`GitConnection`/仓库、项目授权、手动/自动运行与 publication generation/head 等；来源写入由专用发布事务负责，后续事实准入归 F-004。
- **输入 → 输出：** actor、目标范围、凭据引用及授权、冻结配置/commit → 读取结果和来源版本，或失败/待审/延后。Git 必须固定仓库、分支、目录与 commit，完成原子发布后才能交付新有效版本，`deferred` 不算成功。
- **上下游：** F-001 提供权限和凭据边界；独立 Git Worker 调用 F-007 运行服务；发布的资料交 F-004/F-006。静态网页是常规路径；Bearer 认证网页在 production 禁用；浏览器 `rendered` 依赖开关及 Broker 配置，审核后才发布；`siteForm` 仅 Owner 私有预览，不能发布进资料、检索或 AI。
- **交接门槛 / 失败归属：** 明确抓取方式、可用环境、审核/发布状态、来源指纹及旧有效版本；验证凭据失效、配置漂移、部分失败和范围外访问。F-007 负责读取、审核与发布；F-004 不把未经允许发布的预览当作资料。UI/API 存在不证明生产启用或真实服务通过。
- **实现依据：** [web-sources](../../src/lib/web-sources.ts)、[authenticated-web-sources](../../src/lib/authenticated-web-sources.ts)、[browser-web-sources](../../src/lib/browser-web-sources.ts)、[broker 配置](../../src/lib/web-browser-broker-client.ts)、[Git execution](../../src/lib/project-git-automation-execution-service.ts)、[Git run service](../../src/lib/project-git-automation-run-service.ts)。

### F-008 简报、自动化与通知

- **负责 / 不负责：** 简报、确定性检查、持久化调度、租约/心跳/失败暂停及通知；不自主完成计划工作，不绕过模型外发确认，不用通知已读推导问题解决。
- **数据与状态：** `AutomationRule`/`AutomationRun`、`BackgroundJob`/attempt/reconciliation、`WorkerRuntime`、`Notification`。调度器管运行生命周期，处理器管业务结果；专用 Git 的运行/授权和原子发布仍归 F-007。
- **输入 → 输出：** 明确规则、活动项目及运行前置条件 → 持久化运行结果/安全失败/等待确认和提醒；模型整理或视觉任务由相应 F-004 处理器执行，需遵守 F-010。通用自动化连续三次失败暂停；其他任务不能不核对实现就套用相同重试策略。
- **上下游：** F-002 提供项目状态/计划输入，F-004/F-007 等执行领域处理；F-011 展示通知。通用 `AutomationRule` 的旧 `repositorySync` 分支被暂停，与 F-007 已有的专用授权 Git 计划读取是不同路径。
- **交接门槛 / 失败归属：** 已领取、排队、待确认、执行成功、通知送达分别记录；核对租约失效、重复领取、失败暂停、归档和恢复。调度/租约问题由 F-008 处理，领域失败交处理器模块；未知运行先对账，不能凭重复通知或自动重试掩盖。
- **实现依据：** [automation](../../src/lib/automation.ts)、[project-processing-worker](../../src/lib/project-processing-worker.ts)、[notification-service](../../src/lib/notification-service.ts)、[Worker 入口](../../scripts/automation-worker.ts)。

### F-009 MCP 与受控动作

- **负责 / 不负责：** 显式白名单动作与审批、外部 MCP 只读调用、成功结果人工导入，以及本应用对外只读 MCP 导出；不允许任意执行、写工具或自动把工具输出当事实。这两个方向必须用不同授权与验收记录。
- **数据与状态：** 内置动作使用 `ProjectAction`/策略/审批/审计；外部读取使用 `McpConnection`、工具定义/审核、`ProjectMcpToolGrant`、`ProjectMcpAction`/派发/结果/导入记录；对外导出使用 `McpExportGrant`、OAuth、`McpExportApproval`/`McpExportDispatchAudit`。均保留各自状态机，不能相互代替授权。
- **输入 → 输出（读取外部）：** 可信连接、管理员审核、项目授权、逐次批准与输入/工具/凭据/网络指纹 → 成功/失败/未知等动作结果；仅成功且完整的结果可由 Editor/Owner 人工纳入未审核来源。`unknown`、过期或漂移不能作为可重复成功的依据，不自动重试外部读取。
- **输入 → 输出（向外导出）：** 外部客户端请求指定项目摘要/证据/计划，经 Owner 内容预览及指纹批准 → 被批准的只读内容和消费审计。生产须启用 export 与 OAuth 并配置合法 HTTPS 公共地址；本地旧式 Bearer 生产恒关；不能借外部工具读取授权导出本项目资料。
- **上下游：** F-001 负责 actor/Owner 访问，F-002/F-004 供被批准导出的数据；读取结果导入后交 F-004。导入不等于自动进入事实、RAG 或模型；当前 F-005 的选材显式排除 MCP 来源，不以“已导入”承诺可问答。
- **交接门槛 / 失败归属：** 两方向分别验证授权/过期/撤销/指纹漂移/消费或未知状态；F-009 负责审批和派发/导入/导出完整性，来源域负责数据版本。不能把成功联网当成成功导入，也不能把导出路由存在当成生产已启用。
- **实现依据：** [action engine](../../src/lib/action-engine.ts)、[MCP dispatch](../../src/lib/project-mcp-action-dispatch-service.ts)、[result import](../../src/lib/project-mcp-action-result-import-service.ts)、[对外路由](../../src/app/api/mcp/route.ts)、[export grants](../../src/lib/mcp-export-grants.ts)、[OAuth 配置](../../src/lib/mcp-export-oauth-config.ts)。

### F-010 模型、用量与平台管理

- **负责 / 不负责：** 固定供应商注册、连接/凭据引用、能力和有效路由、权益、平台额度/预留/结算、模型测试记录及调用/Token 审计；不决定业务回答正确或事实已确认，分别记录连通性测试结果、用户额度、Token 用量与支付。

- **输入 → 输出：** actor/project/operation、有效 provider/model、当次输入清单及确认、额度前置条件 → 受控调用结果与实际用量/账本状态。平台额度路径先预留、再按明确结果结算；用量未知时可保持 `held` 待对账，不能自动算零或认为释放完成。
- **上下游：** F-003～F-006/F-008 等按实际调用路径提交业务输入，F-010 返回安全结果；F-011 呈现配置和用量，F-012 提供网络/代理运行依赖。OpenAI 代理属于部署网络，不改变业务授权或使其他供应商走同一路径。
- **交接门槛 / 失败归属：** 能力匹配、外发确认过期/漂移、余额不足、供应商失败、未知用量、配置测试/应用部分失败需分别处理。批量配置的 `unknown/applyUnknown/stopped` 不能报全部启用；未知结果停止后续项。F-010 负责调用和账本，业务模块负责结果写入与业务状态，不能自行重试可能已计量的未知调用。
- **实现依据：** [model-provider-http](../../src/lib/model-provider-http.ts)、[ai-entitlements](../../src/lib/ai-entitlements.ts)、[user-token-usage](../../src/lib/user-token-usage.ts)、[能力批量状态](../../src/app/settings/platform-operation-batch.ts)、[能力界面](../../src/app/settings/platform-operation-assignments.tsx)。
